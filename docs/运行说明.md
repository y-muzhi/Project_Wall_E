# WALL-E 本机运行

应用使用 React / TypeScript / Milkdown 与 Python / FastAPI，SQLite 文件数据库、单进程。正式入口是 `/requirements`，详情是 `/requirements/:id`。生产模式由同一个 Python 服务提供前端资源与 `/api/v1` 接口。

从项目根目录执行以下 PowerShell 命令。首次安装使用已锁定依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock
Push-Location frontend
npm ci --no-audit --no-fund
npm run build
Pop-Location
```

首次明确初始化数据库，或检查已有数据库：

```powershell
.\.venv\Scripts\python.exe -m backend.app.infrastructure.database init
.\.venv\Scripts\python.exe -m backend.app.infrastructure.database check
```

`init` 校验已有数据库，不会重新填充业务数据。默认路径为 `data/wall-e.sqlite`；使用其他库时先设置 `WALLE_DATABASE_PATH` 为绝对路径。迁移已有旧库前会备份，不能证明的旧事实会拒绝迁移并保留。

启动正式应用：

```powershell
.\.venv\Scripts\python.exe -m backend.app
```

在浏览器打开 `http://127.0.0.1:8000/requirements`。服务绑定本机地址、一个工作进程、无 reload；启动检查数据库、进程锁及恢复，缺数据库或前端构建则拒绝启动。再次构建前端后刷新页面使用新资源。可用 `WALLE_FRONTEND_DIST` 指定构建目录。按 Ctrl+C 由正式生命周期停止服务；后台关闭与下次恢复沿用已有保证。

开发模式先启动上述后端，再在独立终端执行：

```powershell
Set-Location frontend
npm run dev
```

开发入口为 `http://127.0.0.1:5173/requirements`，Vite 将 `/api` 代理到本机 8000 端口。其他本机后端端口可通过 `WALLE_API_URL` 指定。`npm run preview` 预览已有构建，使用同样的本机代理。

无模型凭据时，创建需求、工作台、正式文档、人工编辑、评论、版本与生命周期可使用；AI 运行实际报告配置失败。已批准的供应方/模型配置见 [volcengine-v1.md](proposals/volcengine-v1.md)，凭据由 `WALLE_MODEL_API_KEY` 环境变量提供，不写入仓库。真实供应方计数兼容、上下文预算候选和真实效果验收仍有独立未闭合项，不能把配置冻结当作这些验证已通过。

项目根的验证入口：

```powershell
node tools/spec-audit.mjs check
node tools/verify-frontend.mjs
node tools/verify-storage.mjs
node tools/verify-product-browser.mjs
```

最后一个命令构建实际根页面，在 `output/playwright` 使用新的隔离 SQLite 文件，启动同源 Python 服务并用 Playwright CLI 驱动真实业务页面。它不使用默认业务库、不继承模型配置；正常结束关闭自己的浏览器与服务。Windows 浏览器验证依赖 Git Bash、npx 及个人目录中的 Playwright 技能包装器。原始结果保存在 `docs/verification`，验证范围以每份记录为准。

当前代码已具有实际产品入口，完整交付仍以 [实现进度.md](实现进度.md) 与 [验收场景映射.md](验收场景映射.md) 为准。
