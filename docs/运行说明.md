# WALL-E 本机运行

应用使用 React / TypeScript / Milkdown 与 Python / FastAPI，SQLite 文件数据库、单进程。正式入口是 `/requirements`，详情是 `/requirements/:id`。生产模式由同一个 Python 服务提供前端资源与 `/api/v1` 接口。

从项目根目录执行以下 PowerShell 命令。首次安装使用已锁定依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock
Push-Location frontend
npm ci --no-audit --no-fund
npm run build
Pop-Location
```

首次明确初始化数据库，或检查已有数据库：

```powershell
.\.venv\Scripts\python.exe -m backend.app.infrastructure.database init
.\.venv\Scripts\python.exe -m backend.app.infrastructure.database check
```

`init` 校验已有数据库，不会重新填充业务数据。默认路径为 `data/wall-e.sqlite`；使用其他库时先设置 `WALLE_DATABASE_PATH` 为绝对路径。迁移已有旧库前会备份，不能证明的旧事实会拒绝迁移并保留。

启动正式应用：

```powershell
.\.venv\Scripts\python.exe -m backend.app
```

在浏览器打开 `http://127.0.0.1:8000/requirements`。服务绑定本机地址、一个工作进程、无 reload；启动检查数据库、进程锁及恢复，缺数据库或前端构建则拒绝启动。再次构建前端后刷新页面使用新资源。可用 `WALLE_FRONTEND_DIST` 指定构建目录。按 Ctrl+C 由正式生命周期停止服务；后台关闭与下次恢复沿用已有保证。

开发模式先启动上述后端，再在独立终端执行：

```powershell
Set-Location frontend
npm run dev
```

开发入口为 `http://127.0.0.1:5173/requirements`，Vite 将 `/api` 代理到本机 8000 端口。其他本机后端端口可通过 `WALLE_API_URL` 指定。`npm run preview` 预览已有构建，使用同样的本机代理。

无模型凭据时，创建需求、工作台、正式文档、人工编辑、评论、版本与生命周期可使用；AI 运行实际报告配置失败。已批准的供应方/模型配置见 [volcengine-v1.md](proposals/volcengine-v1.md)，凭据由 `WALLE_MODEL_API_KEY` 环境变量提供，不写入仓库。真实供应方计数兼容、上下文预算候选和真实效果验收仍有独立未闭合项，不能把配置冻结当作这些验证已通过。

项目根的验证入口：

```powershell
node tools/spec-audit.mjs check
node tools/verify-frontend.mjs
node tools/verify-storage.mjs
node tools/verify-counted-runtime.mjs --regression
node tools/verify-product-browser.mjs
node tools/verify-product-browser.mjs --suggestions
node tools/verify-clean-install.mjs
```

产品浏览器命令构建实际根页面，在 `output/playwright` 使用新的隔离 SQLite 文件，启动同源 Python 服务并用 Playwright CLI 驱动真实业务页面。它不使用默认业务库、不继承模型配置；正常结束关闭自己的浏览器与服务。Windows 浏览器验证依赖 Git Bash、npx 及个人目录中的 Playwright 技能包装器。原始结果保存在 `docs/verification`，验证范围以每份记录为准。

`--suggestions` 使用明确隔离的五补丁生成前置，验证实际根页决定/采用/放弃，不证明模型生成。干净安装命令在 ignored output 中新建局部依赖环境，按锁安装、构建并通过真实 TCP 验证启动；不修改正常依赖或业务库。

当前代码已具有实际产品入口，完整交付仍以 [实现进度.md](实现进度.md) 与 [验收场景映射.md](验收场景映射.md) 为准。


新增专项入口：`node tools/verify-product-browser.mjs --cards` 独立验证真实根页面卡片回答/普通文字过期及未知恢复，明确隔离生成前置，不证明Provider效果。`node tools/verify-counting.mjs` 验证D-011独立Schema/真实TCP计数适配及相关C03，不启用生产计数或发送真实Ark请求。D-011已批准，真实模型和两角色Chat封装兼容仍是生产启用门禁。


D-011计数策略候选固定在 backend/resources/counting/v1/strategy.json，读取须校验SHA。精确编译器已接内部ORCH、审计及后台，公开请求和环境变量不能启用该分支；生产发送链路仍沿用保守拒绝。候选的256预留不代表真实Chat封装兼容已证明。verify-counting验证基础与独立编译器，verify-counted-runtime --regression验证实际本机计数/Chat TCP、C03/C07、取消及保留；两者均不调用真实Ark。最新范围见[计数编排验证说明](verification/counted-runtime-notes.md)。

内部计数分支在数据库旁创建 `<数据库文件名>.count-audit` 私有目录：准备和观察到的结果独立保存。准备记录不证明已发送/付费，缺结果保留未知，后台启动不自动重发。成功原始计数响应保留30天，清理后请求/计数摘要继续保留；备份此分支的数据时一并保留该目录。该目录与业务SQLite均被Git忽略，不公开提供下载。


六任务观测工具默认离线：`.\.venv\Scripts\python.exe -X utf8 tools/framing-probe.py --prepare`建立隔离真实SQLite输入，`--plan docs/proposals/framing-observation-plan-v1.json`只检验批准计划。只有明确`--execute`及准确批准canonical SHA才读进程凭据和执行，最多6＋6、无重试/首失败停，不访问正常业务库或启用生产。`--prune-run`是私有原始记录的手动30天维护工具，不承诺自动定时任务。D-012原计划在随后DeepSeek短测试期间未执行。

用户本机密钥文件为项目根`.env.local`，单行`WALLE_MODEL_API_KEY=本机密钥`，该文件被Git忽略。只有独立`tools/model-smoke.py --execute`读取它；正式服务及framing工具仍从进程环境读取，不自动加载该文件。默认`tools/model-smoke.py`仅打印无凭据的离线请求计划，真实执行须每次明确用户授权；当日三个已授权槽位都已经执行，重复同槽位拒绝。DeepSeek简短测试最多一次请求/128输出token/45秒/无重试，不改变正式业务配置，当前测试结束。不得将任何密钥发到聊天或仓库。


独立产品HTTP/存储验收（本机受控计数/模型，不读取密钥、不发付费请求）：

```powershell
node tools/verify-product-flow.mjs
```

每个分支新建忽略的output/product-flow/UUID隔离库与临时端口，实际应用生命周期及后台关闭后保留诊断库；正常data/wall-e.sqlite与已运行的查看服务不变。原始结果与命令退出码/hash保存在docs/verification/product-flow-*.json，范围见product-flow-notes.md。通过不自动启用生产计数或证明真实模型效果。
