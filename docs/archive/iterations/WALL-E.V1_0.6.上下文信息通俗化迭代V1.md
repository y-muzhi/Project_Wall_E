# 上下文信息通俗化迭代V1

编号：UX-033。日期：2026-10-18。状态：源码已实施，最终修订已合入前端1.1-draft-sync12的BND-MODEL-CALL；后端仍为sync4。保留DRAFT及原验收边界。

## 1. 问题与范围

用户要求修改请求详情中难懂的描述。“投影版本”“软目标观测”“结构精简一期”属于内部术语，且将软目标与实际用量、允许上限混在一起，用户无法判断到底发送了多少或超出了多少。

本次仅修改前端请求详情的表达及保存数据的展示，不改后端、提示词、上下文选择、预算、权限、业务数据、卡片回答或事实确认流程。沿用只读详情，不调用模型或计数API。

## 2. 首轮界面与字段（已由第4节替代）

|位置|显示规则|数据来源|
|---|---|---|
|概览标题|本次发送了什么|selection_summary存在时展示|
|正文内容|数量＋“个区块（段落、标题、表格等）”|read_blocks，不称章节数|
|历史对话|数量＋“条消息（不等于完整对话轮数）”|history_messages，不称对话轮数|
|实际输入（模型返回）|token数或未记录|call.input_tokens|
|发送前预计输入（含预留量）|token数或未记录|preflight.input_tokens|
|期望控制在|token数或未记录|soft_input_target；优化参考，不是硬门禁|
|允许的输入上限|token数或未记录|preflight.budget.input_tokens，不硬编码|
|与期望目标相比|发送前预计输入超出／低于目标的token差值，或与目标相同；缺少任一值时无法比较|仅由前述保存的预计输入与目标做减法；不使用实际用量替代|
|技术信息|默认折叠，显示上下文整理格式版本、发送前计数批数|context_strategy、count_attempts；明确不是Chat调用次数|
|Token用量|实际用量与发送前检查分开；说明输入、输出、总上限及各部分计数|原call、preflight及counts，保持统计口径|

正文说明期望目标不单独阻止请求，正式发送仍检查输入／输出／总上限等。明确本次结构精简沿用原读取范围及历史窗口；完整权限及审计由程序保存，模型仍收到任务必要的范围及操作说明。缺失值显示“未记录”，不显示“未记录个区块”或用0补缺失。

## 3. 首轮实现与合并（历史记录）

实现位于frontend/src/guide/model-call-view.tsx，新增ContextOverview替换原诊断区块，并调整TokenDetails文案。没有新增接口、字段、持久对象、模型调用或计数。原技术值保留在折叠区便于排查。

规范已合入[前端设计BND-MODEL-CALL](../../design/WALL-E.V1_0.6.前端设计文档.md#bnd-model-call)；[专项记录](../../verification/context-copy-2026-10-18.md)记录静态检查和正在运行的Vite只读模块读取结果，未扩大全项目验收。本轮不新增测试、不构建生产产物或重启服务；5173开发页使用Vite更新，8000静态页需后续获准构建后才更新。

## 4. 用户反馈后的最终修订

用户明确要求删除第一个概览模块，并指出表达口语化、缺少正式系统感。以本节为当前规则，第2、3节仅保留变更历史。

- 完整移除ContextOverview及入口，“本次发送了什么”、目标比较和“技术信息”均不再展示，不将其改名或迁移到其他区域。
- 请求详情保持调用概览、请求上下文、Token用量、原始请求。正文和历史数量仅由上下文分组统计；实际用量、发送前计数及上限仅在Token用量展示一次。
- Token用量区分“实际用量（模型返回）”和“请求预检”。采用“预检输入（含预留量）”“输入上限”“输出上限”“输入与输出总上限”；分项标记“分项计数”。说明使用正式、简洁、准确的陈述，保留缓存包含关系和统计重叠提示。
- 请求上下文说明为“内容来源于本次请求快照，不受后续文档修改影响。”历史身份称“历史消息编号”，原始请求标题不附加开发实现叙述。
- 将正式系统用语、避免口语化和开发者自述、同一指标不跨模块重复展示写入前端通用文案原则及AGENTS.md，作为后续界面设计约束。

前端sync12已替换对应组件规范；后端仍为sync4。selection_summary、context_strategy及其他接口／快照保持兼容，仅停止展示此概览。本轮仍不新增测试、生产构建、服务重启、模型／计数调用或业务写入，检查记录续写原专项文档。
