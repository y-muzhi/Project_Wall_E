## 1. 问题与实际证据

用户确认包含目标区块、章节、操作、原文及新正文的事实变更后，程序仍请求模型，正文没有写入。只读核对需求 REQ000003：消息 30 是事实确认卡，消息 31 是用户明确确认；随后运行 14、调用记录 18 再次请求模型，消息 32 又返回相同确认卡。CURRENT 仍为 v1。调用确实成功，问题出在本地提交链路。

C06 原先对所有 INITIALIZE 卡片回答统一创建 RUNNING/PREPARING 运行，工作器统一调度模型；真正写入要等下一次模型输出 confirmed_fact_patches，经 C07 才采用。用户已经确认的具体变更因此又依赖模型重新组织，可能重复确认。

## 2. 当前规则

普通澄清选择题回答继续创建 AI 运行。事实变更 CONFIRM 的回答由 C06 在提交事务内处理：保存正式回答、解析原卡片中已展示的具体变更、应用已选择确认的变更、更新正文版本、重新定位评论锚点、保存程序回执、结束运行并释放占用。确认后不自动调用模型；需要继续澄清时由用户发送下一条消息。暂不确认或跳过仅保存答案，不写正文、不调用模型。

混合组含事实确认时，整组回答一起保存并结束本轮，仅应用已确认的明确变更；其他回答留在历史中供下一次用户主动继续时使用。整个变更集合先检查、后原子采用，不能局部写入。

## 3. 变更格式与写入边界

兼容原完整事实声明，以及此次实际返回的表格紧凑声明（“原表格：”后直接接表格，行选择后直接接新行数组）。不推断普通自然语言的写入操作。CONFIRM 必须有明确确认／暂不确认选项，无自定义回答、无推荐预选；章节、目标、冻结权限、当前版本、补丁结构及模板标题保护保持。

表格替换采用行级边界：声明中的完整表格必须与卡片所展示的原文一致，表头及被选择的旧行必须与当前正文逐字一致，键必须唯一，新单元格必须满足表格结构。只替换被确认的行；不采用模型对其他行的转述。本次模型把未修改行的“用户或数据隔离”抄成了“用户数据隔离”，该行不是确认目标，继续保留当前正文原文。区块操作仍要求整个旧区块一致。

无法确定写入的回答仍保存并展示程序原因，正文保持原样，不调用模型补救，也不拦截原模型返回。FLOW-003 直接展示规则保持。实际存储或提交错误回滚整个事务。

## 4. 前后端契约与记录

C06 响应字段及 HTTP 202 保持；guide_run 可以是普通回答的 RUNNING/PREPARING，也可以是程序直接处理后的 COMPLETED/FINISHED。工作器只调度 RUNNING。前端识别已完成回执后重新读取正文、消息和状态，不把已完成当作提交失败、不要求额外模型轮询。

保留真实新的 GuideRun 作为正式回答和文档来源记录，程序回执明确说明是否写入及正文版本，并注明本次未调用 AI；不会伪造 LLMUse 或模型结果。幂等重放不会二次写入，不同请求键重复提交仍返回原正式回答身份。
