实施顺序：公共名称编辑组件 → 文档名称接入并删除旧入口／表单 → 需求名称接入并删除更多操作内旧入口 → 必要离线检查、类型、格式和临时构建 → 同步映射及断点。

输入／输出／不变量：公共组件接收实际名称、草稿、编辑及禁用状态，输出开始、变更、保存和取消事件；父级原命令保有校验、目标ID、metadata_version、原请求及结果恢复。不新建业务流程，不用正文版本保存名称，不触发AI。文档名称仍1—80码点，需求名称仍1—20码点。

最终交互：名称旁采用同一编辑图标按钮；名称区域悬停、键盘聚焦时显示，无悬停设备可直接操作。点击后在原名称位置显示输入框及“保存”“取消”；自动聚焦并选中，Enter保存、Esc取消，中文组合输入期间不触发保存／取消。取消和成功退出后恢复按钮焦点；失败保留输入，未知结果及已保存待读取仍由原恢复入口处理，不能取消未知请求或换新请求。

文档原信息栏只保留确认／归档／恢复；人工编辑页和归档文档继续隐藏文档改名入口，其他占用仍按原权限禁用。需求名称位于居中页头，更多操作保留文档记录／重新读取；名称编辑不改变状态、正文或会话。长名称换行／截断与可用宽度适配，不挤出按钮。

同日截图反馈收敛宽度：原表单作为块级flex容器，输入flex-grow填满容器，导致短名称也横跨页头／正文整行。统一将整个名称编辑表单（含保存／取消）设为440px、max-width:100%，输入仅填表单内剩余空间；窄容器沿原flex规则收缩／换行。需求表单用margin-inline:auto居中，文档表单保持原名称左对齐。仅共享CSS修正，不改命令或输入长度上限。

同日布局稳定性反馈的最终规则（替代前段表单占位及换行方式）：常驻名称显示结构始终参与布局，进入编辑只设置visibility:hidden并inert／aria-hidden，不移除占位。输入／保存／取消及反馈在绝对定位编辑层，整体上限440px且不超出容器；输入可收缩，按钮不换行，统一32px控件高度。需求编辑层居中，文档编辑层左对齐。输入聚焦使用preventScroll，取消／成功仍沿原焦点恢复。错误、保存进度及UNKNOWN／CONFIRMED核实也在该层，不增加标题／元数据行或页头高度；文档非改名操作的原反馈保留。输入／输出不变，不通过全局固定页头高度掩盖局部排版问题。

公共组件NameEditor契约（shared/name-editor.tsx，供后续按正式FE组件职责归并）：

| 输入／事件 | 当前定义及默认值 | 责任边界 |
| --- | --- | --- |
| label／value／draft／editing | 必传；可访问名称／实际名称／未提交文字／编辑状态 | 名称与草稿均由原业务适配器控制，组件不自建保存状态 |
| heading／canRename | heading默认strong，可选h1；canRename默认true | 文档strong、需求h1；是否显示入口与写权限分开 |
| disabled／inputDisabled／readOnly | 默认false／跟随disabled／false | 禁用入口与输入；UNKNOWN等保留只读文字，不改原请求 |
| saveDisabled／cancelDisabled | 默认inputDisabled或readOnly／false，适配器可显式覆盖 | 能否保存／取消由原命令阶段决定，不用关闭浮层取消服务端动作 |
| feedback | 可选ReactNode | 错误、状态及核实入口位于绝对定位层，不撑开页面 |
| begin／change(value)／save／cancel | 必传回调，只表达用户动作 | 组件不调用API，不生成幂等键，不校验业务版本或写正文 |
