## 3. 主要流程缺口

### 3.1 已回答与允许写入正文是两种状态，推进环节没有闭合

`messages/cards.py::formal_answer_text`只保存问题、所选label、自定义答案；正式结构保存card_key／selected_option_keys等。用户提交有效，`guide/commands.py::submit_card_responses`为初始化创建新Run，触发消息正确绑定新回答。

但`guide/output_evidence.py::validate_fact_patches`与`_formal_proves`采用严格完整声明证明：普通单选／多选选择不能直接证明一项正文补丁。可写入的CARD_RESPONSE必须来自CONFIRM卡，包含目标、章节、操作、完整旧正文与新正文的具体声明，用户选择confirm；另一条路径是USER TEXT整条恰为该完整声明。原始想法和本次普通选择均不满足这个写入条件。该保护已有明确Prompt说明，不能在修复中擅自把普通选项升级为已确认正文。

正常下一步应利用已提交答案形成具体候选正文，再请求相应CONFIRM；用户确认后才产出可通过证明的confirmed_fact_patches。当前Prompt虽然说明“未有证明可生成上述确认卡片”，但未明确要求回答后的阶段推进及禁止无原因重问已回答项。实际模型连续选择重新问范围，未生成事实确认卡片，确认环节没有发生。

### 3.2 模型缺少完整、明确的已回答事实视图

`guide/model_context.py::read_context`有意排除INTERACTION_CARDS历史，以免把未选择推荐当事实；传输中的formal_responses只有选择键，没有对应原卡及已选option的完整description／impact。问题与label仍在真实摘要中，因此不能说模型不知道用户回答；但结构化回答的完整语义及原卡绑定没有随选择键展开。服务端在验证时可回查原卡，模型却只看到有限摘要。

建议在后续版本中从原不可变卡片及正式回答派生明确的“已提交选择”视图，带来源消息／原卡身份、问题、实际所选option内容及自定义回答／跳过状态；不注入未选选项或推荐，不伪造新用户证据。与最终写入确认状态分别表达，历史裁剪时不能悄然丢掉尚未完成确认的选择。

### 3.3 合法输出不等于流程有进展

`guide/trusted_output.py::validate_business_output`检查卡片结构、卡片文本等价、读取来源及补丁证明，但没有跨轮“已回答且无新冲突／信息缺口又原样提问”的检查。

`guide/result_persistence.py::persist_ai_result`允许初始化空补丁＋卡片输出正常保存、结束本轮并释放占用；空补丁不更新正文版本。因而每次都在技术上成功，业务上没有推进，形成“提交答案→新Run→同组问题→空补丁→完成”的循环。

不能仅按全局card_key去重：这几轮虽然重复使用同三个键，选项已变化，且后一次用户主动换了目标选择。修复应按原问题与已提交答案的实际语义／来源识别重复，允许有明确原因的冲突澄清或更细问题；本例仓库和AI范围连续未变化，不应无理由再次从头问。

## 4. 建议修复路径（待实施）

1. 在模型上下文中明确区分“已提交的意图／选择”“待确认的具体正文”“已确认并写入正文”；补足所选项语义及不可变来源绑定，保留原事实证据校验。
2. 新版初始化Prompt明确阶段推进：选择完成后优先提出基于所选事实的具体CONFIRM；后续问题只补实际缺口。有冲突时列出具体矛盾，本轮新选择优先，不从头重复整个范围组。
3. 为初始化结果加入无进展检查与可观察原因，拦截无理由重复已回答问题；不要用无限自动重试制造额外付费调用，也不要静默过滤全部卡片后冒称完成。
4. 模板、正文及元数据体积优化另行版本化评估，保持完整模板原文、稳定前缀、计数／发送／审计同文与实际权限；不直接扩大预算来掩盖推进缺口。

任何生产改动须采用新冻结资源版本，保留现有v5历史恢复，不能原地改Prompt后破坏已发生调用的审计。不得自动更改Message20／22的选择、补写用户正文或重发现有运行。

## 5. 后续检查与当前结论

后续针对性离线检查应覆盖：普通选择→具体确认卡→确认后写入；两轮已提交选择持续保留；原卡所选项完整语义与未选推荐隔离；用户改选的冲突处理；重复无进展输出拦截；拒绝defer／跳过／未提交选择作为事实；旧冻结运行恢复及身份／计数审计保持。

本轮未运行上述检查，也未实现建议。当前主要结论由实际请求和输出支持：正式答案已送达，但未转入正文确认阶段，同时缺少跨轮推进保护；重复不是前端重复显示、答案丢失、历史裁剪或缓存未命中造成。修复后的模型行为仍需在授权范围内验证。
