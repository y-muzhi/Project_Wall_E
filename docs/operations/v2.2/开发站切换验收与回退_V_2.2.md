## 开始条件

- [ ] 确认切换授权、操作人、验收人、回退决策人和维护窗口，记录预计完成时间和最晚回退决策时间。记录源开发站环境 ID、数据代次、部署 ID、配置／程序／Schema 摘要、当前运行 ID，登记目标绑定和新数据代次。对集成记录对应的绑定、运行 ID 和能力。记录现场单元及 Unix 套接字，确认两边归属。
- [ ] 固定开发候选和前端制品。确认安装方已交付经独立演练的受管跨结构执行及回退清单，包括原停写、封存与读取、目标只读核对、选择与开放、反向保全、旧部署重新开放。清单须带实际命令、策略路径、操作 ID 取得方式及预期回执，且与本次源／目标绑定吻合。`describe-restore-deployment` 的 `document-ai-deployment-policy.v1.json` 预览回执只用于目标配置核对。缺少实际切换或回退入口即停止于本步骤。
- [ ] 采用已验收的开发账号常驻出口 `http://127.0.0.1:17890`。在受信开发模型策略中将 `local_http_proxy` 固定到该地址，并核对其摘要、目标绑定及 systemd 凭据引用。仅经当前明确授权才执行真实模型与计数验收，先填测试文档、最大次数、预算及重试上限。缺少授权时标记供应方验收待执行。若当日放行标准要求真实供应方验收，停在放行前。[常驻代理实机验收](../../verification/v2.2/mac-linux-openai-proxy-installed-2026-11-27.md)

## 当天执行顺序

| 步骤 | 操作 | 通过条件 | 停止条件与动作 |
| --- | --- | --- | --- |
| 1. 双站基线 | 从两个 HTTPS 入口分别打开工作台，在浏览器 Network 记录 `/`、`/.well-known/walle-environment.json`、`GET /api/v1/environment`、`GET /api/v1/requirements`，核对静态入口及模块。开发预选已有需求、文档、未提交的服务端人工草稿、有多个修订版的文档，记 ID、草稿基准、修订序列及内容摘要或受控比对位置。保留仍有本机未同步输入的原标签。 | TLS 受信，页面可用，资产和 API 同源。固定入口、握手和响应环境／代次一致。两站可读各自预选记录。切换前开发及集成的文档 AI 与其它三项 AI／执行能力应为 `DISABLED`，实际基线若偏离则先查明。 | TLS、绑定、资产加载、预选记录或基线偏差不明时，停止且保持原运行。 |
| 2. 停写与封存 | 按已核准的开发操作停写并暂停外发。读回开发在途指引、未决保存／回执、进程与控制状态。封存原库、审计及原结果索引，独立读回，确认原程序、前端和控制凭证可用于回退。浏览器有本机未同步输入时先通过产品的草稿核对／导出保全。 | 开发写入与外发关闭，在途和结果未知均已处理。封存摘要及来源对应原开发代次，原库仍在原位。数据库、草稿与历史基线更新至停写点。集成仍在原运行。 | 有未决操作、封存缺失或来源不符时停止。按原操作读回状态，再按回退 A 处置。 |
| 3. 准备新代次 | 在独立目标库跑受管恢复与结构转换。重新打开目标只读应用，从独立只读入口核对正文、服务端草稿、修订和历史。核对保留行、审计、源摘要、新旧绑定以及回执。 | 环境 ID 沿用开发，新代次与原代次不同，部署／配置与固定目标匹配。目标有 200／210 迁移记录，完整性及外键通过。原库摘要和归属匹配封存点。只读身份的写入及 AI 拒绝，外发暂停。 | 任一数据差异、错绑定、旧库变动或意外写入／外发时停止。未选择目标走 A，结果未知走 B。 |
| 4. 闭态选择与网关复核 | 按固定维护步骤选择目标，保持普通服务关闭。运行候选的私有只读检查，获取绑定到同一目标代次、控制摘要和原开发 HTTPS 的网关验证回执。 | 选择回执、只读验证及网关回执均指向同一候选，原开发 HTTPS 保持受控，外发仍暂停。 | 无法核对选择、网关或只读证据时停止。确认目标未开放后走 A 或 B。 |
| 5. 开放后入口、原内容和草稿 | 核对第 4 步的证据和开发模型策略后，使用 `serve-release-open` 开放。立即从原开发 HTTPS 新标签核对页面、静态模块、握手和同源 API。分别使用原开发代次和集成环境 ID 发只读负例。在隔离浏览器资料的旧标签验证本机草稿保全，并核对服务端草稿、修订和历史。 | 页面与当前绑定一致。旧代次返回 `409 DATA_GENERATION_MISMATCH`，错环境返回 `409 ENVIRONMENT_MISMATCH`。旧标签冻结编辑，未自动重放。原草稿与历史符合停写基线。 | 开放失败时先读回实际控制，仍关闭则走 B。已开放或状态未知时先关闭新写入与外发，走 C。 |
| 6. 开发权限与文档 AI | 受控开放后分别使用开发编辑和只读身份查看能力。编辑身份读 `GET /api/v1/requirements/{id}/guide-runs`，只读身份与集成用已知夹具检查同一路由受限。核对开发恢复态、只读及其它三项 AI／执行能力限制。获授权才在专用测试文档按批准预算执行对话、生成、修订和审阅中获批的步骤，核对记录、落盘版本和计数／模型审计。 | 开发编辑开放态 `DOCUMENT_AI=READY`，人工读写保留。只读／恢复态文档 AI 不开放，集成与其它三项能力继续 `DISABLED`。获批的真实检查与预算、请求及审计一一对应。 | 无权限身份可调用、模型策略错误、结果异常或请求状态未知时先暂停外发和新写入。核对原任务与审计，按 C 处理。 |
| 7. 集成复核与放行 | 重复步骤 1 的集成页面和 API，核对集成受管进程、运行 ID、预选记录及能力。重新读取开发入口、要求的受管结算回执及测试文档。登记放行决定后才解除剩余维护限制。 | 集成环境 ID、部署、数据代次、运行 ID、能力和预选内容与窗口基线一致。开发所有当日必验项通过，回退源及证据仍可读。 | 集成状态变化、开发回执未结算、任一必验项未通过或已到回退决策时间时，停止放行并进入适用的回退分支。 |

业务 GET 优先使用页面已经发出的同源请求。需构造负例时，在正确 HTTPS 的测试标签使用当前已认证浏览器发 GET，并带 `X-WALL-E-Environment-ID`、`X-WALL-E-Data-Generation`、`X-WALL-E-Binding-Protocol: 1` 和 `X-WALL-E-Client: web-v1`。每次只改预定的绑定项。`401`、`404` 或来源拒绝须先定位，不能作为代次保护或权限通过的证据。

正文、草稿、修订列表和指引运行列表请求带 `document_id`，修订列表按分页读取。用 `GET /api/v1/revisions/{revision_id}` 核对预选修订内容。开放态只读及集成的指引运行列表应返回 `403 ENVIRONMENT_CAPABILITY_DISABLED`，恢复态应返回 `403 RECOVERY_READ_ONLY`。

## 回退与复验

| 分支 | 执行步骤与通过条件 |
| --- | --- |
| A. 尚未写入选择回执 | 核对原操作和控制状态。若已停写且确认未写入选择回执，使用获准的原维护取消流程。保留封存和候选证据，重开原部署，复验 HTTPS、原代次、权限、草稿和历史。 |
| B. 已写入选择回执，普通服务仍关闭 | 先核对原操作和控制，确认候选尚未开放。停止本次只读候选与相关套接字。以内容、摘要均与原切换策略一致的 `document-ai-restore-revert.v1.json` 调用 `select-release-deployment`。按回退回执确认原部署及原数据代次恢复，保留两代数据。重开原 HTTPS 后复验。控制无法核实时转 C。 |
| C. 新代次已开放或实际状态未知 | 暂停新写入和外发，读回控制、原操作键、进程、在途任务及审计。确认开放过时，封存新代次数据库、请求回执、审计及新增草稿，保全本机输入。按新结构继续修复或使用经核准的同结构恢复。原库保持保全；这一阶段不能用 B 的命令恢复旧库。 |

跨结构回退使用经核准的整组恢复流程。`ROLLBACK_CODE` 适用于同结构，不能让旧程序读取转换后的库。受管回执结果未知时，先核对同一个原操作，避免重复选择、重启或外发。

回退完成标准为原开发绑定的 HTTPS 页面和同源 API 正常、旧草稿与历史仍可读、原能力矩阵恢复、测试新代次的请求被原入口拒绝、集成仍符合窗口基线。记录实际恢复的运行 ID、部署／代次、操作回执、剩余待处理数据和下一位处置人。
