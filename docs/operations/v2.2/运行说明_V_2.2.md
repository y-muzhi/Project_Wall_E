# WALL-E V2.2 运行说明

2026-11-27 确认。日常运行使用 Mac 上的 Linux 虚拟机。开发和集成环境各自运行后端、提供对应的已构建前端，并使用独立数据。Linux 上的 Caddy 接收 HTTPS 请求，通过各环境的 Unix 套接字转发给对应后端。

## 日常访问

| 环境 | HTTPS 入口 |
| --- | --- |
| 开发 | [开发环境](https://e-fea4f0eb-791e-405c-b6d1-55e744741c42.walle-dev.test:9443) |
| 集成 | [集成环境](https://e-a90dea3e-c702-4d58-bc90-bd679a8ad5b3.walle-dev.test:9443) |

在已配置的 Windows 工作站打开项目目录下的 `output/v22-mac-access/打开 Mac WALL-E.cmd`。启动器经 Mac 的 SSH 跳板连接 Linux，将 Windows `127.0.0.1:9443` 转发到 Linux `127.0.0.1:9443` 的 Caddy 网关，为浏览器配置两个站点的域名和认证，再打开两套环境。访问期间保持启动器运行。每个站点的前端和 `/api/v1` 共用表中的 HTTPS 入口。

Mac 当前的局域网 SSH 跳板地址为 `192.168.31.160:22`（2026-11-27 用户确认，常驻代理安装时已通过严格主机密钥校验连接双端）。Windows 的 `walle-mac` SSH 别名应指向该地址，`walle-linux` 继续经该跳板连接 Linux 来宾。若本机别名仍指向旧地址，连接前需更新 `HostName` 或在本次命令覆盖地址，并按现有信任记录严格校验 Mac 主机密钥。

## 核对服务状态

1. 确认要查的是开发还是集成环境。Windows 启动器连接失败时，先核对 Mac 连通性、`walle-mac` 和 `walle-linux` SSH 配置，以及本机 `9443` 的占用。
2. 通过对应入口检查首页、`GET /api/v1/environment` 和需求列表。业务 API 使用站点认证和当前环境绑定，需求列表核对使用浏览器或同等的已认证同源请求。
3. 需要进一步定位时，在 Linux 核对 Caddy 的 `9443` 监听，以及目标环境的后端进程和 Unix 套接字。获准发布或启停前，先核对该环境和在途任务，完成后经同一 HTTPS 入口复核页面与 API。

开发站文档 AI 的切换当天使用 [开发站切换验收与回退](开发站切换验收与回退_V_2.2.md)。安装及隔离验证见 [V2.2 实施计划](../../project/v2.2/实施计划_V_2.2.md)。早期 Windows `8001` 和临时 Vite `5174` 的记录按各自版本查阅。
