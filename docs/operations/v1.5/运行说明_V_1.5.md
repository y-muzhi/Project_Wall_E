# WALL-E V1.5 本地运行说明

本页只提供有效操作步骤，不维护进程实时状态。最近现场及其日期见[当前断点](../../project/v1.5/实现进度_V_1.5.md)；启动前重新核对实际WALL-E进程及在途工作。文档中的命令不是自动执行授权。

## 已有正常库与后端

当前已有正常库`data/wall-e-v1.5.sqlite`，schema150；旧`data/wall-e.sqlite`不迁移、不清除。已有库只校验，不重复初始化。先在项目根PowerShell指定绝对路径：

```powershell
$env:WALLE_DATABASE_PATH = Join-Path (Get-Location).Path 'data/wall-e-v1.5.sqlite'
.\.venv\Scripts\python.exe -m backend.app.infrastructure.database check
```

获准启动且确认没有重复服务时，人工能力可用直接入口：

```powershell
.\.venv\Scripts\python.exe -m backend.app
```

后端绑定127.0.0.1:8000，单worker、无reload、不自动初始化。直接入口不读取.env.local；使用AI时按下方安全助手启动，二者不能同时运行。未配置凭据或同release准入时，AI沿真实门禁拒绝。

## 仅首次创建独立新库

此步骤只适用于确需建立一个全新V1.5数据环境，并已确认允许创建的情况。选择明确不存在的文件名，再设置绝对WALLE_DATABASE_PATH后运行：

```powershell
.\.venv\Scripts\python.exe -m backend.app.infrastructure.database init
.\.venv\Scripts\python.exe -m backend.app.infrastructure.database check
```

不把本步骤套用于已有正常库，不清库、不覆盖旧数据。新目标库的AI准入需要另按下方规则核实或显式导入。

## 开发前端与生产静态资源

获准启动时，另一个终端进入frontend：

```powershell
cd frontend
npm.cmd run dev
```

使用http://127.0.0.1:5173/requirements，由Vite加载源码并代理8000。历次临时构建不等于部署frontend/dist；8000的静态目录不能据此认定为最新前端。确需生产部署时，按当前更新授权运行`npm.cmd run build`并核对服务使用的目录，不自动覆盖正在使用的资源。

## AI准入与安全启动助手

当前冻结资源在backend/resources/v15。manifest=a8c5087236d8e4b4b40d62a92643832fe37cc2b5e426725f1ddde7d5670abc40，release=5ced9443c445aa10330e906a875fd4dafe69b6ebe0eb5e40179251b5eefb5d97，profile=61941797052baa3c4a6cc1df54759b91d7fa933d2a4b98ec19d8b3b116cfc70e，模型deepseek-v4-1-flash-260910。冻结文件初始OFFLINE_READY保持原字节；运行时技术LIVE由正常数据库／计数审计证据核实，不通过改配置标志放行。

已记录的v15合格技术来源为data/v15-observation-20261024-v15-once/observation.sqlite的LLMUse1。源库及旁边count-audit／准入JSON必须保留；不存在自动迁移或向用户库自动导入。若明确允许为一个已初始化的新目标库配置，使用原程序入口导入并核实，操作不调用供应方或改业务正文：

```powershell
$technicalEvidence = Join-Path (Get-Location).Path 'data/v15-observation-20261024-v15-once/observation.sqlite'
.\.venv\Scripts\python.exe tools/admit-v15-resource.py --database $env:WALLE_DATABASE_PATH --approve-saved-call --source-database $technicalEvidence --llm-use-id 1
.\.venv\Scripts\python.exe tools/admit-v15-resource.py --database $env:WALLE_DATABASE_PATH
```

上述准入导入已于2026-10-25仅在新建wall-e-v1.5.sqlite执行，旧库未操作。准入不是新的付费许可，也不证明全部语义效果；Prompt／Schema／profile／布局改变须按同release规则重新核对，不继承旧v14等凭证。

启动助手默认完全离线检查资源／预算，不读取密钥或打开数据库，不启动服务、不计数／Chat：

```powershell
.\.venv\Scripts\python.exe tools/ai-service.py
```

已经核实目标库和准入、且明确允许启动AI服务时，可替代上方直接后端命令使用：

```powershell
.\.venv\Scripts\python.exe tools/ai-service.py --start --credential-file (Join-Path (Get-Location).Path '.env.local')
```

助手先核对绝对已存在schema150库与同release正常证据，再安全读取凭证；只设置该启动进程环境，不输出或持久化密钥，不自动导入准入或创建库。走原8000单worker服务入口；不要同时再启动第二个后端。只读GET复用已有runtime.catalog，保存请求详情不重新编译、计数或调用模型。

## 调用与预算边界

每次Chat输入≤131072、输出≤8192、总量≤139264，预留1024；最多三个不同计数候选，先移除可选历史，再移除可选邻近背景，不删必要正文；未知计数、超预算及失败传输不自动重试。当前北京端点／固定DeepSeek模型单批计数text UTF-8合计≤800000字节，独立于Chat Token上限。响应最多8MiB内存读取、单项持久审计4MiB，摘要只能支持超预算否决，不能批准Chat。

已记录的真实许可均已执行结束；未花费的最大次数不能续用。后续代理执行真实计数／Chat仍须明确次数、预算、重试边界及全新隔离槽；不以查看、复制快照、只读详情或离线检查暗中触发。正常审计、已占槽及历史失败不得清理后重用。

## H06长文档配置与使用（2026-10-29）

分章操作：在生成设置选择“创建框架，分章撰写”，提交新建框架后点“分章节撰写当前文档”，选择一章、填写要求并发送。成功后可选择下一章；每次需明确发送，不自动续写。已有文档也可直接分章；正文版本变化后显式使用最新版本，历史章节保持。截断时不写入，缩小章节后再发。

新增可选profile：`deepseek-long-v3`，同一模型deepseek-v4-1-flash-260910，输入131072、输出32768、总量163840、framing1024、零重试，读超时仍180秒。上限是限额而非保证一次完成；供应方超时、预算不足或截断仍需按实际失败处理。

新资源backend/resources/v16：manifest=8a4a16de358eb66a6d057ffba4e54fd3b2e696d4673754cfe1435b0bb79ebc5e，release=8c218ea79f3ef14c778a0581fddfac8ba65e8c1fc1902936244ff4a13f512027；counting v2、contract v4、release v8，Prompt沿用v6原字节。本轮仅OFFLINE_READY，未取得真实准入，旧v15来源不能导入为v16证据。

后续获准启用时，配置`WALLE_MODEL_PROFILE=deepseek-long-v3`；ResourceCatalog与ModelProfile同步选择新资源／预算。仍须先完成当前明确授权的隔离真实观测并显式导入对应证据，再按既有程序更新服务。CLI `tools/observe-v15-once.py --profile deepseek-long-v3`默认只离线预览；真实模式必须另明确1—3计数批、1次Chat、163840总预算及新独占输出目录，不可复用历史许可。准入工具使用`--profile deepseek-long-v3`核对／导入相同配置。上述是操作说明，不代表本轮已执行真实调用或服务切换。

不设置新profile时继续deepseek-v2／v15／8192输出。历史请求读取和恢复按其冻结release和profile，不能借新限额放宽旧审计。变更profile不改正常业务数据库或旧资源字节。
