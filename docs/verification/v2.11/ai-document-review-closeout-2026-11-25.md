## 问题和对应修复

- 第二份草稿最初在持久化回读处被旧的需求级单行判断拒绝。改为基于草稿 ID 的真实读取，创建、保存、提交和取消分别核对目标及版本。运行恢复保留合法占用，旧版代表性需求状态仍可读取。
- OpenAI 准入回读最初只识别旧结构。新增候选采用独立摘要，先用实际标记选出候选，再按冻结对象校验。旧 `Schema210` 构造源和发布文件保留原字节。
- 提交一篇草稿过程中立即切换时，原页面可能显示尚未保存。切换等待已有完成请求收敛后再读目的文档，保留原命令结果及失败恢复。
- 截断响应可能带可读 JSON。文档操作现在按真实 `finish_reason=length` 结束为失败，审计保留原返回和解析未通过状态。不会创建文档、应用正文或生成有效批次。OpenAI 文档写入读取等待调整为 1,800 秒，讨论仍为 180 秒。
- 输入用量 131,072、输出 100,000 的模拟回包经过原生 HTTP 与程序校验，审计超过 300,000 字节，整份生成正文准确保存。输入 131,073 在允许的候选计数范围内被拒绝，模型发送次数为零。普通讨论仍使用原冻结配置及等待时长。
- 首轮扩大回归中，Windows 的隔离路径过长导致旧准入回执的原子改名失败。复跑使用短 `--basetemp`，不调整生产准入文件名。
