# D-011 计数编排与独立审计验证

记录日期：2026-10-06。范围是内部准确计数、实际编排/后台、SQLite C03/C07、独立文件审计与本机可控计数/Chat TCP。真实 Ark、付费调用、Chat 封装兼容证明、模型效果与全部 373 正式验收不在本记录通过范围内。

## 实现与门禁

`counted_context.py` 的每轮完整文本、Schema 来源、固定预算、裁剪顺序及 Read Manifest 从最新实际 C03 重新验证；不能用另一输入的计数授权发送。完整签名 v1/v2 输出校验器不变。AuditRepository 在短写事务内重查实际事实并保存私有计数摘要，可信结果校验重新复现每一轮候选，之后才可进入原 C07 原子提交。

ORCH 的准确计数是私有依赖分支，计数前和 Chat 前均要求兼容门禁。没有公开 HTTP 或环境变量选择器；候选仍 `production_enabled=false`，证据仍 `compatibility_proved=false`。测试显式注入离线兼容回调，不能作为真实同模型两角色封装及 256 预留的证明。生产默认路径继续保守拒绝未证明的请求。

计数等待不持有 SQL 写事务，每轮计数前重查 Run/占用/内容/正式来源；Chat 重试在 2/5 秒等待后只重新组装和计数一次，不在等待前产生一份弃用计数，也不嵌套计数重试。计数失败不会发 Chat。已批准模型、预算、采样参数、公开字段、DDL 和资源字节不变。

## 独立文件审计

计数记录保存在数据库旁的 `<数据库文件名>.count-audit`，分别为 UUID 的 prepared/finished 文件，不与每个 Chat 尝试的 LLMUse 混计。准备文件经脱敏、容量校验、独占创建、flush/fsync 后才允许计数 I/O；观察到的成功、失败或中断单独留结果。PREPARED 不证明已发送或付费，缺结果保留未知；启动不重发、不补造完成结果。

写入要求实际数据库进程锁，并受任务 lease 退休门禁约束。退休先胜禁止迟到文件写入；已经开始的 fsync 完成后退休才返回。新进程不能为旧准备记录制造完成结果。路径拒绝符号重定向，文件 ID 固定校验；部分准备文件或容量/保存失败拒绝后续步骤。此处验证 flush/fsync 与实际竞争，不宣称已经证明所有断电/磁盘故障的目录持久性。

成功原始计数数组严格保留 30 天，过期后用同目录临时文件及替换仅清理原始响应，保留请求、计数、来源、哈希和身份；边界当天不清理，未知/失败记录和无关文件保留。Chat 请求快照只存计数摘要，不将分词响应放入 LLMUse 的 Chat 原始响应字段。审计目录、业务库和凭据均忽略，不进入 Git。
