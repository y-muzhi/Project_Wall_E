# 测试记录保留规则

2026-10-08 用户要求删除测试生成的 JSON 和截图，后续仅在 Markdown 中记录测试结果。本规则取代历史文档中的原始证据留存要求。

本次清理：删除 3,690 个测试 JSON 和 647 张截图。其中版本库原有报告 1,296 个、截图 234 张；忽略目录中的测试输出 JSON 2,394 个、截图 413 张。保留 70 份原有专题 Markdown，另新增本规则及历史摘要。仅静态核对文件清单，没有执行产品测试。`output/clean-install-*` 副本中的依赖清单、Schema、正式资源和夹具属于测试输入，未当作结果文件删除。

保留本目录已有专题 Markdown。历史文字中的 JSON/截图路径仅表示当时使用的文件，原文件现已按用户要求删除，不再是可用附件。清理前的 JSON 顶层结果摘要见 [历史测试报告摘要](历史测试报告摘要.md)；摘要不是重新执行或重新验收。没有统一结果字段的报告不推断为通过，既有失败、未验证状态不因清理而变更。

后续得到测试授权后，记录以下内容即可：

- 日期、代码版本、测试范围及必要环境。
- 实际执行命令、通过/失败/中断结果及关键计数。
- 失败原因、修复情况和仍未覆盖的内容。

不保存测试截图、JSON 报告、录像或原始日志，也不把原始 JSON 换后缀塞入 Markdown。旧验证脚本存在生成和消费 JSON/截图的链路，不应直接照历史命令运行；先改为内存或临时目录处理、把结论写入 Markdown，并在退出时清理临时文件。

清理入口为 `python tools/cleanup-test-artifacts.py`，可加 `--dry-run` 只查看数量。工具仅处理 `docs/verification` 和 `output` 中的测试 JSON/截图，跳过依赖目录、符号链接及 clean-install 副本中的应用输入；不会读取凭据、启动服务、执行测试或改变验收台账。配置、Schema、夹具和正常业务审计属于程序输入或业务事实，继续保留。

当前测试与验收仍按用户先前要求暂停。本次只是文件清理。
