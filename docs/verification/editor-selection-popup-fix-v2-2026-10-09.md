# UX-019 浮动样式点击和选区定位基础检查

日期：2026-10-09。范围：修复浮动正文／标题选择器真实点击，统一编辑器内外焦点边界，定位到完整选区上方。实际规则见[迭代文档第27节](../design/WALL-E.V1_0.6.迭代优化V2文档.md#v2-19-implementation)。

## 复现及原因

在5179隔离内存编辑器页面，点击“测试选中正文”后，真实点击“选区正文或标题级别”，浮动栏hidden=true，activeElement没有控件名称，复现无法展开。前轮selectOption检查绕过点击展开过程，没有覆盖该缺陷。

原因是正文到body挂载浮动控件的焦点过渡被当作外部离焦；焦点尚未落到选择器，更新隐藏了浮窗。原位置从选区末端计算且允许向下翻转，也不符合新定位要求。

```text
npm.cmd run typecheck
npm.cmd run build -- --logLevel warn
node --test --test-reporter=spec frontend/tests/selection-toolbar-position.test.mjs frontend/tests/editor-interactions.test.mjs
```

npm命令在frontend目录执行，node检查命令在项目根目录执行。类型检查及最终含TypeScript的生产构建通过，只有既有超过500kB产物提示。7项基础检查通过、失败0；其中新增3项覆盖整个选区上沿、横向边界、顶部不翻转、选区离开／回到可见区域。

## 修复后真实操作

使用相同内存夹具和1280×900尺寸；没有业务API、自动保存、数据库或模型请求。

|观察|实际结果|
|---|---|
|点击展开|修复后实际点击原生下拉框，浮窗hidden=false，焦点为“选区正文或标题级别”；点击前后位置均x24、y134.5，未隐藏或跳动|
|样式选择|实际点击后↓＋Enter把“正文测试”转为h1；重新选中该文字、点击选择器、Home＋Enter切回正文。最终p为“正文测试”，h1只保留原“测试标题”|
|内部焦点|夹具给真实blur回调计数。初始选中正文、点击浮动选择器，计数都为0；进入浮动控件没有被当作离开编辑器|
|外部焦点及冻结|通过外部夹具按钮重新选择文字，计数为1；之后点击外部“冻结测试编辑器”，计数为2，只读状态true，浮动栏隐藏。真实离开仍通知，未取消离焦行为|
|上方锚定|正文选区上沿188.5px，浮窗上沿134.5px／下沿180.5px，间距8px。横向因正文左边界夹取为24px；不是从选区文字末尾开始|

新增的几何边界由基础测试覆盖。长文档实机滚动、复杂多行／跨块选区、原生菜单各浏览器差异、真实自动保存竞争和输入法没有新增完整端到端验收，不据这次短观察宣称全部场景通过。
