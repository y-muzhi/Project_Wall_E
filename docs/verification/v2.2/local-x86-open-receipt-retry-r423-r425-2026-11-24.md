# R423／R425 原开放回执续办与固定目标的普通重启

2026-11-24（香港时间）。独立 `codex/2.2` 当前工作文件、固定 Ubuntu 24.04.5 x86_64／ext4、CPython 3.13.18、SQLite 3.54.1。沿 R418 专属部署输入，固定当前前端，实际 Caddy 只监听来宾回环 9443。两个子演练使用独立来宾覆盖盘、数据库、应用身份、操作、回执和本地验证资料。

- R423 在实际目标进程写入并同步原开放回执后，于更新 `control.v1.json` 为 OPEN 前模拟一次磁盘写入失败。真实应用退出并清理自己的套接字。开放回执存在，控制仍为同一 `CLOSED/RECOVERY_REQUIRED`，原主库摘要保持。固定观察以退出值 3 返回 `PENDING_RECONCILIATION`，另一站仍读原草稿。
- 移除注入后，使用同一原操作、同一运行 ID 和原计划调用原固定启动入口。原回执逐字节复用，应用实际进入 OPEN，原正文可读。正常停机及在宿主冻结后读取同一原事实通过。夹具初轮缺少固定时区环境而在实际启动前被拒，补齐已声明的 `TZ=UTC` 后重新完成。
- R425 在另一个完整切换样本中，实际固定目标开放并正常停止。使用旧部署的普通启动准备被拒绝。使用固定目标重新准备，取得新的普通运行 ID，经正常入口读回原正文，再次调用旧开放动作被拒。两个实际应用正常停止，原发布开放回执保留且独立于新的当前普通开放回执，原数据库和稳定锁身份不变。运行阶段均退出 0。

两阶段测试只使用本轮按原归属创建的资料。R423 注入点位于专属夹具，不进入用户源码或固定发布产物。正式候选和受管发布登记另行验证。
