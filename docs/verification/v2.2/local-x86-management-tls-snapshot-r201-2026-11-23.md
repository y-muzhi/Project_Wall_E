# R201 Ubuntu x86_64 独立管理站、停派发及快照

2026-11-23，独立 `codex/2.2`。Ubuntu 24.04 x86_64、实际 ext4、固定 Python 3.13.18／SQLite 3.54.1、Caddy 2.6.2。后台程序为本机 R192／R193 实测程序加 R200 原管理观测修订，独立普通源数据沿同一停机盘。

- 以真实 `manage_registry.py prepare`、`initialize`、`diagnose` 建立独立管理 UID、锁、登记库与初始化事实。使用正式 `gateway` 生成管理站单独的 TLS 配置，`serve` 经独立受保护 Unix 套接字运行。采用隔离管理静态产物、独立连接组、独立临时 CA、虚拟机回环 9444。
- 在真实 TLS 中分别验证 MANAGER、DEVELOPER、VIEWER。未认证返回 401，普通业务路由返回 404，管理进程关闭返回 502。伪造入口身份头没有增权，错误来源及 VIEWER 写入返回 403，错登记代次返回 409。新管理库真实返回空目录。
- 原管理服务正常关停后，以固定工具捕获格式 2 快照。通过原宿主工具停派发，管理站新运行 ID 仍读回原管理资料并报告 `BLOCKED`。随后以同一暂停的保护凭证捕获格式 3 快照。两个快照均在独立连接通过完整性、外键、原作用域和原字节检查，同一原键重试一致。格式 2 原回执为 `61e760089d67f7cd488e0f83adc8ffeec949c528fc6f353b59ee25ae987267a2`，格式 3 为 `35f414b3f918fc1de9bf703993762c125ba530aaf1f01c9b6b1bd9090cbbe332`。
- 两套普通业务库、各自原安装及原控制摘要均保持。实测管理进程正常停止、Unix 套接字消失并释放来宾 9444，宿主无监听端口映射。
- 本次管理登记是新空库。含原启停、交付及未知任务的运行中宿主恢复、生产采用和云宿主未验证。
