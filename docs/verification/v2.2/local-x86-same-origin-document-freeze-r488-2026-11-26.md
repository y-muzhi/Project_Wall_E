# R488 同 HTTPS 入口换代与旧文档操作冻结

2026-11-26。开发和集成独立工作区的当前前端分别通过 `npm run format:check`、`npm test` 各 609 项及 `npm run build`（TypeScript 和 Vite）。两次构建产物各 120 项，逐项字节相同。入口 SHA256 `024c5caa962e072fc724ee3351ece26ecbc404b8b97141e75fa96900197ace6b`。Vite 有既有分块大小提示。

- 无网 Ubuntu 24.04 x86_64 QEMU 来宾，以真实普通程序启动两个物理根、UID、部署、套接字和 SQLite 数据库。测试装配时仅使第二份的环境 UUID 等于原安装，保留两份不同数据代次。实际业务入口使用相同 HTTPS origin 与来宾 CA。普通应用和 TLS 真实，网关在来宾 9443 以正式站点渲染函数分别组装该单一测试 origin。
- Chrome 在原站新建需求和文档。文档实际 HTTP 201 后，仅浏览器回执被测试路由丢弃。切换来宾 Caddy 到第二套安装，核对两套实际公开配置、握手与响应数据代次，第二套对旧数据代次请求返回 409。

- 最初正式网关拓扑拒绝了单普通站构造。改用已准入安装的站点渲染函数组装测试入口，未改产品网关。第二次验证端缺少 Web 所需的同源请求标记，随后按正式请求契约补齐。第三次进入新标签成功，回看旧页的精确匹配漏了中文句号。最终修正断言并重新检查原输入控件值，来宾退出码 0，临时进程、覆盖盘和浏览器资料已清理。
