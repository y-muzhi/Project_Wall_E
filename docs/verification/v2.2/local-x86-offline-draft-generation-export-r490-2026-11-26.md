# R490 同网址换代时保护并导出活动草稿

2026-11-26。最终应用前端入口 SHA256 为 `aab5b4192f56cd925ce0d3de79a839ca06e456e1635c9e63847e641b0fcdf17e`。两个固定 WALL-E 普通安装运行在无网 Ubuntu x86_64 QEMU 来宾。不同部署、UID、数据库及 Unix 套接字，仅测试的环境 UUID 与 HTTPS 地址相同。Chrome 使用独立资料和来宾 CA，Caddy 切换仅监听来宾回环 9443。

- 两站通过真实 API 分别保存同数字 ID 的文档。浏览器在原站实际进入人工编辑、离线后输入独有正文，保留原页。
- 切换实际 Caddy 到新代次的普通安装，两侧公开配置和握手各自匹配。来宾回环恢复后从原标签核对连接，页面检测到换代、确认本机草稿保护并提供导出。实际下载文本包含旧代次 UUID 和离线输入。
- 显式打开新标签并访问同一文档 ID，只读到后继库自己的正文，旧输入不出现。浏览器检查在离线编辑开始后没有业务写请求。两个实际服务端的正式正文也不含旧本机输入。来宾退出码 0，原启动盘保留，当前运行的临时资料全部清理。
- 初次浏览器夹具漏打开“更多操作”，第二次确认离线编辑但 Chrome 自动联网事件未触发应用核对。最终按现有页面使用显式“重新核对连接”，无需绕过连接、权限或恢复条件。

后继是独立初始化的受控普通安装。正式备份恢复并对同地址部署后的联验仍需配合受信候选。
