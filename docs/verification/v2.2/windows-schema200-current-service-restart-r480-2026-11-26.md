## 固定数据结构

开发 `codex/2.2` 与集成 `codex/2.2-integration` 两个独立工作区各自发布固定 Schema200 `db20-r51`。发布只新增不可变版本并原子更新该工作区固定 pin，既有 `db20-r50` 保留。两侧清单 SHA256 相同：`4ad407e7968738c51b46d861fd28251fd41571f6967deaeed9be90d2b21f76c8`。分别使用现行 SQLite 3.54.1 初始化新临时库，启动校验返回 Schema 200；没有打开、覆盖或迁移用户数据库。

## 当前应用服务链

每个分支用显式 `WALLE_DATABASE_PATH` 指向本分支独立临时 SQLite，由当前 `create_app` 默认数据库装配和固定 `load_release()` 读取 `db20-r51`，启动独立 Uvicorn 单进程，开发端口 18101、集成端口 18102。测试给应用注入当前 `GuideWorker` 和固定 `ResourceCatalog`，不加载模型／计数供应方依赖；前端构建不作为本批业务 API 断言的依据。

两侧各自通过实际 HTTP 完成需求创建、空白文档创建、人工草稿创建、编辑并保存，以及当前需求／文档／草稿读取。然后优雅停止首个服务进程、重新启动全新服务进程，再读回原需求、文档和保存草稿。两侧均退出码 0，重启读回通过，Schema 与固定 manifest 摘要相同；临时数据库、锁和服务日志均在 owner 目录内清理。
