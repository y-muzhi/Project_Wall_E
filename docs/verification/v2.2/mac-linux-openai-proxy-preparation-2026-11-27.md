# Mac 至 Linux 常驻代理准备记录

## 获准安装后的复核

用户已明确授权安装两端代理并复验。Windows `192.168.31.138` 与 Mac 原地址 `192.168.31.142` 在同一子网。`ping -n 2 -w 1000` 检查中，默认网关 `192.168.31.1` 两次均响应，Mac 原地址一次超时、一次由 Windows 报目标主机不可达。随后分别用 10 秒和 8 秒连接超时核对 `walle-mac` 和 `walle-linux`，两者均在 Mac 跳板阶段失败。未进入远端执行安装。恢复 Mac SSH 后从手册的安装前检查接续。模型及计数调用均为零。

## 授权前的准备

2026-11-27（香港时间）。目标是 V2.2 开发环境的 `http://127.0.0.1:17890`。安装、卸载、开发服务身份探针和两端代理进程恢复步骤见[运行手册](../../operations/v2.2/Mac至Linux开发环境OpenAI代理_V_2.2.md)。

- **静态及离线**。Windows 下使用 PowerShell 通过标准输入执行 `python -B -`。转发器与独立检出中实机临时使用的副本 SHA-256 相同。手册两段 Python 命令均通过语法解析。Mock 核对其他域名收到 403 且未打开上游、伪造 Host 不影响固定的 OpenAI 上游请求，以及来源 IPv4 限制，均通过。Windows 沙箱拦截了本机 TCP 连接尝试（WinError 10013）；离线结果只覆盖处理函数与来源判断。
- **实机历史证据**。此前临时 Mac 网桥转发以 Linux 开发账号取得 OpenAI TLS 1.3 和其他域名 CONNECT 403。临时 Linux 单元曾通过 `systemd-analyze verify`，本次手册的完整配置仍需实机核对。[临时实机记录](mac-linux-openai-vpn-2026-11-27.md)
- **本次远程复核**。执行 `ssh -o BatchMode=yes -o ConnectTimeout=6 walle-mac …` 和相同选项的 `walle-linux` 只读检查。沙箱内连接被拒，获准执行只读 SSH 后 Mac 跳板 TCP 22 超时，Linux 跳板连接在 SSH 握手阶段超时。当前网桥、端口占用和服务状态未能重查。常驻安装仍待用户明确授权。本轮未写远端、未改变应用和代理进程，未执行常驻回环 TLS、域名拒绝或进程恢复验收，模型及计数调用均为零。
