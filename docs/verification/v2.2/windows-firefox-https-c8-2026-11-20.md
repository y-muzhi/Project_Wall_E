# WALL-E V2.2 隔离 Firefox 与真实 Linux 页面闭环

2026-11-20（Asia/Hong_Kong）。实际 C8 固定程序、Schema、两个静态根和安装见 [HTTPS 接口闭环](linux-https-document-cycle-c8-2026-11-20.md)。远端 Caddy 与两套真实应用均运行在专用 ARM64 验证机。Windows 使用项目专用 Playwright Core 1.65.1、其固定 Firefox 构建 1572／159.0，官方 ZIP 实际 SHA256 为 `17abdb829293f482dae4c85be9e0dff5995a66457d8b3ca7a7efc6f5ef9c08c5`。两个一次性独立 Firefox 资料分别导入测试 CA 的网站信任，Firefox 正常校验证书和主机名。Windows 和 Linux 系统证书库均保持原状。仅回环 9443，经本轮独占 SSH 转发。

- 初次便携浏览器策略未导入证书，Firefox 实际返回 `SEC_ERROR_UNKNOWN_ISSUER`。改用 Firefox 自带 NSS，分别在两份临时资料的数据库显式导入测试 CA，再正常进入站点。客户端未设置忽略证书错误。名称解析只在这两份资料中生效。
- 开发环境真实页面首次通过 WEB 握手、新建需求和文档并人工编辑，实际自动保存返回 200。修复验证脚本的临时目录识别、原读取响应解码和重启变量引用后，以同一需求打开原草稿，显示此前服务端已保存的内容。关闭本轮所属开发应用后验证重核失败，继续输入未发出 PUT。重启取得新 run，同代次恢复后仍未自动发送。点击“核对并保存草稿”只发出一次 PUT 并保存新的正文。完成编辑、刷新，真实 CURRENT 保留断线期间输入。
- 集成环境用第二份 Firefox 资料进入其独立域，以实际页面完成需求和文档创建、人工编辑、自动保存、完成、刷新读回。两套环境的需求／文档／草稿编号相同，文本不同。普通页面动作期间没有跨站请求。
- 实验结束先按所有权关闭两套应用与网关，确认 Unix 套接字消失，再退出浏览器与专用转发。临时 NSS 资料随实验清除。只保留 Markdown 证据。用户服务、用户浏览器及数据不在验证范围。

覆盖了真实 TLS、浏览器业务主链路及同代次断线重启保持输入。运行中切换 data_generation 的浏览器流程、只读认证、原结果查询、不同标签与配额完整矩阵仍待验。该次运行固定为 C8，C9 新增能力提示未包含在内。
