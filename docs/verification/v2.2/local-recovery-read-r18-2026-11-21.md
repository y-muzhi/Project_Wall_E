# V2.2 R18 关闭状态下的只读恢复专项

2026-11-21。Windows 隔离开发副本。固定启动入口增加 `serve_environment.py serve-recovery`。

- 使用真实命令创建需求和带正文的设计文档，再以 Schema200 SQLite Backup 在新目录换代。应用通过真实 ASGI 生命周期函数、请求中间件和原业务路由读回需求、正文、评论索引、版本和已有消息。工作器、后台恢复和发布路径设为调用即失败的探针，整个试验未触发。握手明确返回 CLOSED、BLOCKED、READ_ONLY 和当前 AVAILABLE 引用。
- 真实只读 SQLite 保持原字节，无 WAL、SHM 或回滚副本。原代次、错误来源、未登记身份、所有实际写入和未核验的命令／执行读路径被拒。取消标记、外发冻结变化、回执替换、访问规则撤除或出现 WAL 时返回不可用。退出释放验证锁。
- 核对过程中确认 SQLite immutable 连接报告的日志模式与文件 WAL 头标记语义不同。普通读写入口仍要求 WAL 连接。恢复入口分别核对冻结文件头、准确字节、完整 Schema200 历史及数据绑定。
- 试验客户端需要本机进程通信，默认受限执行曾停在 Windows 事件循环的 socketpair，已停止本轮进程并清理两处专属临时目录。获准的隔离复跑通过。Linux 用户、稳定锁、ext4 目录和套接字边界由 Windows 适配层提供，线上 Linux 实证与预留恢复安装的生成仍待接。
