# WALL-E V2.2 Firefox 旧数据代次保护负例

2026-11-20（Asia/Hong_Kong）。在 C9 两套真实专用 Linux 安装运行 Caddy、业务后端和固定前端。Windows 使用独立 Firefox 资料及专用 CA，TLS 正常核对。该负例只在 Firefox 的原标签替换固定公开入口响应，刻意给出不同数据代次；真实后端仍报告原代次，用于验证入口与握手不一致时的实际页面。

- 普通页面打开已持久的隔离文档，开始本轮测试草稿。标记断线后输入保留。真实服务未收到任何草稿 PUT。
- 点击重新核对时解析新入口和真实旧代次握手，页面显示环境或代次变化。原人工编辑器进入只读，本机草稿核对成功，原输入仍可见。显式导出文件含原来源、原数据代次和未同步输入，未标成新代次。新标签入口保持原站点，旧页面收到 online 事件后没有重放或重启核对。
- 真实隔离服务确认草稿仍为原版本和原正文。随后按普通 API 完成本轮验证创建的草稿，未把本地输入提交给任何代次。Caddy、两套业务、9443 转发和专用 Firefox 已关闭，临时资料和文件已清除。
- 第一轮同时替换入口及握手的夹具未通过；改成只改变公开入口并保留真实后端握手后得到上述结果。紧接的浏览器脚本需按人工草稿的可访问名称区分可见编辑器与解析器，修正后通过。

这是实际浏览器对不一致入口的负例。服务端完整 RESTORE 产生新数据库及换代后进入新实例的联合流程仍待验证。
