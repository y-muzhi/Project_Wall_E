# R485 模态窗内环境恢复

2026-11-26（香港时间）。两个独立工作区 `codex/2.2` 和 `codex/2.2-integration`。

## 实现及离线检查

浏览器原生模态窗挡住页级连接核对。新建需求或文档的结果待核实时，表单锁定且页级核对不可操作。经源码核对，应用现在将现有连接和换代恢复提示提供给当前打开的新建对话框。连接未就绪时保留原输入和命令，文档提交也禁用。恢复就绪后用户显式核实原请求。详见独立 V2.2 待合并设计。

两工作区分别通过 `npm run format:check`、`npm test`（各 609 项）和 `npm run build -- --outDir <本轮专用目录>`，后者包含类型检查。两边构建均有 Vite 主包大小警告。旧版实机基线启动两台普通应用和正式 HTTPS 网关，但 Playwright 的 Node 直发路径没有来宾域名解析，第一次请求未到达应用。当前实机采用 Chromium DevTools 在真实浏览器收到后端响应后截断，并保持原 TLS 与应用认证。

## 真实 HTTPS 只读身份

Ubuntu x86_64 无网卡来宾中，使用固定安装的两套普通环境及各自 `gateway-check` 只读自动化身份。经固定 Caddy 的 HTTPS 入口和本轮 CA，开发和集成两站的环境握手均返回 `READ_ONLY`，读取需求列表为 200，尝试创建需求返回 403 `ENVIRONMENT_ACCESS_DENIED`。此项覆盖实际只读身份及网关，不等于只读恢复副本的换代浏览器验收。该轮应用和来宾已终止，临时数据随覆盖盘清理。浏览器丢回执仍独立验证。

## 浏览器阶段检查

修订后的来宾在本机 HTTPS 网关转交浏览器的同源创建请求，仅丢弃第一次已成功提交的响应。客户端的原请求键和请求正文仍记录在本轮临时浏览器验证状态。开发站旧补丁同时显示页级和对话框核对动作，浏览器探测选中了被模态窗遮挡的入口。最后的源码采用现有模态栈判断实际接管恢复入口的对话框，只显示其可用入口。

最终构建的开发站需求流程已通过真实 201、结果待核实、唯一核对按钮、核对不自动写入和原键／原请求正文重放。文档流程经核实已读回原文档，但初次工具将完整回执按 JSON 序列化顺序比较，断言失败。接续分别核对请求键、请求正文字节、回执 HTTP 状态和语义字段，查明失败原因。集成浏览器和最终数据库行数仍待完整验证。

## 最终双站实机结果

以两条分支独立构建的 120 个普通前端文件，搭配真实 Linux 双站、独立 Chrome 测试资料和固定 HTTPS 网关。将同源 Chrome 请求由 Playwright 路由转交真实 HTTPS 业务入口，验证环境只为该同源转交保留请求来源标识。需求和文档各在真实 201 后中断一次浏览器接收。每站对话框均只有一个可操作的环境核对入口，核对本身无写入，原键核实请求的键和正文字节与第一次相同，HTTP 结果及 JSON 业务字段一致。文档回执对象字段排序可能不同，最终按语义字段比较。浏览器回到原需求及原文档，真实数据库各只产生 1 条对应需求、1 条对应文档。开发与集成两边全部通过；最后一次隔离来宾同时执行后续 Schema 实验。
