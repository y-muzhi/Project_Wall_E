# V2.2 R63 两套普通环境的最终隔离回归

2026-11-21。Windows 独立实施分支。重新编译本版 Schema，建立两份临时 WAL SQLite 及各自工作目录、环境身份、数据代次、部署、配置和 Windows 独占进程锁。用同一实际 WALL-E `create_app(ordinary=...)`、GuideWorker、OrdinaryScope 及原文档命令运行两套独立生命周期。Starlette TestClient 只建立进程内 HTTP 处理，不监听 TCP。Linux 目录句柄、UID 和持久文件归属使用可见 Windows 适配，事务、Schema、实际数据、生命周期和 Windows 锁均实际运行。

- 两套应用同时开放，真实业务接口创建需求及设计文档，开始编辑、保存并形成新的正文版本。两边故意使用相同需求／文档业务号和相同五个原操作键，各自只读取自己的正文。
- 在同库尝试第二个独占运行锁被拒。向另一环境送入原环境标识，或向原入口送入另一数据代次，均按真实 HTTP 绑定拒绝。
- 先停开发，此时集成保持原 run_id 继续读自己的内容。开发重启后新 run_id、原数据代次及正文保持。集成随后独立停启，同样读回自己的正文。双方实际控制以正常停止收尾，原租约清理。
- R65 补充关停竞争验证。在开发实例的真实写事务更新测试行后暂停该请求，正常停止开发，使其实际 HTTP 事务租约失效，再释放请求。原请求返回 503，重启后测试标题及正文保持原值，集成始终通过同一运行实例读取。没有新进程或 TCP 监听，临时范围正常清理。
- 一次 Windows 测试适配缺少读事务，按实际 `verify_binding` 要求增加事务后全套复跑通过。模型、计数与付费出口不可用，原生 Linux 宿主、独立浏览器与真实 TLS 分别见 C8/C9 既有证据，本轮新代码的 ARM64 联验仍待宿主连接。
