# R211 Ubuntu 恢复管理入口接纳和只读重启

2026-11-23，独立 `codex/2.2`。从 [R204 关闭选择](local-x86-registry-selection-r204-2026-11-23.md) 继承真实暂停及新管理锚，使用无网络 Ubuntu x86_64、ext4、固定 Python 3.13.18／SQLite 3.54.1、真实 Caddy 2.6.2 和独立管理前端。

- 实机原入口在 `prepare-registry-recovery-entry` 拒绝写入。定位为新候选盘使用上层目录的 setgid 位，生成的根控候选临时目录和存储目录实际继承模式 `02700`，与接纳前要求的 `0700` 不一致。程序现对新存储目录显式设置 `0700` 并持久化，仅在已有目录为同组且为空时接受继承模式并续查，已有其他内容的目录按原保护拒绝。专属网关和套接字继续使用各自权限。
- 两个独立增量盘分别从原空目录、完全无候选目录启动。实际 `prepare-registry-recovery-entry`、`admit-registry-recovery-entry` 成功，双方分别重放原回执。新存储及候选均为 `0700`。错接纳摘要拒绝启动，活动配置按候选放置为专属连接组 `0440`。两次接纳摘要分别为 `104ead51aa845dfa6376300fa579397ed0aaecf6615d2ac4c3eb801fc888a94f` 和 `32688d407a804748d7fb9961efed242c3f02eee29dc22e3ac8c056ad940adc85`。
- 实际管理用户通过 TLS 验出三种角色、新代次、固定首页和操作读取，使用旧入口账号名请求新入口返回 401，新配置中没有旧账号。新入口回报 `BLOCKED`，所有可用管理动作保持禁用；正常停止清理专属 Unix 套接字，第二次启动读回同一代次和暂停状态，运行 ID 已更换。以上阶段两套普通业务库、旧管理库及新旧锚字节保持。所有验证共享来宾内各自回环 9444，从未映射到宿主。
- 固定 SQLite 后端复验 183 项和 16 个子项通过，658 个后端文件通过 Ruff 格式。对照同一分支原 HEAD 的 F／I 全量扫描，原基线 301 条、当前 274 条，当前结果无新增诊断。本轮变更的 Python 和宿主启动文件另经 Ruff F 检查通过。此轮实机使用新建的空登记，原现场有未结任务的恢复及生产采用另验。
