# R398 活动恢复登记的真实管理浏览器

2026-11-24（香港时间）。Ubuntu 24.04.5 x86_64、真实固定管理入口、Caddy TLS 9444、无宿主端口映射。使用 Chromium 159.0.8154.6、Node 24.22.3 和 Playwright CLI 0.1.24，非 root 独立浏览器资料，仅把本来宾 Caddy CA 导入专属信任库，TLS 验证保持开启。

- 从 R395 关闭选择的实际新管理库启动。实际部署的 3 项管理构建资源逐字节通过。真实浏览器确认两环境可读、当前登记只读、登记按钮禁用。点“更新写入状态”后继续保留原入口、两环境和暂停。1360×900 与 1050×800 两种尺寸通过。
- 进入“操作记录”，输入实际原 START 请求键并点击“核对旧登记”。干净资料显示“本机没有此请求键的旧登记记录。”，符合本机历史范围。具备原、现授权的真实管理 HTTP 另行读取四个旧键全部成功，错误代次及暂停写入分别返回 409 和 503。浏览器无控制台错误。
- 测试结束时浏览器、Caddy、固定管理进程和来宾退出，原登记与暂停、业务两站原安装及数据库在退出前摘要一致。无浏览器资料、截图或原始日志入库。

当前浏览器用例覆盖恢复期只读状态和干净浏览器的历史边界，R397 独立证明同进程开放后的真实管理写入。
