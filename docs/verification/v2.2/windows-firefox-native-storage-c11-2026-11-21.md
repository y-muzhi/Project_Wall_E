# V2.2 C11 Firefox 原生存储与多标签

2026-11-21（香港时间）。在 Windows 本地隔离目录复制与原锁一致的前端依赖及实际资源，并以 Vite 打包真实命令仓储、文档编辑器、草稿仓储和 Web Storage 适配器。Firefox 使用全新配置、临时 CA 与两个同端口 HTTPS 主机名。输入为合成记录，测试端口自动分配。

- 两个真实标签针对同一作用域、同一原键和同一命令同时申请。IndexedDB 仅产生一份新准备和一次发送资格，另一标签读取已有记录或因版本变化失去资格。在同一 HTTPS 来源内，分别更换环境和代次，两套新作用域均可使用相同原键。
- 实际命令仓储跨同源各作用域使用共享 100 条上限。另一作用域增加第 101 条被拒绝，原记录保留。注入键与值不同代次的测试记录后，原范围报告损坏并保留原字节，有效的新代次仍可读。首次使用已有代次构造输入时，真实唯一索引在写入前拒绝，随后用空闲代次完成损坏条目读取验证。
- 启动实际文档编辑器和原草稿仓储。相同草稿在两个标签并发写入后保留较新的修订，旧版本清理请求无效。同一文档号在其他代次与环境可各自保存。共享 20 条上限拒绝第 21 条，保留既有草稿。损坏的草稿作用域外壳保留，其他有效代次仍读取自己的项。
- 同一端口上的另一实际 HTTPS 主机名，用完全相同的环境、代次、原命令键和草稿号获得独立真实存储。Firefox 的私有测试配置使用明确 Web Storage 容量，7 MiB 写入触发原生配额错误，现有其他作用域键维持原值。产品端全部网络请求是测试静态资源 GET，零业务写入。
