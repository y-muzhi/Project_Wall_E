# R489 普通应用废止旧 START 与后继重启读回

2026-11-26。当前 `codex/2.2` 源码、R488 独立前端构建、固定 Linux 运行包与 V2.2 FRESH_ONLY Schema。在无网 Ubuntu 24.04 x86_64 QEMU 来宾使用非 root 应用和维护身份，HTTP 只走该来宾内独占 Unix 套接字。当前安装由实际注册与初始化入口生成。

- 第一次普通运行通过真实 API 建立需求、文档、正式正文和活动人工草稿，另保留创建请求的原键及 201 结果。服务正常停止，原库无 WAL、SHM 和回滚日志。
- 用真实 `serve_environment.py prepare-start` 和 `retire-start`，按原关闭控制的操作、修订和摘要准备再废止旧 START。基于废止后的控制生成新 START。原启动凭证按原摘要调用 `serve` 被拒绝，返回 `ENVIRONMENT_CONTROL_MISMATCH`。没有新套接字或 OPEN 回执，控制、原启动凭证、先前开放回执、数据库字节及程序来源不变。
- 真实 `serve` 使用后继 START 启动成功，握手取得新 run ID，环境与数据代次相同。读回原正式正文、活动草稿及原键返回的同一 201 业务结果。数据库 inode 与原程序来源保持。最后应用正常停止。
- 首轮在来宾原应用已启动后超过宿主 640 秒限时。复验加长限时，并把检查收束为准备、废止、旧启动拒绝和后继真实重启。复验来宾退出码 0，覆盖盘与临时文件均已清理，宿主没有端口转发。

本轮核对普通安装内的 START 替代及受控重启。TC201-P1-12 中正式受信候选同时刷新程序来源、选择并安装到原普通环境的端到端路径仍需联验。
