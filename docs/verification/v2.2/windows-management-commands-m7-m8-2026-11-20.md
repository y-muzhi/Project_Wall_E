# V2.2 M7／M8 管理表单与原请求验证

日期 2026-11-20。Ubuntu 24.04 ARM64 使用 M6 固定管理程序、固定 Caddy 和专用回环 9444。独立产物 `web-m7-management-v2` 包含 3 文件，索引摘要 `5ec2e2051049ba589b67ec882a1dab7b0b3e5762c5012abfd4d86e32340662b3`。固定版本 Node 24.22.3 的 `npm run format:check`、`npm run typecheck` 和独立 Vite 构建通过。

- 五份临时 Firefox NSS 配置均以私有测试证书根完成真实 TLS。管理员从宿主目录登记两套普通环境，另一只读账号无登记入口，受限存储浏览器发出零条 POST 并保留表单选择。430px 宽下表单可操作，无横向页面溢出。
- 在浏览器原生 IndexedDB 内实际读取派发事务成功后的固定请求。首条真实 HTTPS POST 返回 202，测试仅扣留浏览器对成功响应的处理。同一资料第二标签申请处理时被当前派发占用阻止，POST 计数未增长。关闭原标签并刷新后，页面只查询服务端，按同一原键读回并在同事务移到本机回执区，未重发。首轮 Firefox 报出了已显示的锁占用异常，改为让锁回调显式返回失败结果后再由界面处理，复验无未处理页面异常。
- 真实开发和集成两位已分配主体通过表单保存固定提交、登记引用、人工说明及未覆盖范围。浏览器输出的原请求字节由固定宿主工具实际核对 Git 和独立证据。开发在证据缺失时收到拒绝并保留原键，补齐证据后以原键提交；集成从回执打开原开发交付。真实管理库为 4 条原操作、两份交付、18 条资源登记。
- 所有测试程序、9444、派发占用和五份临时浏览器资料均按归属结束。原隔离普通安装、控制和配置摘要一致。真实服务器换代、浏览器实盘配额、损坏矩阵、清理和受管启停不在本记录范围。
