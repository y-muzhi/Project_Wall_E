# R484 Linux 双站原请求键回放

2026-11-26（香港时间）。从 `codex/2.2` 与 `codex/2.2-integration` 当前应用分别装配两套普通 Linux 安装。Ubuntu 24.04 x86_64 TCG 无虚拟网卡，数据库、环境配置、稳定锁、应用身份和 Unix 入口各自独立。测试只写新建临时数据。

使用同一个请求键，通过两套真实 Unix HTTP `POST /api/v1/requirements` 提交不同标题。两侧返回各自需求，局部编号相同。两站分别重放本来请求，结果数据与首次一致，新的 HTTP 请求 ID 不同。每站同键换内容都返回 409 `IDEMPOTENCY_CONFLICT`。将开发环境绑定头发送到集成站时返回 409 `ENVIRONMENT_MISMATCH`。

正常停止并重启开发应用。开发侧再次使用原键读取同一结果，集成侧在这期间也保留原结果。重启后的异内容重放仍返回 409。来宾以 `WALLE_QA_DONE:0` 正常关机，宿主 QEMU PID 61284 退出，回收本轮虚拟盘、启动介质、临时数据与日志，底层镜像大小及修改时间保持一致。

本次覆盖原请求键结果持久化、同站回放和请求作用域。浏览器响应丢失后的恢复、带原草稿和未知请求的同结构来源刷新、真实只读入口和跨数据代次恢复仍需联合实测。
