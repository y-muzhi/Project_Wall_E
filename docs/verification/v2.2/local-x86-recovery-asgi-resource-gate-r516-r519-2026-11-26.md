# V2.2 私有恢复首次启动跟踪与资源目录耗时

日期 2026-11-26（香港时间）。无网 Ubuntu 24.04 x86_64 QEMU TCG，独立 ext4 覆盖盘。R516 使用当前程序及仅为试验重钉的固定运行入口，R519 使用旧封存运行包的固定解释器独立加载同一资源目录。

## R516 首次核验

成功走完普通应用写入、维护、原结果、封包、搬移、恢复演练与全新私有副本。父端只给真实固定子进程保留诊断输出，启动命令、有效 UID／GID、对端核对、35 秒启动及 16 秒停止条件均沿原工具。起始无套接字或稳定锁持有者。35.05 秒时仍未收到实际业务 HTTP 握手，子进程在 ASGI startup 并持有稳定锁、已绑定 Unix 套接字。原 SIGTERM 回收等待 16.04 秒，进程仍未正常退出，由原工具发送 SIGKILL，退出 -9。此后稳定锁释放，套接字仍留在该隔离试验根。工具拒绝签发 `LOCAL_VERIFIED`，返回 `RECOVERY_APPLICATION_STOP_UNVERIFIED`，退出 3。源数据库和源控制的受保护摘要保全。该失败解释 R510／R512 的停止诊断不能当作实际资料 HTTP 已通过，两个旧试验当时的具体耗时仍未知。

## R519 原资源目录独立计时

固定解释器内构造同一 `ResourceCatalog()`，不启服务。完整目录 70.05 秒，其中 Draft 2020-12 的结构检查 67.51 秒。46 次结构检查对应 28 个标题，v4/v5 有 6 份传输结构各检查两遍，v8/v9 有 12 份传输与标准输入结构各检查两遍。目录校验本身大于完整私有进程的原 35 秒等待，说明修复套接字回收逻辑不足以解决当前来宾的首个问题。

R520 在已经逐文件核对摘要的同一次 v8 目录加载中复用 12 份同一文件解析和结构结论。每个 Function 的映射、上下文、提示词、预算和原结构兼容保持各自校验。详见独立待合入迭代。R521 对照和 R522 真实核验按各自证据记录。
