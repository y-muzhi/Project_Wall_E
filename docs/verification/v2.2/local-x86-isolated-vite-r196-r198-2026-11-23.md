# R196／R198 Ubuntu 两套普通 Vite 与真实业务入口

2026-11-23，独立 `codex/2.2`。依据 V2.01 后端 6.3.3—6.3.5 和 [V2.2 单独接续](../../iterations/pending/v2.2/WALL-E.普通环境受信HTTPS入口接续_V_2.2.md)。本机 Ubuntu 24.04 x86_64、ext4、真实 systemd 255、Caddy 2.6.2、固定 Node 24.22.3、npm 11.19.1、Vite 8.3.2。Node Linux x64 公共归档 SHA256 为 `4f2b175a6d53a5c617a80dba2676238a0688cef28c6da4eba35c7d844e66fcfb`。

- R196 原型用已锁定的实际前端源文件与每套独立的 `npm ci` 检查私有套接字和同源 WSS。两个进程分别收到自己的改动。正式接入中，每个 Vite 使用独立 UID、源码、node_modules、npm 缓存、Vite 缓存和临时根。宿主 systemd 提供 root 拥有、独立连接组的 `0660` Unix 套接字。实际 Node 先从 procfs 核对继承描述符的监听 inode、类型、状态和确切路径，再接管该描述符。
- 使用正式 `environment_gateway.py --vite-site` 渲染两套站，开发和集成分别使用虚拟机回环 9443 和 443。公开配置、开发模块、认证和业务 API 沿用原安装。临时 CA 明确验证。认证失败、错误 Origin、缺失或重复 Origin、静态来源归属、未列模块、隐藏配置和编辑器路径经真实 Caddy 核对。独立前端及业务 UID 直接连接或改名上游套接字失败，5173 和 Vite 默认 WS 端口未监听。敏感入站头由入口删除。
- 两站实际 WSS 属各自来源，原 HMR 握手成功，新状态探针得到同源确认。以各自 UID 原子替换测试 TypeScript 模块后，收到更新并各自查出新内容，另一站保持自己的模块。真实 Caddy 和 Vite 同时运行时，分别从两个原固定 WALL-E 后端读取各自保存的真实测试需求。后端退出时返回 502。验证进程核对归属并停止两套 Vite、普通应用和 Caddy，套接字及来宾回环端口释放。
- 初次独立数据盘不足，之后加盘使原来宾盘设备编号变化。复验改为独立 ext4 数据盘和固定 QEMU 设备顺序，保留原业务锁和目录身份检查。Node 继承 Unix 描述符时，`Server.address()` 未返回原路径，移除这项重复判断，保持原生监听描述符核验。夹具只查看当前引导日志，避免把上一轮服务错误当作本次启动错误。
- 后端相关离线回归 182 项和 16 个子项通过，前端 605 项通过。Prettier、TypeScript、`node --check`、Ruff 与普通／管理固定构建通过。固定产物分别为 120 和 3 个文件，首页摘要与 R184 一致，两套产物均没有 HMR 路由和开发状态模块。普通构建保留原包体提醒。
- 当前记录为实际 Linux、TLS、HTTP 与 WebSocket 客户端。Chromium 活页面断连、开发服务停止和精确客户端依赖路径见 [R199](local-x86-browser-vite-r199-2026-11-23.md)。云上入口、真实异机仓库及生产采用未执行。
