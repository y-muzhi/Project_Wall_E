# 独立主导航与收起／展开基础检查

日期：2026-10-09。对应UX-002补充、UX-006，方案见[迭代优化V2第7节](../design/WALL-E.V1_0.6.迭代优化V2文档.md#v2-02)及[第12节](../design/WALL-E.V1_0.6.迭代优化V2文档.md#v2-06)。用户允许相关基础检查，仅Markdown记录，不执行完整验收。

## 原因及修改

- 工作台旧max-width:1600px及居中边距在宽窗口形成导航旁额外灰色区域；改为填满应用剩余内容列、margin:0、padding:16px。
- 导航入口旧选中样式只匹配aria-current=page，详情为location时失去强调；现模块入口样式统一，aria-current只表达位置语义。
- 应用顶栏固定48px，导航固定在其下；业务编号留在详情内部，详情滚动约束仅作用于内容区。导航不读取详情业务状态。
- 桌面导航200px／64px切换，右上角保留操作按钮，收起后保留工作台图标；localStorage独立保存偏好，窄窗仍使用原完整200px模态抽屉。

## 真实页面观察

使用现有http://127.0.0.1:8000服务及新生产构建，Chromium 154（Windows，Headless），未启动或停止用户服务。浏览器通过角色名称操作，读取实际几何与计算样式，不写入业务数据。

|范围|观察结果|
|---|---|
|1920×1080工作台展开态|导航x=0、y=48、宽200、高1032且position:fixed；工作台x=200、宽1720，控制区x=216、宽1688，无原1600px居中造成的额外灰色空带；页面宽1920、高1080，无横向溢出|
|收起并进入既有详情|导航宽64，工作台与详情的导航位置、宽高、padding、底色、入口背景／字重／文字色／边框以及顶栏文字逐项相同；顶栏只显示WALL-E|
|刷新与展开|详情刷新后仍为64px且可使用“展开导航栏”恢复200px；展开详情返回工作台后，上述导航几何和样式逐项相同|
|页面不存在视图|访问/requirements/0得到应用“页面不存在”视图；其展开导航几何与样式同工作台，未创建或修改业务对象|

检查脚本首次将窄窗口按钮名称误写为“打开主导航”，定位等待超时；源码实际名称为“展开主导航”。纠正定位后上述流程通过，未为脚本名称问题修改产品代码。刷新后临时页面辅助函数被清除，后续直接读取样式完成比较；没有把空结果当成验证通过。
