# 文档整理静态检查

日期：2026-10-11。范围：文档分类迁移、索引、本地引用和维护工具文档路径。对应[独立整理记录](../maintenance/文档整理记录-2026-10-11.md)。

## 方法

- PowerShell 对每个源和目标验证绝对路径在项目内，检查源存在且目标不存在，再逐文件移动。
- 临时 Python 脚本扫描 Markdown 本地文件链接，并与移动前基线比较；不进行历史附件恢复。
- SHA-256 对比冻结来源／采用记录和项目业务文件，确认整理没有改变其内容。
- 静态搜索维护工具中迁移后的文档路径，检查引用目标存在。
- `git diff --check` 检查本轮改动空白；新增索引另行检查尾空白。
- 所有临时状态置于系统临时目录，完成后删除；不留测试 JSON、截图或原始日志。

## 结果

- 36 份迁移文件的源／目标检查通过：旧位置已移除，新位置存在；docs 一级只留 README.md。
- 归档 5 份已合并资料，待合并目录 9 份，合并记录 3 份；参考原稿保留原位置。
- 95 份原始稿、批准来源、模板、来源 JSON 及采用记录 SHA-256 与整理前一致。
- 578 份后端／前端业务、资源与测试文件 SHA-256 与整理前一致；其他任务的已有修改保留。
- 扫描 1741 个本地文件链接。基线已有 589 个不存在的目标引用，整理后 590 个；唯一新增为冻结批准稿内的 D-014 旧路径，已在决策索引和整理记录说明实际入口。可编辑文档未新增缺失目标；本检查只检查文件存在性，不宣称所有历史章节锚点已验收。
- 10 个维护工具中 17 组迁移路径均指向存在文件，未残留应替换的旧文档路径；只做静态核对，未执行这些工具。
- 11 份新增／重写导航与维护记录无尾空白。git diff --check 在本轮文档与路径工具范围返回 0；Git 的 CRLF→LF 提示是行尾规范化提示。
- 原设计版本仍为前端 1.1-draft-sync8、后端 1.0-draft-sync2；没有新合并或验收状态变更。
