## 4. RC20-03：接收检查缺少角色门槛（P1，确认，静态推导）

相关规则同时存在：

- 后端1519行规定BACKEND → FRONTEND → INTEGRATION，最终联调后才进入ACCEPTANCE。
- 后端1119—1120行允许VERIFY_CANDIDATE／CAPTURE_AND_CHECK在列出的普通任务状态下触发，没有按purpose附加角色／交接历史前置条件。
- 后端1364—1367、1414—1417行接受HANDOFF／ACCEPTANCE，未限定INTEGRATION专属。
- 后端4340行按“当前＋已完成角色”生成范围，ACCEPTANCE仅再并入ACCEPTANCE。
- 后端1375行在合格后可进入AWAITING_ACCEPTANCE；合格对象规则没有把三角色已完成交接写成独立必要条件。
- 前端445行直接给出两种目的选择，没有后端逐purpose许可集合。

静态反例：任务仍在BACKEND／RUNNING时选择ACCEPTANCE → 按现有范围算法得到BACKEND＋ACCEPTANCE → 即便该范围的所有真实必检及收尾均满足，也没有明确契约要求FRONTEND／INTEGRATION角色交接已发生，控制层文字仍可解释为进入AWAITING_ACCEPTANCE。该推导不是已运行或已利用的产品漏洞；V2链路尚未实施。

重要限定：后端4360行已经要求INTEGRATION／ACCEPTANCE必检包含真实候选前后端联通，不能说现稿完全没有端到端检查。该要求仍不等于强制顺序角色完成／真实交接历史，不能弥补角色门槛缺失。

建议统一约束由控制层负责，至少同时覆盖：创建捕获／重查操作、固定检查范围、合格判定、进入AWAITING_ACCEPTANCE、准备交付和接收时的复验。ACCEPTANCE仅允许当前有效角色INTEGRATION，且前两次角色交接有真实已成功的原操作事实；接收范围固定覆盖BACKEND／FRONTEND／INTEGRATION／ACCEPTANCE，资源缺阶段即未就绪。复用原HANDOFF_ROLE操作／会话／检查事实即可，不能仅信任客户端声明“已完成”，也不必先新增一个平行角色完成账本。

前端应从后端当前合法目的集合构造选项；后端仍拒绝手工构造的提前ACCEPTANCE请求。补充后须定义明确拒绝码及无部分捕获／检查／接收的完成范围，并增加后台／前端／交接不完整／旧代次／完整联调等边界场景。本轮未替正文选择最终字段名或错误码。

## 5. RC20-04：事实澄清没有输入路径（P2，产品边界确认）

后端1260行每题action只有CITE_FIXED_BASIS／USE_FIXED_BASIS；前端607—608行映射相同。原生选项只展示，不等于已有一个可提交任意澄清答案的契约。引用固定设计不能表达新的复现结果、现状证据或指出已有行为对象；让模型自行处理也不能承载具体事实。

这不是两个章节互相矛盾，而是有意限制导致常规澄清缺位。新增业务规则仍应走文档，不能因此把所有事实答复强制归为设计变更。

补能力时可定义明确的事实／复现证据／已有选项绑定，答复单独标明不改变固定Revision、权限、预算和目标；与原设计冲突或实际要求新增规则时继续移交文档。不能声称程序仅凭自由文本就能可靠证明“没有改变业务规则”，也不能用提示词代替权限检查。本轮只确认问题及建议，不把新增答复类型当用户已定案。

## 6. RC20-05：原命令凭据持久性不足（P2，恢复边界确认）

前端965、980、986—988行明确PendingAction及完整原请求只存sessionStorage；写失败／超过1MiB时退回内存并提示保留当前页。后端1761行及前端104行又要求原method／path／key才能查回执，只有完整原body仍在才可能显式同键恢复。

关闭标签页／浏览器后原凭据可能丢失；不能保证浏览器一定恢复sessionStorage。NOT_FOUND仅表示查询时未找到，不证明原请求不会迟到。丢原键后也不能安全用新键提交“相同操作”。

同时，已接受且用户仍知道task_id／operation_id的动作，可通过现有任务／操作历史继续观察；不应描述为所有情况下都完全不可恢复。该路径不能普遍补回尚未取得业务ID、创建任务／资源前的丢键请求，也不能唯一重建完整原body。

建议优先复用StoragePort／现有IndexedDB能力保存独立待核对命令记录，确认本地事务提交后再首次发送；确定记录键／origin隔离、完整输入校验、1MiB与8MiB请求上限关系、写失败策略、多标签页竞争／显式同键恢复、终局判定及清理。只增加IndexedDB一词还不构成完整恢复设计。也可设计后端安全查询未决命令，但必须覆盖任务创建前及尚未收到的请求；“按任务查询操作”本身不能覆盖这些情况。

恢复只先读原回执，不授予自动重发／模型／Git写入。保留中的source／repository_quiescent_confirmed=true只作原请求核对，不能给新的捕获／交付窗口自动确认。IndexedDB也不承诺跨浏览器、不同origin或用户清理存储后必然恢复。
