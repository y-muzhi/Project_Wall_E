## 3. 关闭、持久化与协议边界

关闭控制使用原Idempotency-Key和严格body={method:POST,path:原规范路径}，不生成关闭自己的新业务键，不复用原请求body或true窗口确认。原业务接收、两模块回执查询和关闭共用同一注册表：scope只取注册能力及method＋规范路径；集合入口不从body推断身份。目标当前不存在时仍可按原scope管理权关闭，不要求重建实体或复验原业务版本／一次性窗口；未知或不可管理scope拒绝。

服务端沿原idempotency_records增加CLOSED，不增加第二份命令账。只有CLOSED允许business_input_json=null，且必须为null；其成功结果为空，原错误为409 COMMAND_CLOSED，闭合记录不可修改、删除或恢复PROCESSING。旧151行、输入及既有终局保留原值。

新V2业务接收在同一短BEGIN IMMEDIATE内提交PROCESSING与真实异步Operation／同步结果，提交前不派发外部副作用。关闭先提交则迟到原业务无权执行；接收先提交则关闭返回ALREADY_RECEIVED及原回执，不取消原操作、不夺取Git结果。提交未知仍需原键核对，不把NOT_FOUND或HTTP传输失败当关闭成功。关闭HTTP200与原业务409分别解码。

前端复用同一恢复库及原PendingAction，记录格式升为schema4。identity_sha256只用于校验冻结原身份的损坏，不是认证签名；body损坏但原身份可验证时仍可明确关闭。关闭先持久化REQUESTED，可靠CLOSED才原子写CLOSED_UNEXECUTED墓碑并释放原意图；ALREADY_RECEIVED继续核对原操作。关闭丢响应／本地终结写入失败时保留待核对状态，重开／上线只读查询；明确重发关闭仍用原身份，不能自动重放旧业务。已接收的外部未知结果不因关闭而变成可安全重试。

## 4. 精确金额核对

采用任意精度整数微元，不使用二进制浮点；D=1000000，price_micro为每百万Token价格对应的微元整数。I为完整输入，O为完整输出，互斥缓存组K_j为输入子集；reasoning已含在O时不重复收费。

```text
N_use = (I - sum(K_j)) * input_price_micro
        + sum(K_j * cache_price_micro_j) + O * output_price_micro
settled_micro = (N_use + D // 2) // D
N_cap = I_cap * max_input_price_micro + O_cap * max_output_price_micro
reserved_micro = (N_cap + D - 1) // D
```
