### 1.3 填写与实施规则

页面禁用和表单检查用于及时反馈，服务端仍须校验业务条件。只有后端确认成功提交的数据才能显示为已保存或已完成；AI 任务受理与最终完成分别展示。网络失败、响应丢失或无法解析不能直接当作服务端未执行。未确认输入保留和重复请求必须遵循本文的本地生命周期与后端幂等、版本契约。

前端只发送各接口允许的字段；不得由页面补造 FunctionType、Allowed Targets、模板内容或缺失的配置选项。未决页面路径、配置来源、历史版本承载形式与统计能力见附录A。

安装、构建、启动命令、后端地址来源、浏览器存储不可用时的处理及退出清理机制的未决部分见 [Q-FE-BASELINE](#q-fe-baseline)、[Q-FE-DRAFT](#q-fe-draft)。

<a id="fe-ui-principles"></a>

**FE-UI-PRINCIPLES 设计方向与交互原则**

WALL-E采用以黑、白和中性灰为主的简洁界面，参考OpenAI风格中的清晰排版与克制表达，使需求正文、对话内容和当前操作成为视觉重点。以下原则适用于工作台、详情页及公共组件；页面已明确的业务条件、布局尺寸、保存时序和键盘规则继续由对应条目定义。

视觉参考为[OpenAI Design Guidelines／Typography](https://openai.com/brand/)。该指南描述的OpenAI Sans具有几何感、圆润特征与清晰的字重层级。本项目采用下文的系统字体方案；本文的配色、字号建议和交互规则属于WALL-E设计方案，不作为OpenAI产品的官方组件规范。

|原则|适用范围|设计要求|页面差异与边界|
|---|---|---|---|
|内容优先|工作台、正文、对话与建议|用排版、对齐和留白建立层级；页面标题、内容与操作区各有明确位置；减少装饰性大色块、渐变、重阴影和无意义卡片嵌套|详情正文保持视觉中心；左右侧栏继续遵守[BND-DETAIL](#bnd-detail)的宽度与响应式规则|
|黑白灰为主|页面底色、文本、边框与通用操作|白色承载主要内容，浅灰区分辅助区域和悬停态，黑色或深灰表达正文与主要动作|错误、危险和成功等语义颜色按[FE-UI-COLOR](#fe-ui-color)使用|
|主次清楚|每个独立操作区|突出当前主要动作；取消、返回等次要动作采用中性弱强调；按钮文案表达实际动作，例如“创建需求”“完成处理”|并列接受、拒绝等决策保持各自含义；不通过样式预选用户答案，不改变原有操作顺序|
|一致且可预期|跨页控件、状态与布局|同义操作采用相同名称、图标与样式；同类控件保持尺寸与对齐一致；悬停、聚焦和加载不造成按钮或周围内容跳动|已确认的局部尺寸优先；公共组件的例外必须在其5.6节明确|
|状态真实可见|提交、保存、AI运行与建议|清楚区分处理中、等待用户、成功、失败及结果待核实；状态变化以实际响应和资源状态为依据|不以动画结束表示任务完成，不把单项建议接受显示成正式正文已更新；数据依据仍采用5.4、5.5|
|反馈就近且克制|表单、弹窗和页面请求|字段错误放在对应字段附近，弹窗错误留在弹窗内，区域加载留在对应区域；同一结果不叠加多种重复提示|Toast时机、队列和时长仍按[BND-TOAST](#bnd-toast)；首次加载、刷新失败与空数据按各页面5.5区分|
|操作可辨与可达|按钮、图标、输入与弹层|可操作元素具备可辨识的悬停、键盘焦点和按下反馈；纯图标操作提供说明与可访问名称；状态同时用文字或图形表达|确认弹窗焦点、Esc、Enter及关闭条件按[BND-CONFIRM](#bnd-confirm)；不增加未经定义的业务快捷键|
|动效服务于变化|弹层、Toast和控件状态|仅用简短淡入淡出或必要位移帮助理解出现、消失及展开；避免循环装饰动画、闪烁和弹跳；用户选择减少动态效果时去除非必要过渡，仍以文字或图标呈现处理中状态|动效不延迟业务反馈，不改变请求时机、轮询间隔、提示停留时长或操作许可|

<a id="fe-ui-color"></a>

**FE-UI-COLOR 配色与状态表达**

|用途|公共设计规则|局部适用规则|
|---|---|---|
|页面与内容表面|主要内容使用白底；辅助面板或分组可用浅中性灰底，通过留白和细边框分层|工作台表格、详情正文、侧栏和弹层保持各自既定结构，不额外增加装饰性容器|
|文字层级|标题和正文用黑色或深灰；说明、时间等次级信息用可清楚阅读的中灰|弱化次级内容时仍须可读；重要错误、待处理状态、未保存提示不能因使用浅灰而被隐藏|
|主要与次要动作|普通主要按钮采用黑色或近黑色实底、白色文字；次要按钮采用白底细边框或中性文字样式|[BND-CONFIRM](#bnd-confirm)的“项目主色”指本行普通主按钮色；危险确认继续使用红色|
|状态语义色|黑白灰作为界面主体，少量颜色只用于具有含义的状态或必要的内容标记；同时配文字或图标|保留[BND-TOAST](#bnd-toast)成功绿色图标、失败红色图标及危险操作红色；普通提示用中性色；原有正文来源和评论定位标记仍按详情页规则|
|选中与悬停|用浅灰背景、清晰勾选、边框或文字强调区分状态；同一操作的默认、悬停、按下、选中、禁用和加载状态可辨|加载保留动作含义，禁用不表现为可提交；具体许可引用对应操作，不由色彩推断业务状态|
|边框与焦点|分隔边框保持轻量；键盘焦点使用清楚可见的外轮廓，不能只依靠细微灰度变化|[BND-FILTER](#bnd-filter)已有的默认、悬停、聚焦边框色和点击区尺寸继续使用，不被全局建议覆盖|

<a id="fe-ui-typography"></a>

**FE-UI-TYPOGRAPHY 字体与排版层级**

界面采用清晰的无衬线字体，中英文混排优先使用系统字体回退；字体栈为 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。代码、代码块使用 `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace`。字体缺失时按顺序回退，同类文本保持一致的字体类别，不依赖远程字体下载才能阅读或操作。

|文本角色|排版原则|建议字号／行高／字重|已确定约束|
|---|---|---|---|
|页面标题|清楚标识当前页面，避免宣传页式超大标题压缩工作空间|24px／32px／600|长标题处理采用各页面规则|
|区域或弹窗标题|比正文高一级，采用适度加粗区分分区|18px／26px／600|不以扩大标题替代已定弹窗或侧栏尺寸|
|需求正文与对话正文|以长时间阅读为目标；中英文、列表和段落保持舒适行距|16px／28px／400|Markdown标题、列表、表格与代码按内容结构排版；内容列宽度仍采用详情页规则|
|表单、表格与按钮|使用紧凑、清楚的界面文字；重要字段和动作通过字重区分|14px／22px／400，主要按钮可用500|[BND-FILTER](#bnd-filter)的14px字号已确定，其余数字属于本次建议|
|辅助说明与时间|保持次一级层级，避免过小、过细或低对比文字|12px／18px／400|承载错误原因或必要操作条件时应按正文或表单层级展示|

**WB-OP01 查询、筛选与翻页处理步骤**

|步骤|触发或条件|前端处理|接口与结果|
|---|---|---|---|
|1|首次进入|主导航进入使用空关键词、全选筛选、第一页；详情返回使用已保存查询状态|暂不修改上一次成功结果|
|2|编辑关键词|只更新输入值；修改其他筛选时继续使用已提交关键词|不请求|
|3|Enter、搜索图标或筛选变更|关键词提交时 trim；筛选变更使用完整当前选择；查询条件变化设为第一页|全选字段从查询参数中省略|
|4|清除关键词|点击清除按钮始终取消已生效关键词；手动删空按 [BND-FILTER](#bnd-filter) 的已提交值/未提交草稿规则判断|实际清除时只查询一次，保留其他筛选，回第一页|

|7|最新请求成功|同时更新 items、分页、成功条件快照；按列表状态表显示结果|只使用后端排序，不按格式化时间再排序|
|8|最新请求失败|按字段错误或查询失败展示；保留当前输入、条件和最后成功结果|允许重试，失败不映射为 total=0|
|9|旧请求迟到|忽略其数据、错误及完成通知|不覆盖新结果，也不能关闭新请求的加载状态|

**WB-OP02 打开需求与返回**

1. 点击需求标题或列表行时，保存当前已提交条件、页码和滚动位置；拖动选择文字不执行打开操作。

2. 使用该行 `id` 进入 [BND-DETAIL](#bnd-detail)；`requirement_no` 仅作展示和查询，不代替内部 ID。

3. 详情加载失败由详情页显示错误；工作台已保存状态继续保留。

4. 返回工作台时恢复查询条件和页码，查询最新数据后恢复可用的滚动位置；数据减少造成越界时按 OUT_OF_RANGE 处理。

**WB-OP03 新建需求**

1. 点击顶部“新建需求”，打开 [BND-CREATE](#bnd-create)。

2. 字段填写、联动、校验和提交步骤按 [BND-CREATE](#bnd-create)／5.6 执行。

3. 创建成功后关闭抽屉，使用返回的需求 ID 进入详情；取消则停留工作台，列表条件不变。

**页面结构**

需求详情页采用“文档主区域 + 两侧辅助区域”的三栏结构：

Current Document 始终是页面唯一主区域。AI 对话不是与文档同等权重的永久主区域，而是右侧辅助面板中的一个功能页签。

**左侧大纲**

- 默认宽度为 `200px`。

- 宽度固定，不支持拖动调整。

- 首次进入需求详情时默认展开。

- 用户可以主动收起。

- 收起后完全释放原占用空间，不保留空白窄栏。

- 收起后在文档工具栏中保留“大纲”入口。

- 页面恢复时，优先恢复用户上次的大纲展开状态。

- 点击大纲标题，文档编辑器滚动至对应章节。

- 用户滚动文档时，大纲同步高亮当前章节。

- 大纲只展示 Markdown 标题层级，不承载评论、版本、编辑操作和初始化进度。

- Plan V1 不判断和展示“未填写、部分完成、待确认、已完成、不适用”等章节状态。

**中间文档编辑器**

中间区域展示 `RequirementDocument.markdown_content`。

使用 Milkdown + Crepe 展示和编辑 Markdown。

文档编辑器占用左右辅助区域之外的全部剩余空间。

文档编辑器区域宽度不得小于 `640px`。

Markdown 正文内容列最大宽度为 `960px`；编辑器区域超过该宽度时，正文内容列在编辑器区域内居中展示。

表格、代码块等宽内容超出正文内容列时，在自身容器内横向滚动，不撑开整个页面。

页面本身不得因为正文内容产生横向滚动条。

左侧大纲或右侧面板收起后，释放的空间全部交给文档编辑器。

文档编辑器是页面视觉中心；其中展示的 CURRENT 是唯一正式事实源，人工编辑时展示的 MANUAL_DRAFT 仍是独立草稿。

右侧面板展开时，与文档编辑器并列展示，不覆盖在文档上方。

文档是否可编辑继续由 `Requirement.document_work_state` 和 Requirement 状态决定，不受页签切换、面板收起或响应式模式影响。

**右侧辅助面板**

右侧面板包含三个页签：

- AI 对话

- 评论

- 版本记录

三个页签共享同一个内容区域，同一时间只能展示一个。

尺寸规则：

- 偏好宽度默认为 `420px`。

- 最小宽度为 `360px`。

- 支持拖动分隔线调整宽度。

- 文档编辑器区域始终不得小于 `640px`。

- 右侧面板最大宽度不得超过扣除左侧大纲和分隔线后的可用空间的 50%。

- 右侧面板最大宽度同时不得超过“当前可用空间减去 `640px`”。

- 页面根据最小宽度、最大宽度和用户偏好宽度计算当前有效宽度。

- 当用户偏好宽度超过当前允许范围时，只临时压缩当前有效宽度，不覆盖用户保存的偏好宽度。

- 窗口重新变宽后，在合法范围内恢复用户偏好宽度。

- 不提供右侧面板或 AI 对话的全页面模式。

- 右侧面板允许整体收起。

- 右侧面板始终与文档并列，不允许覆盖 Current Document。

**响应式范围**

完整桌面布局：

- CSS 视口宽度不小于 `1280px`。

- 左侧大纲和右侧辅助面板可以独立展开或收起。

- 左侧大纲和右侧辅助面板可以同时展开。

- 左侧大纲固定为 `200px`。

- 右侧辅助面板使用当前合法的有效宽度。

- 中间文档区域不得小于 `640px`。

紧凑桌面布局：

- CSS 视口宽度为 `1024px～1279px`。

- 左侧大纲和右侧辅助面板最多展开一个。

- 进入紧凑布局时，如果两者都处于展开状态，自动收起左侧大纲，保留右侧辅助面板。

- 用户打开右侧辅助面板时，自动收起左侧大纲。

- 用户打开左侧大纲时，自动收起右侧辅助面板。

- 自动收起只改变当前页面布局，不取消 GuideRun、不放弃 SuggestionBatch、不改变评论、Revision 或正文状态。

不支持范围：

- CSS 视口宽度小于 `1024px`。

- 页面显示“当前窗口过窄，请将窗口调整至至少 1024px”的阻断提示。

- 阻断状态下不提供编辑、AI 操作、Suggestion 决策、评论操作和版本操作。

- 用户可以返回需求工作台。

- 正在运行的 GuideRun 不因窗口变窄而取消。

- 已存在的 MANUAL_DRAFT 不因窗口变窄而删除。

- 人工编辑过程中进入该范围时，前端立即尝试保存一次当前草稿；保存失败时继续保留浏览器内的编辑内容。

- 窗口恢复至 `1024px` 以上后，关闭阻断提示并重新读取当前活动状态。

- V1 不实现移动端单栏页面、覆盖式抽屉、底部导航和触屏专用交互。

- 响应式断点以 CSS 像素判断，浏览器缩放可能改变当前布局区间。

**右侧面板默认状态**

Requirement 为 `INITIALIZING` 时：

- 首次进入详情默认展开右侧面板。

- 默认选中“AI 对话”页签。

Requirement 为 `ACTIVE` 时：

- 首次进入详情默认收起右侧面板。

- 用户展开后，默认进入“AI 对话”页签。

- 此后优先恢复用户上次的展开状态、宽度和选中页签。

右侧面板的展开状态、宽度和当前页签属于前端页面偏好，不属于 Requirement 业务数据，不新增持久化业务对象。

**页签交互**

- **AI 对话**

    - 展示连续的用户与 AI 消息。

    - 展示初始化交互卡片、等待用户回复状态以及修改建议处理内容。

    - 切换到其他页签或收起右侧面板，不会取消正在运行或等待用户的 GuideRun。

    - AI 正在运行、等待回复或存在待处理建议时，收起状态下的入口需要显示状态提示。

- **评论**

    - 展示当前文档的评论。

    - 用户点击正文中的评论标记时：

        - 自动展开右侧面板；

        - 自动切换到“评论”页签；

        - 定位到对应评论。

    - 切换页签不会改变评论状态。

**区块辅助栏**

- Current Document 的每个顶层 Block 右侧提供区块辅助栏。

- 区块辅助栏不得写入 Markdown，也不得改变 Markdown 的序列化结果。

- 鼠标悬停、键盘聚焦或选中区块时，显示来源信息入口。

- 点击来源信息入口，打开非模态浮层，分别展示区块创建信息和最近修改信息。

- 来源信息使用用户可理解的主体和操作文案，不展示原始枚举值、区块 ID 或来源对象 ID。

- 时间按照浏览器当前时区展示到分钟，不使用相对时间。

- 存在 `OPEN + ATTACHED` 评论时，辅助栏常驻显示评论图标和数量。

- 多条评论使用一个图标和数量表示，不为每条评论分别占用正文空间。

- 没有未解决评论时，添加评论入口只在区块悬停、聚焦或用户选择文字时显示。

- `ORPHANED` 评论不在正文中显示锚点标记。

**修改建议展示**

- SuggestionBatch 在右侧辅助面板的“AI 对话”页签中展示。

- 批次顶部显示标题、摘要和实时处理数量。

- Suggestion 卡片固定按 `order_no ASC` 排列。

- 右侧面板使用纵向对比，不使用左右并排对比。

- 替换建议依次展示“原内容”和“建议内容”。

- 插入建议展示插入位置和“新增内容”。

- 删除建议展示“待删除内容”。

- 表格行建议分别渲染原表格行和建议表格行。

- 不进行字符级 Diff，不把 Suggestion 内容提前叠加到 Current Document。

- 点击 Suggestion 卡片时，Current Document 滚动至目标位置并临时高亮；高亮只表示目标，不代表建议已应用。

- 原内容始终只读；用户选择编辑建议时，只将建议内容区域切换为可编辑状态。

- 批次完成前允许用户重新选择接受、拒绝或编辑后接受。

- “完成本批修改”和“放弃本批建议”固定显示在批次操作区，不随单张卡片滚动消失。

**评论页签展示**

- 评论页签按照 `created_at ASC, id ASC` 展示未删除评论。

- 评论卡片展示处理状态、锚点状态、原引用、评论正文、创建时间和当前可用操作。

- 点击 `ATTACHED` 评论卡片时，Current Document 滚动并临时高亮对应 Block 或 Selection。

- 当前选中评论通过卡片边框和正文临时高亮表示，不改变列表排序。

- `RESOLVED` 评论降低视觉强调，但评论正文和引用内容仍保持可读。

- `ORPHANED` 评论使用警告图标和“位置已失效”标签，不提供正文定位和“让 AI 修改”。

- `RESOLVED + ORPHANED` 必须同时显示“已解决”和“位置已失效”，不得合并为单一状态。

**版本记录**

- 展示当前 Requirement 的 Revision 列表。

- 用户点击版本入口时，自动展开右侧面板并切换至“版本记录”。

- 历史版本只读查看，不支持恢复到 Current Document；快照具体展示容器见 [FE-Q03](#fe-q03)。

**收起规则**

完整桌面布局下，左侧大纲和右侧辅助面板可以分别收起，互不联动。

紧凑桌面布局下，左侧大纲和右侧辅助面板互斥展开。

紧凑桌面布局中打开一个辅助区域时，另一个辅助区域自动收起。

用户主动展开、收起或调整宽度时，更新浏览器本地页面偏好。

因视口宽度限制产生的自动收起或临时宽度压缩，不覆盖用户原有页面偏好。

页面恢复到完整桌面布局后，可以恢复此前因宽度不足而无法使用的展开状态和偏好宽度。

收起只是页面展示行为，不改变任何业务状态。

收起 AI 对话不会取消 GuideRun。

收起评论不会解决或删除评论。

收起版本记录不会改变 Current Document 或 Revision。

重新展开后读取最新业务状态。

如果后台状态在收起期间发生变化，入口展示状态提示，重新展开时以服务端最新结果为准。

页面布局偏好只保存在当前浏览器，不写入 Requirement 或其他业务对象，也不跨设备同步。

**进入与恢复步骤**

1. 读取需求和 CURRENT，显示加载状态；任一必需数据失败时不创建空编辑器代替数据。

2. 根据服务端工作状态及活动引用选择后续读取：MANUAL_EDITING 读取独立草稿，GUIDE_ACTIVE 读取运行，SUGGESTION_REVIEWING 读取批次。

3. 校验活动对象是否属于当前需求；工作状态与活动对象不一致时进入数据异常状态，阻止新的正文写入。

4. 恢复浏览器布局偏好，再按当前 CSS 视口限制计算实际布局；自动收起不回写用户偏好。

5. 加载当前页签所需数据；正文评论标记需要独立的完整数据保障，不能仅因评论页签没打开就假装没有评论。

6. 编辑恢复时比较后端草稿版本与本地未确认快照基线；相同才允许用户恢复本地内容，不同则保留两者供人工处理。


#### 5.4 操作与结果反馈

|状态|进入条件|用户可见反馈|下一步|

**保存与快照顺序**

1. 编辑器一次输出完整 Markdown 和对应 block_state_json；两者必须属于同一编辑快照。

2. 停止输入2秒、持续输入最长10秒、失焦或页面隐藏时尝试保存；同一时刻最多一个保存请求。

3. 保存请求在途时继续输入，只替换一个“最新待发快照”，不排队保存所有中间版本。

4. 保存成功时更新后端确认版本；如果编辑器已有更新，不能用返回的较旧内容覆盖它，也不能显示全部内容已保存。

5. 存在最新待发快照时，以最新确认版本发送；自动保存失败按上表处理。

6. 完成编辑先停止新输入、等待在途保存并保存最后快照，再提交完成；取消编辑需确认放弃并协调在途请求，不能在删除草稿后再发迟到保存。

|内容来源|后端[SHR-BLOCK](WALL-E.V1_0.6.后端设计文档.md#shr-block)定义区块创建与最近修改来源元数据；前端通过辅助栏打开来源浮层，正文默认不常驻元数据，不把元数据写进Markdown|
|评论排序与选择|使用[I27](WALL-E.V1_0.6.后端设计文档.md#bnd-comment-api-i27)的created_at ASC、id ASC顺序；选中仅滚动和高亮，不重排，不增加位置排序、拖动或分组|
|评论双状态视觉|OPEN/RESOLVED展示“未解决/已解决”；ATTACHED/ORPHANED通过定位能力和“位置已失效”警告表达；孤立评论显示警告图标和原引用并说明非当前内容；操作仍受[DT-OP17](#dt-op17)—22条件约束|
|已解决评论|保持可见但弱化；隐藏编辑及“让AI修改”，提供重开；重开后按锚点状态显示定位和AI入口；历史Revision不展示当前评论|

**导航、异常与退出**

**导航与布局切换**

|场景|处理|数据保留|反馈|
|---|---|---|---|
|返回工作台|恢复工作台已提交筛选/页码/滚动并刷新|布局偏好保存在浏览器|无额外业务变更|
|有未同步草稿站内离开|先保存；失败提示继续编辑或明确离开|保留后端草稿与本地未确认快照|不能声称最后请求必然送达|
|刷新/重进|先读后端草稿及活动引用，再检查本地基线版本|同版本才允许用户恢复本地内容；不同版本保留供对照|不自动覆盖任何一方|
|收起面板或切页签|只改本地布局|Run/Batch/Comment均保留|活动任务入口显示状态|
|完成/重新激活/放弃草稿或批次/删除评论|调用[BND-CONFIRM](#bnd-confirm)|取消确认不发请求|成功后刷新对应资源|
|运行轮询断网|保留最后状态，退避查询|不把查询失败改成Run失败|连接异常提示；成功恢复1秒轮询|

**异常场景与恢复**

|场景|页面表现|后续操作|
|---|---|---|
|Requirement 不存在|显示数据不存在，不展示空白可编辑文档|返回需求工作台|
|详情加载失败|显示加载失败，不能把失败数据当空文档|重试或返回|
|GuideRun 等待用户|显示待补充问题或冲突卡片，正文只读|用户回复继续当前 GuideRun，或取消|
|基础正文已变化|展示冲突，不自动合并|重新读取最新正文并重新生成或人工处理|
|评论锚点失效|评论标记为 ORPHANED，展示创建评论时保存的原引用，不定位到其他相似内容|用户可编辑、解决或删除；不能让 AI 修改；V1 不支持重新挂载|
|评论保存失败|当前评论数据和页面状态不被错误覆盖|保留用户输入并允许重试|
|正文更新时评论校验失败|Selection 无法定位时正常保存正文并标记 ORPHANED；程序处理异常时正文保存整体失败|正常孤立无需重试；程序异常恢复后重新提交正文|
|卡片超过5张|整组输出不通过校验，不静默截断|重新生成符合上限的卡片组|
|卡片已被其他标签页回答|显示正式 CARD_RESPONSE，覆盖当前本地草稿|卡片变为 ANSWERED，不允许再次提交|
|卡片已失效|展示 EXPIRED 只读状态|清除对应 sessionStorage 草稿，用户通过新消息继续|
|卡片提交请求结果未知|不直接重复创建响应|使用幂等键查询或重试，返回已有正式响应|
|卡片或其他模型输出解析、Schema 校验或业务校验失败|不展示部分结果、未经校验的 JSON 或无效卡片；运行中时继续显示 AI 处理中|同一逻辑调用最多自动重试 2 次；仍失败时 GuideRun 进入 FAILED，Current Document 保持不变|
|历史结构化内容无法解析|使用 content 显示可读文本，不渲染可操作卡片|记录消息结构异常，不把它当作 AVAILABLE 卡片|
|草稿自动保存失败|显示“保存失败”，保留编辑器内容，不回退到正式正文|网络恢复后重试；成功前不显示“已保存”|
|草稿版本冲突|停止继续自动覆盖，提示草稿已被其他页面更新|保留当前本地内容，重新读取后端最新草稿后人工处理|
|刷新页面|恢复后端已经保存的 MANUAL_DRAFT；如存在更新的本地未确认内容，则保留并提示继续同步|不修改 Current Document|
|带未同步内容离开|站内跳转前立即尝试保存；失败时提示仍有未同步修改|用户可以继续编辑，或明确离开并保留本地临时内容|
|完成人工编辑失败|正式正文保持原内容，草稿和编辑状态继续保留|修正校验问题或恢复服务后重新完成|
|取消人工编辑失败|保持 MANUAL_EDITING 和现有草稿|重试取消，不能提前将页面显示为 IDLE|
|正文与草稿关系异常|不自动选择任意记录，也不使用草稿覆盖正式正文|展示数据异常，等待后续异常恢复规则处理|
|模型调用正在自动重试|保持当前 AI 运行状态，不创建重复消息或新的 GuideRun|后端按照既定次数和退避规则执行；前端继续通过既有 GuideRun 状态查询取得结果|
|用户取消 AI 运行|GuideRun 显示已取消，停止加载状态|文档恢复 IDLE；迟到的 Provider 响应不得恢复运行或生成业务结果|
|持久化阶段取消|提示当前结果正在提交，不能取消|等待本次提交完成，不强制中断事务|
|视口宽度低于 `1024px`|显示窗口过窄阻断提示，不展示残缺的编辑器和辅助面板，不允许继续提交编辑、AI、Suggestion、评论或版本操作|用户调整窗口至至少 `1024px` 或返回需求工作台；恢复支持宽度后重新读取最新业务状态；不取消 GuideRun、不删除 MANUAL_DRAFT|
|人工编辑时进入窄屏范围|阻断继续编辑，同时显示草稿保存状态|立即尝试保存一次草稿；成功后保留后端草稿，失败时保留浏览器内当前内容；恢复支持宽度后继续处理|
|右侧面板偏好宽度超过当前允许范围|面板使用当前允许的最大宽度，文档区域继续保持至少 `640px`|不修改用户保存的偏好宽度；窗口变宽后自动恢复至合法的偏好宽度|
|紧凑布局中尝试同时展开两个辅助区域|新打开的辅助区域正常展开，另一个自动收起|不改变当前页签内容和业务状态；重新打开时读取最新状态|
|GuideRun 最终失败|展示安全错误摘要和“重新运行”入口；不展示未校验输出、Provider 原始错误或内部请求|原 GuideRun 保持 FAILED；用户点击重新运行后创建新的 GuideRun|
|GuideRun 执行超时|展示“运行长时间没有进展，已停止本次运行”；Current Document 保持原状|文档恢复 IDLE；用户可以重新运行|
|GuideRun 因服务重启中断|展示“服务中断，本次运行未完成”；不得伪装成模型失败或成功|文档恢复 IDLE；用户可以重新运行|
|GuideRun 等待用户|展示待补充问题或交互卡片，正文保持只读|不自动过期；用户回复继续当前 GuideRun，或主动取消|
|GuideRun 状态查询失败|保留最后一次已确认状态，显示连接异常，不把运行改成 FAILED|按照2秒、5秒、10秒、30秒重新查询；成功后恢复每1秒轮询|

|SuggestionBatch 可修正校验失败|批次保持 PENDING，标记具体未处理或内容不合法的 Suggestion|用户修正对应 Suggestion 后再次完成|
|SuggestionBatch 暂时性应用失败|展示“本批修改尚未应用”；Current Document 和全部单项决策保持不变|查询批次最新状态；仍为 PENDING 时使用原幂等键重试|
|SuggestionBatch 已失效|展示正文版本或目标内容已变化，不再提供直接完成入口|用户放弃批次后重新发起 MODIFY；不自动 Merge 或重新生成|
|草稿自动保存暂时失败|显示“保存失败，正在重试”，保留编辑器和本地临时内容|按照2秒、5秒、10秒、30秒退避，只重试最新快照|
|草稿自动保存确定性失败|显示具体校验错误或版本冲突，停止自动重试|用户修正内容，或重新读取后端草稿并人工处理|
|刷新页面存在未同步本地草稿|同时读取后端草稿和本地临时快照，不自动覆盖任何一方|版本一致时允许恢复本地内容；版本不一致时保留本地内容供人工对照|
|完成人工编辑请求结果未知|保持提交中或结果确认状态，不提前展示成功或失败|重新查询 CURRENT、MANUAL_DRAFT 和工作状态；根据查询结果确认是否完成|
|取消人工编辑请求结果未知|不提前删除前端草稿或显示 IDLE|重新查询 MANUAL_DRAFT 和工作状态；仍在编辑时使用原幂等键重试取消|
|活动对象关系异常|阻止新的编辑、AI 和建议操作，展示数据状态异常|返回 `WORK_STATE_INCONSISTENT`；不得自动删除或选择任一对象|

### 5.6 BND-CONFIRM 确认弹窗

职责与状态归属：负责确认与取消意图、焦点和模态展示。父页面维护操作对象、接口参数、提交状态、成功关闭、错误和刷新；弹窗不执行业务请求。

|输入项|类型或定义引用|必传、可空与默认规则|用途及外部变化后的同步|
|---|---|---|---|
|标题 / 说明文案|string|均必填|说明本次对象及后果，随当前操作同步|
|确认 / 取消按钮文案|string|默认分别为“确认”“取消”；确认文案建议按操作命名|父级可指定本次动作文字|
|操作类型|普通、危险|默认普通|不可恢复操作用危险类型|
|提交状态|boolean|由父页面传入|同步禁用重复提交、关闭、取消和Esc|
|错误信息|string；无错误表示的具体约定见[Q-FE-COMPONENT](#q-fe-component)|失败时传入|在正文下方展示，恢复按钮；同一错误不再Toast|

|输出事件|触发条件|输出结构|表达的事实|
|---|---|---|---|
|确认|允许操作时点击确认，一次点击输出一次|确认意图；业务参数由父级持有|请求尚未执行或完成；进入提交状态后不重复输出|

特殊交互：

- 打开后遮罩覆盖整个页面，底层页面不可点击、不可滚动；焦点限制在弹窗内部。

- 同一时间只显示一个确认弹窗，不叠加打开。

- 按钮排列：左侧取消，右侧确认；右上角提供关闭按钮。

- 点击取消、关闭按钮或按 Esc，均关闭弹窗，不执行业务操作。

- 点击遮罩不关闭弹窗。

- 初始焦点落在取消按钮，避免误触确认；不设置无条件按 Enter 即确认，Enter 仅激活当前聚焦的按钮。

- 点击确认后通知业务页面；请求期间保持弹窗打开，确认按钮显示加载状态，禁止重复提交。

- 请求期间禁止取消、关闭及 Esc 退出，避免用户误以为操作已撤销。

- 操作成功后，由业务页面关闭弹窗、更新页面数据，并显示成功轻提示。

- 操作失败后保留弹窗，恢复按钮操作，在正文下方显示错误原因，允许重试或取消；同一错误不重复显示轻提示。

- 关闭后，焦点返回原触发位置；原位置已不存在时，转移到页面合理的可操作位置。

- 确认框居中显示，白色背景、12px 圆角、轻微阴影，建议宽度为 440px。

- 小屏幕下左右至少保留 16px 间距；内容过长时正文区域滚动，操作按钮保持可见。

- 标题、说明、操作区层级清晰，说明文字支持换行。

- 普通操作的确认按钮使用项目主色；危险操作使用红色，并通过标题与文案明确风险。

- 取消按钮使用中性样式；关闭按钮采用统一圆角悬停效果。

- 提交期间保留按钮原文案并显示加载图标，按钮宽度不变。

- 错误信息使用错误图标与文字共同表达，不仅依赖颜色。

建议透明度40%、宽440px属于视觉建议，尚未确认的设计令牌见[Q-FE-VISUAL](#q-fe-visual)。

### 5.6 BND-TOAST 操作结果轻提示

职责与状态归属：只展示父页面已确定的结果，不判断请求是否成功，不展示异常堆栈；不阻断当前操作。

|输入项|类型或定义引用|必传、可空与默认规则|用途及外部变化后的同步|
|---|---|---|---|
|提示类型|成功、失败、提示|由业务明确传入|决定图标、色彩和默认时长|
|提示文案|string|必填|简短说明实际结果；长文案可换行，不截断关键结论|
|显示时长|时长|可选；成功、提示默认3秒，失败默认5秒|显式时长覆盖默认；具体程序单位见[Q-FE-COMPONENT](#q-fe-component)|

|输出事件|触发条件|输出结构|表达的事实|
|---|---|---|---|
|无业务事件|关闭或自动消失|无|提示消失不改变业务结果，不触发刷新或再次提交|

不在提示中放置必须完成的操作；需要决策或详细处理时使用弹窗或页面内提示。

- 业务页面根据实际操作结果触发提示，将接口错误转换为用户可理解的文案。

- 轻提示只展示结果，不判断请求是否成功，不直接显示原始异常堆栈。

特殊交互：

- 仅在得到明确结果后显示；请求刚发出时不显示“操作成功”。

- 出现时不抢占焦点，不阻止用户继续操作页面。

- 到达显示时长后自动关闭，也可以点击关闭按钮提前关闭。

- 鼠标悬停或键盘焦点进入提示时暂停计时，离开后继续计时。

- 相同类型、相同文案的提示在显示期间再次触发时，合并为一条并重新计时。

- 最多同时显示 3 条，新提示显示在顶部；超过时移除最早的一条。

- 同一操作的结果只提示一次；弹窗或表单中已就地展示的错误，不再重复弹出。

- 表单字段错误应显示在对应字段附近，不能仅通过轻提示告知。

- 提示内容应可被辅助技术感知，但不强制移动用户焦点。

视觉依据与变体：

- 固定显示在页面顶部居中位置，建议距顶部 24px；层级高于普通页面内容和弹窗。

- 提示容器以外的区域不拦截鼠标操作。

- 白色背景、8px 圆角、轻微阴影，内容从左至右为状态图标、提示文案、关闭按钮。

- 成功使用绿色图标，失败使用红色图标，普通提示使用中性色或主色图标；同时使用图形与文字区分结果。

- 宽度随内容适应，最大宽度建议为 480px，小屏幕左右至少保留 16px 间距。

- 文案过长时换行，不截断关键结果。

- 多条提示纵向排列，间距为 8px；出现和消失使用短暂淡入淡出效果，不改变页面布局。

建议顶部24px、最大宽480px属于视觉建议，相关确认见[Q-FE-VISUAL](#q-fe-visual)。

组件实现定位：公共控件的主要模块尚无已确认位置，见附录A [Q-FE-COMPONENT](#q-fe-component)。

### 5.6 BND-PAGINATION 页码分页器

职责与状态归属：用于工作台、评论及版本记录列表；父页面持有已提交条件、请求和最新成功页。对话消息使用游标加载，不使用本组件。

|输入项|类型或定义引用|必传、可空与默认规则|用途及外部变化后的同步|
|---|---|---|---|
|page|integer|必传，从1开始；可大于实际总页数|对应服务端响应查询页|
|pageSize|integer|必传，固定20|取meta.pagination.page_size，不提供切换容量|
|total|integer|必传，非负|符合条件总记录数|
|totalPages|integer|必传，total=0时为0|使用后端返回值|
|loading|boolean|必传|本次分页查询执行状态|
|error|string或null|可选；未传等同无本次错误|用于翻页失败反馈，不伪造分页数据|

|输出事件|触发条件|输出结构|表达的事实|
|---|---|---|---|
|pageChange(targetPage)|用户选择不同且有效页码|目标页integer|翻页意图；父级保留已提交条件后请求，受控结果更新不再触发事件|

特殊交互：

|场景|处理|
|---|---|
|正常翻页|输出目标页，父页面加载；成功同时更新列表和分页|
|第一页/最后一页|分别禁止无效上一页/下一页|
|total=0|展示无记录及0个总页，不生成第0页请求|
|越界页|保留请求页和实际总页数，可回有效页，不无限自动重试|
|翻页失败|保留上一成功页列表和分页并显示重试，不能新页号配旧数据|
|筛选变化|父页面改page=1并查询一次；组件受控更新不发第二次请求|
|请求竞态与重复点击|仅最新响应生效；重复选当前页不输出，不被旧响应覆盖总数|

视觉依据与变体：置于列表之后，显示当前页、总页数/总数及可用翻页入口；加载与禁用可区分；每页20条为固定信息，没有排序选择、自定义跳页或容量选择器。数字页按钮数量、省略号和间距见[FE-Q10](#fe-q10)。


组件实现定位：`frontend/src/shared/pagination.ts :: Pagination`。
