# 交互问题成因与规格需求说明模板补充

日期：2026-10-09。依据：原前后端设计模板、迭代优化V2 UX-001—019及当前实现。本文说明问题成因，并提供可直接放入同类规格模板的条目。它不修改应用内“需求新增／改造”的业务模板资源。

## 1. 结论与原因

这些问题不能全部归因于“需求文档没写”。原文已经有公共视觉、焦点、加载反馈、三栏宽度、模板锁及状态许可；但有些只写了原则，没有写操作过程和组合边界。另一些是明确规则后来不适合用户的实际使用，或实现扩大了规则范围。最后一次下拉点击问题还包含检查方式的遗漏。

|问题|文档与实现的实际原因|应怎样补规格|
|---|---|---|
|点击套框、重复焦点|普通按下、输入聚焦、父容器和原生控件分别绘制反馈；focus-visible也不能简单等同于只有键盘点击。缺少复合控件“谁负责绘制一次焦点”的约束|定义输入方式、父子职责、错误优先级、强制颜色兜底；保持真实焦点而非全局去掉outline|
|导航跨页变样、列表旁空带|导航曾与路由布局耦合；列表自身1600px限宽居中又叠加左导航。单个区域正确不代表整体布局正确|划分全局壳、页面、组件责任，列出整个可用宽度如何分配；明确哪些样式不能由业务状态改变|
|详情顶部多行、按钮分散、标题重复|页面框架与属性区各显示需求标题；品牌栏、需求头、动作行、视图开关分别占高度，缺少单一信息来源与任务动作层级|每个信息指定唯一主展示位置；列明主／次／更多动作、各视图位置、固定头部及额外错误反馈的增高规则|
|正文两侧留白|原设计明确要求960px限宽居中，实现也如此；宽屏三栏下该取舍与用户需求不符|明确“填满栏宽”还是“限制阅读行宽”，给出全局导航和侧栏组合的布局场景；变更后同步旧尺寸及检查条目|
|切换窗口闪烁|“窗口恢复后核对”没有细分事件，实现把普通focus／visibility与过窄窗口／真实页面恢复混用；又把操作不可用与整个正文不可见绑定|用事件触发矩阵分别定义保存、重读、冻结和保留画面；已有内容不能因一次后台读而整体卸载|
|很多刷新按钮、局部读抖动|内部读取控制器直接映射成常驻按钮；不同区域插入加载段落、分页再次显示加载，邻近输入区移动|定义正常自动更新和错误恢复分别由谁负责；写清读取范围、稳定状态槽、失败保留内容、未知请求的专属恢复|
|不能点且不明原因|有些是正确的生命周期／工作占用限制，早期界面只有置灰；不应为了可点绕过许可|每个禁用状态写原因、说明位置及下一步；区分读态、草稿、历史、初始化、完成与请求待核实|
|编辑功能难找|底层命令存在，Crepe默认交互入口被关闭；最初仅有固定工具栏，没有明确斜杠菜单、选区格式、快捷键的能力矩阵|把能力与入口分别列出，明确触发位置、适用状态、IME、取消、撤销及持久化边界|
|浮动下拉点不开|浮层在body下，离焦逻辑只认正文root；focusout早于focusin，过渡时误隐藏下拉。前轮selectOption设置值检查绕过了真实点击展开|定义编辑器拥有的全部交互区域和焦点转移过程；关键控件至少真实点击打开，不能用设置值替代|
|浮窗位置跳变|原来用选区末端作锚点，上方不足就翻到下方；没有满足后来“始终在选区上方”的明确要求|指定锚点、坐标范围、间距、边界夹取、空间不足策略、滚动／缩放更新与关闭条件|
|保存、可编辑、建议接受混淆|保存已确认不代表恢复编辑完成，单项建议决定也不代表正式正文生效；信息分散时容易被读成同一状态|分别表达正文身份、持久化事实、编辑就绪、运行状态和最终采用；不能合并为含义模糊的一个状态|
|迭代与原设计脱节|用户曾明确要求只记迭代、暂不改原设计；后续又有多轮覆盖。实施记录内旧数值及检查观察仍保留历史含义|每轮记录来源、采用／替代关系、代码位置、设计合并位置和检查边界；正式合并替换原条目，保留历史依据|

对应代码入口及每项合并去向见[合并与一致性记录](合并记录-2026-10-09.md)。本轮是静态文档／实现核对，没有重复执行产品测试或把代码存在当成浏览器验收通过。

## 2. 按原模板补充的写法

本文最初编写时仓库没有独立的通用“规格需求说明模板”Markdown源文件；2026-10-10已按用户要求将当前桌面版本原样保存为[统一需求规格说明完整模板](../templates/统一需求规格说明_完整模板_重构版.md)。现有前后端设计采用第1、2、5、7、8章等统一结构。以下按该结构提供可复用条款，后续编写规格时放入对应位置。具体数字要由项目确定，不能直接把WALL-E的全部尺寸复制到其他项目。

### 1.3 填写与实施规则

> 每项交互填写触发、适用状态、操作过程、可见反馈、取消／失败恢复和数据后果。只写“体验友好、支持编辑、响应式、可访问”不算完成。确实不适用的条目标明“不适用及原因”。已实施不等于已验收；实现与已确认定义有差异时登记差异并处理，不从现有代码反推未经批准的新需求。

> 同一信息和操作指定一个主要展示位置。后续采用变更同时更新输入、处理、结果、状态条件、接口及验证条目；旧稳定编号保留为已撤销说明，不能同时存在互相冲突的可执行定义。

### 2.2 公共规则：组件责任与一致性

|填写项|必须回答的问题|示例|
|---|---|---|
|全局／页面／组件归属|谁拥有导航、头部、输入、请求和状态？谁仅负责呈现？|导航属于应用壳；路由拥有详情控制器，Portal只移动呈现位置|
|跨页不变量|哪些尺寸、颜色、强调和偏好不随业务状态变化？|同模块导航入口保持外观；aria-current表示语义|
|复合控件反馈|父子谁画边框、鼠标反馈、键盘轮廓？|搜索容器画唯一输入焦点；搜索按钮自己的焦点独立|
|状态来源|每个状态取自服务端、本地意图还是视图偏好？|本地填写数不作为正式回答；历史选择不作为当前运行|

### 5.1 公共视觉与交互

|控件／区域|默认及悬停／按下|鼠标／触控聚焦|键盘聚焦|禁用及原因|加载及错误|
|---|---|---|---|---|---|
|普通按钮|明确背景、边框和尺寸；状态切换不改变几何|是否增加轮廓及其责任位置|可见轮廓、Tab及Enter／Space行为|文字说明、title或关联描述；指出恢复路径|固定反馈位置；不以动画结束代表完成|
|输入／复合输入|原生与父容器职责|单一边框／反馈|单一可见焦点，强制颜色兜底|只读与disabled分别定义|错误色优先，保留输入，不重复Toast|
|图标／弹层|命中区、名称、展开含义|实际点击及外点关闭|键盘打开、关闭、焦点恢复|关键操作不得只靠悬停发现|覆盖层级、位置和长内容限制|

还需定义正文标题层级、行高和间距，以及正文／历史／预览之间的适用范围。数字明确标记“已固定”或“暂定”，不能混用。

### 5.2 页面入口、布局与展示

|区域|责任与内容|尺寸／空间分配|滚动责任|响应式与开合|长内容及异常|
|---|---|---|---|---|---|
|全局壳／头部|品牌、导航、页面头宿主|常态高度及异常增高方式|固定还是随页面滚动|窄窗入口、导航开合、偏好|长标题策略；真实错误不得被固定高度裁掉|
|正文|唯一主要文档区及所看身份|最小宽度、是否限宽、统一边距|谁是实际阅读滚动宿主|侧栏开合后如何获得空间|表格／代码局部横滚，不撑开页面|
|辅助面板|标签、历史、阅读、输入|上下限和正文保留宽度|阅读／输入／发送分别谁滚动|入口、关闭、调宽、焦点目标|失败保留最后内容；输入高度上限|

必须至少写明：大窗口、最小支持窗口、窄窗、所有辅助栏展开／收起、长标题／长表格、已有错误提示这几类组合。不要只列各组件宽度而省略相加后的可用空间。

### 5.3 页面数据与输入

|事件／操作|读取对象／请求范围|保存已改内容|是否冻结|保留哪些节点／内容|并发与恢复|
|---|---|---|---|---|---|
|首次进入／重新进入|列出实际资源|按业务需要|明确首次数据门禁|不以空编辑器冒充缺少数据|最新响应及对象身份校验|
|普通窗口焦点／标签显隐|明确“读”或“不读”；不写笼统窗口恢复|与重读分开定义|明确“冻结”或“不冻结”|编辑器、输入、选区、阅读位置|不得自动制造成功或丢弃输入|
|真实页面恢复／支持宽度恢复|定义对应事件及前置事实|必要保存及等待顺序|实际状态通过前暂停操作|已确认画面保留方式|幂等事件、失败专属重试|
|列表筛选／翻页|明确仅本列表或确需关联资源|通常不涉及正文保存|只禁用有关控件|成功页与查询关系保持|旧响应不覆盖新请求；空态不等于失败|
|写操作已接受／未知结果|写明后续读取及确认判据|原请求保持|按该操作状态|原输入和请求所有者|确认／恢复不转为新重复写入|

输入约束同时写正式提交与提前反馈的共同算法：Unicode长度、换行、trim、非法文本、IME、空白及超限。界面计数不能另用一套长度定义。

### 5.4 操作与结果反馈

每个操作沿用原表：入口与条件、对象／范围、输入与请求、调用能力、触发／准备／已确认成功／失败或取消。再明确：

|补充项|填写规则|
|---|---|
|入口层级|主／次／更多及所在区域；人工草稿、历史和正常读态分别列明|
|按钮不可用|列出每个原因及就近反馈、下一步，不能只写disabled|
|读取与恢复|常态是否自动更新；哪些错误才显示重试；请求未知如何确认；重试实际读取范围|
|弹层关闭|外点、Esc、焦点移出、重复点击；有未提交输入或未知请求时能否关闭|
|焦点序列|打开初始焦点、内部切换、关闭返回目标；触发元素已移除时的后备目标|
|真实完成范围|本地格式、本地回答、已接受请求、已保存、业务完成、正式正文生效分别说明|

### 5.5 特殊状态与生命周期

逐项列出首次加载、已有数据重读、读取失败、空数据、结果未知、历史只读、草稿未恢复、保存冲突、窗口阻断和IME。加载期间优先保留已确认内容与组件；需要暂停时单独约束交互，不能直接让整个页面消失。错误恢复只放在相关区域，正常状态不暴露每个内部读取控制器。

### 5.6 组件：编辑器及浮层契约

|能力|触发／入口|适用状态|事务及取消／撤销|焦点／位置|持久化边界|
|---|---|---|---|---|---|
|固定格式工具|逐项列举常用、更多与上下文能力|草稿、只读、恢复中、IME|命令不适用不改内容|保留选区，禁用说明|仅本地变化，保存由父所有者确认|
|斜杠菜单|位置、查询限制、类型、过滤、键盘|段落／代码／URL分别定义|删除查询与命令是否一次事务；Esc保留什么|焦点是否留正文、外点关闭|不伪造占位业务内容|
|选区格式栏|非空文本选区、支持样式|只读／暂停隐藏|模板锁及账本仍经过同一事务|完整选区还是光标锚点；固定间距；溢出与空间不足策略|不直接改正文DOM来伪造格式|
|链接|选区／光标／斜杠入口|合法协议、表单校验|保留文字或以地址为标签；取消和过期位置|表单属于编辑器内部区域|原保存机制，无新上传／模型请求|
|快捷键|准确组合及平台对应|仅编辑正文、IME例外|原撤销／重做与原生删除导航|不得截获表单自己输入|不触发业务提交快捷键|

> 编辑器内部区域须包含正文、固定工具、body／Portal下自己拥有的菜单、浮动栏和链接表单。内部焦点移动不等于离开编辑器；真正移出才按保存规则处理。必须考虑pointerdown、focusout、focusin、change的顺序；原生下拉展开时不销毁控件、不持续重写选中值。销毁时清理所有监听及浮层。

### 7.4 浏览器本地数据

每类偏好／输入填写键名、版本、默认值、用户写入时机、刷新／跨路由恢复、失效和存储失败。自动响应式夹取／收起不得覆盖明确偏好；读取缓存不能替代正式业务事实；布局变化不销毁受保护的输入和请求。

### 8.1／8.4 验证与质量

|最少应定义的交互场景|需观察的结果|
|---|---|
|复合控件真实点击＋Tab|不重复套框；键盘有焦点，错误和业务标记保留|
|鼠标打开原生下拉再键盘选择|完整焦点过渡可用；直接设置value或selectOption只能补充，不能代替|
|滚动／顶部不足／长选区|浮窗跟随规定锚点，边界及隐藏策略一致|
|普通切窗与必要恢复分开|请求、冻结、保留节点及保存行为分别符合触发矩阵|
|已有数据慢读／失败／重试|列表、输入和阅读位置保持；不变空态，不整体闪烁|
|窄窗／侧栏／长内容组合|实际宽度与命中区可用；正文不溢出；发送及恢复入口可达|
|输入与请求跨开合保留|本地文字、原请求、回复对象及正式版本身份一致|

检查规模按改动和用户授权选择；基本交互修复先覆盖真实路径，无需每项保存截图。结果在Markdown记录范围、方法、实际结果、失败修正与未覆盖项。设计要求、静态代码一致、基础检查通过、完整运行验收通过分开登记。

## 3. 后续变更的最小闭环

1. 以原设计定位问题，区分规则缺失、规则不适合、实现偏离和检查遗漏。
2. 迭代记录写清最终采用及被替代规则，明确是否涉及公共字段或数据语义。
3. 对照实际实现的事件、状态、命令和样式覆盖顺序，记录差异；源码存在不等于交互可用。
4. 同步原模板的对应字段／处理／结果／状态／接口／验证，保留稳定编号及历史归档。
5. 做本次必要的基础检查或静态复核，分别记录已核对、已运行和未覆盖内容。

这样能降低同类遗漏与回归的概率；仅补文档不能保证不再出现实现缺陷，真实交互路径和变更同步仍要落实。
