## 1. 视觉方向：OpenAI 风格黑白灰

原前端设计文档 [FE-UI-PRINCIPLES](WALL-E.V1_0.6.前端设计文档.md#fe-ui-principles) 已定方向："以黑、白和中性灰为主的简洁界面，参考 OpenAI 风格"。本迭代将该方向落为可施工的确定规则：

|规则编号|确定规则|
|---|---|
|DIR-01|界面主体只允许黑、白、中性灰三级层次：正文与主按钮近黑（#202124 系），次要文字中灰（#6b7280 系），辅助底色浅灰（#f3f4f6／#f7f7f8 系）。禁止引入蓝、绿、黄、紫等彩色底或彩色文字作为常规界面元素。|
|DIR-02|语义色仅保留三处：危险操作与错误（红 #b42318 系）、Toast 成功图标（绿 #15803d，仅图标）、当前定位高亮（中性深灰描边）。除此之外任何"状态表达"用文字＋图标＋灰阶完成，不靠颜色。|
|DIR-03|删除全部未登记的彩色令牌（slate 蓝灰系、淡蓝、淡绿底等），统一到 `--border`、`--muted`、`--surface`、`--danger`、`--success` 一组 CSS 变量；新增颜色必须先登记本文档再施工。|
|DIR-04|排版遵循 OpenAI 式克制层级：一级标题 24/32/600，区域标题 18/26/600，正文 16/28/400，界面文字 14/22/400，辅助说明 12/18/400。不再新增更大字号或装饰性字重。|
|DIR-05|强调靠留白、对齐、细边框与字重，不靠色块、渐变、重阴影。浮层阴影只用于弹窗、抽屉、Toast、下拉四类。|
|DIR-06|控件反馈统一：悬停浅灰底、键盘焦点 2px 深灰外轮廓、按下状态可辨、禁用灰字。所有可点元素必须具备悬停反馈，不允许无反馈的可点元素。|
|DIR-07|施工只允许引用下表令牌；样式代码禁止新增字面量颜色值。确需新颜色时先修改本文档登记，再施工。|
|DIR-08|页面结构契约：页面的行结构、区域划分与栅格以文档条目为准；条目未定义的结构，施工保持现状，不得自创。新增页面结构先登记本文档再施工。OPT-LAYOUT-05 的页头三行是本契约的首个实例。|

**设计令牌表（全部视觉条目的唯一取值来源）**

|令牌|值|允许用途|
|---|---|---|
|`--text`|#202124|正文、标题、主按钮底色、选中描边、进行中标章底、定位高亮描边|
|`--muted`|#6b7280|次级文字、时间、说明、图标、禁用文字|
|`--border`|#d1d5db|控件边框、卡片边框、下拉边框、评论标记边框|
|`--border-light`|#e5e7eb|分隔线、页头/页脚边、表格行线|
|`--surface`|#f7f7f8|辅助面板底、徽章底、用户消息底、警告条底、定位高亮底、已解决卡片底|
|`--surface-hover`|#f3f4f6|悬停底、选中浅底、下拉选项悬停|
|`--danger`|#b42318|危险按钮、错误文字、失败图标|
|`--success`|#15803d|仅 Toast 成功图标，不得他用|
|表单控件 accent-color|`--text` 同值|复选框、单选按钮选中态|

各条目（OPT-VISUAL-01～14）中出现的具体色值一律以上表为准；条目与令牌表冲突时以令牌表为准并回改条目。

### OPT-VISUAL-13 全局样式作用域纪律

|内容|确定定义|
|---|---|
|现状|根因条目：搜索双框、页码按钮 36px、复选框蓝色三个问题的共同来源是全局选择器（`button`、`input`、`:focus-visible`）无差别作用于所有组件，组件被全局规则误伤后只能再打补丁覆盖。补丁式修复（如只删搜索框内 outline）不治本，下一个新组件还会被误伤。|
|依据|DIR-03、DIR-06、DIR-07。|
|确定修改|styles.css 全局规则设白名单，只允许：`*` 盒模型、`body` margin、字体栈与字号、`button/input/textarea/select` 的 `font: inherit`、`:focus-visible` 外轮廓、控件 `accent-color`（随 OPT-VISUAL-10）。除此之外任何规则必须挂在组件类作用域下（如 `.pagination button`、`.search-input input`）；新增全局规则须先登记本条白名单。配合各条目完成后的状态：分页按钮尺寸归 OPT-VISUAL-08 的 `.pagination` 作用域，搜索框归 OPT-VISUAL-12 的 `.search-input` 作用域。|
|验收|styles.css 中元素选择器仅出现在白名单内；任何组件样式可被组件类完整描述，不依赖对全局补丁的覆盖顺序。|

### OPT-VISUAL-14 图标体系：内联 SVG 替代文本字符

|内容|确定定义|
|---|---|
|现状|根因条目：界面没有图标来源的定义，施工用文本字符凑图标——筛选箭头 `∧`/`∨`、加载 `◌`、搜索 `⌕`、关闭 `×`、Toast 图标 `✓`/`!`/`i`。字符字形随平台字体漂移，粗细不可控，与黑白灰方向不冲突但精度不可验收。|
|依据|DIR-04、DIR-06；FE-UI-PRINCIPLES"同类控件保持一致"。|
|确定修改|①图标一律内联 SVG，统一 16px 视口、1.5px 描边、`currentColor` 或 `var(--muted)`，禁止新增文本字符图标；②基础图标组一次性定义并复用：关闭（×）、搜索、清除、上/下箭头、加载（三点省略）、成功（√）、信息（i）、警告（△）；③现有字符随相关条目替换：箭头随 OPT-VISUAL-11、加载随 OPT-VISUAL-09、Toast 图标随本条、搜索/清除随本条；④Toast 图标颜色规则不变（成功绿/失败红/提示中性），仅换载体。|
|验收|tsx 源码无新增字符图标；同一含义的图标全站只有一份 SVG 定义。|
