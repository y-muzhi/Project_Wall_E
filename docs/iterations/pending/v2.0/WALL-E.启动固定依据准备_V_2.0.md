# V2.0 启动固定依据准备

2026-11-08，依据 BE START.PREPARE_BASIS、AI20-BACKEND、7.3／7.4。正式设计保持原样。

工作区原步骤核验后，后台在原 START 第二步预留确定的私有文件命名及有序版本摘要。主设计在先，材料按文档 ID 排序。完整 UTF-8 分文件保存，允许确认过的空材料。文件与封存回执沿真实 NTFS 原句柄独占发布，回执绑定原操作、任务、代次与每一份原文的身份及摘要。依据与可写代码目录隔开。

后台读取按原操作、原代次及原文件身份校验，使用只读文件句柄。公开操作只返回安全进度与文件数量。还未对执行器开放目录权限，后续经实际受信执行器入口施加并核验只读授权。

停止抢占禁止将迟到依据用于执行。重启仅核对原封存，完整且仍持有原资格可继续保存原完成事实；不完整或身份不明保留 UNKNOWN，不覆盖或重新分配。准备前能确定缺失的原文显示 CONTENT_NOT_READY。工作区已完成的事实保留。


## 只读依据文件的原句柄交接（2026-11-08）

沿原 START 的主设计及材料顺序，后端从封存提取编号、长度、原文 SHA256 和依据组摘要。Guard 仅在同一原 TASK 的 basis 角色内创建固定编号文件。创建必须是首次新建；文件继承该角色的读取权限与完整性标签。Guard 向已核验的原后端进程复制不可继承的写数据句柄，附带属性读取和同步，保留原 FileID。Guard 不读取正文。 [Microsoft 句柄复制](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle)

后端先核对原作用域、文件身份和实际句柄权限，按封存写入完整原字节，刷新并关闭。Guard 用只读、拒绝写及删除共享的原句柄核对写入已关闭、对象与长度，并保持该句柄；后端在该边界内独立读回原字节及摘要，Guard 接受同一原回执。相同编号只允许一次原派发，未知时继续观察，不能按可能复用的远程句柄编号强行关闭或重新发放。 [Microsoft 文件共享](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)

本批为单个原依据文件的本机交接组件。已准入生产管道上的整组发布、原 START_INSTANCE 分派、停止后的实际文件清理和 LPAC 访问仍独立完成。


## 整组依据的固定计划与关闭证据（2026-11-08）

后端从原封存生成一次有序计划，固定原任务／工作区／代次、来源摘要及连续编号的每个成员长度和 SHA256。原 Guard PREPARE 的输入摘要同时绑定计划 SHA256。Guard 在同一原目录 owner 内仅允许登记一个完全匹配的组，按计划编号发放原句柄。每份回执须对应原槽、FileID、内容摘要和原绑定，Guard 保持所有拒绝写共享的原读句柄。

只有整个依据目录与计划名称完全一致、每个原回执已核对、所有写入关闭且原作用域仍开放时，才在现有 Guard 私有日志内追加一次整组关闭证据。记录仅含原身份、计划及回执摘要和数量。重复或未知时读原证据并复核原句柄，缺件、换件、额外文件及停收时阻断。关闭证据只覆盖依据阶段，完整 PREPARE ACK、生产认证管道交接和启动前最终准入单列。

## 认证管道中的原目录保留（2026-11-08）

在同一 TASK PREPARE 中，后端明确请求文件角色保留时，使用原来源属性句柄、原步骤和固定依据计划摘要。Guard 先核对程序、原控制方及来源，持久写入原 PREPARE 意图和私有文件保留标记，再创建并持有新角色目录。完整分配后另追加一次原目录身份回执；只有该回执与当前原句柄同时核实才报告持有。保留请求及重复请求的整项 PREPARE 仍为 UNKNOWN；OBSERVE 可查询原绑定、原输入摘要、计划摘要和真实目录持有状态。进程重启、部分分配或原句柄丢失后只查原记录，不能接管或重建目录。

已受理的文件保留沿原 STOP 持久封闭，并核对未派发的原范围后关闭 Guard 所持目录句柄。目录及其内容的删除仍需完整 RELEASE 证据；仅释放句柄不能当作文件清理。依据成员句柄、工作区发布、运行包与隔离准入继续走同一 PREPARE 归属。

## 认证管道中的整组依据交接（2026-11-09）

在原 PREPARE 内增加受限的依据阶段。每个请求与回复使用原鉴权管道和原请求摘要，绑定原操作、步骤、nonce、目录引用及初次 PREPARE 的输入摘要。只接受同一原目录的活句柄及持久身份回执。计划按连续编号分段传入，各帧只含有界元数据。仅完整计划与原摘要一致后才按编号交接原写句柄；后端写入并关闭后由 Guard 持无写共享读句柄，后端独立读回并提交原回执。关闭阶段仅追加一次整组证据，查回阶段仅核对已保存证据及原句柄。回复只表示相应依据阶段，无完整 PREPARE 确认。

请求超时、断线或回复未知时不得重发可能已交接的写句柄，完整关闭只能通过原证据查回。STOP 先持久封闭原范围，再尝试确认所有原写端已关闭；未证实则保留原 owner 并让 STOP 保持未知。只有原句柄实际释放后才确认未派发 STOP。进程重启后缺原 owner 不能接管目录或推断写端已关闭。文件删除仍由后续 RELEASE 处理。

## 认证管道中的固定工作区发布（2026-11-09）

原 TASK PREPARE 一并固定原工作区树清单摘要。Guard 核对原目录及持有回执，先保存一次性发布意图，再返回原 workspace 目录身份和原生写入存续句柄。该句柄是仅传给原后端且不可继承的匿名管道写端。后端只在持有该句柄的范围内按原清单发布和读回，不向管道写入正文或控制数据。Guard 保持原读端，只以原管道断开事实核对写入范围已关闭。

Guard 的完成阶段沿原目录、清单及后端读回的树身份摘要持久保存一次发布证据，查回阶段只核对已有证据。STOP 先封闭原范围，发现原写端仍可能打开则保留目录和 UNKNOWN；原写端关闭后可确认未派发停止，部分目录仍由 RELEASE 处理。丢失写端回复不能重新发放。工作区证据与完整 PREPARE 确认及 START_INSTANCE 分开。
