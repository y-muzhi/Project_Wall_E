# V2.0内容选择实现绑定补充

日期：2026-11-05；状态：PENDING／实施细化，未自动合入正式设计。来源BE0.17-draft-17的7.2.1—.2及OBJ-CODE-POLICY；不新增捕获／权限或真实执行授权。

## 固定语义

- 选择器只计算路径是否纳入和Git模式，无文件／Git／数据库IO，不代替完整枚举、秘密检查、原生句柄、静止、封存或准入。
- 精确文件规则只命中该文件；末尾一个/表示目录及其所有后代，不按裸字符串前缀命中相邻名称；include的“.”匹配全部新增文件，exclude不允许“.”。空include数组仅保留实际仍存在的跟踪路径。
- 合法文件名中的!、方括号、$等仅按原文精确匹配，不解释为否定／glob／Shell表达式；Windows本已禁止的*、?等仍拒绝，不运行任何展开。
- 基线完整文件集先用既有ContentPathIndex核对路径、模式、重复、父目录别名及文件目录冲突。跟踪文件按精确原路径自动纳入并保留原模式；文件已删时由完整枚举反映缺席，不凭规则制造删除。新增文件统一取固定new_file_mode。
- 规则原文不去空白、不改大小写、不规范化成另一条规则。两侧各自或跨侧同一规则拒绝；同名文件与目录、父目录大小写别名冲突拒绝。include目录内排除非产品子项允许；exclude目录完全遮蔽显式include子项则拒绝。正常父子include重叠只影响布尔选择，不重复采集或删改输入规则。
- 非产品排除规则命中任一基线跟踪文件即配置不适用，包括跟踪项在后续候选被删除的情况；不能通过当前存在性绕过。规则与基线／枚举路径的共同父段若为casefold别名则拒绝，不静默漏选。
- 目录剪枝仅依据明确exclude目录规则；不因没有include命中便剪枝，以免漏掉其下自动保留的跟踪文件。调用方在剪枝后不得打开其后代正文；这一纯选择器无法单独证明调用方已遵守。
- 所有错误仅返回固定原因，不回显项目路径或内容。错误归SOURCE_UNSUPPORTED，不把失败当空选择。

## 后续接入

该绑定为原设计“重复／别名／冲突”及精确路径语义的程序化细化，不发布秘密策略／可用CaptureRules或执行配置。后续完整捕获器必须实际调用本选择器，分别核对新增、跟踪、目录剪枝、失败／取消及模式；未接入前只标组件已验证。
