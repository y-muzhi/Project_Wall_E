## 2. 前端设计范围

主路径为文档入口 → 文档代码任务列表 → 具体任务工作区；全局设置承载仓库、执行配置、检查配置和授权。创建使用抽屉，固定设计、材料、起点、目标、配置、授权和预算后只保存；开始另行操作。

任务工作区用执行、代码、检查、交付、用量五个页签，问题和等待事项在执行视图处理。现有文档讨论、版本阅读、消息和请求详情按所属复用，不另建角色聊天大厅、控制台、代码编辑器或文档讨论体系。

## 3. 本轮补齐的契约

| 条目 | 确认的缺口 | DRAFT处理及边界 |
| --- | --- | --- |
| F20-01 固定版本选择 | 现有RevisionSummary含版本标记，不直接给出编码资格；不能把markers当确认 | 新增只读可选设计版本投影，服务端按既有确认事实判断；原Revision原文接口继续复用 |
| F20-02 来源文件选择 | CAPTURE_BASE需要include_untracked_paths，但首稿无可读取文件观察 | 仓库显式刷新记录文件观察，另GET分页读取；GET不刷新磁盘，失效返回真实SOURCE_CHANGED |
| F20-03 配置设置 | 前端不能凭空构造解释器、模型、命令、runner或凭据引用 | 提供已有受控配置选项目录及版本列表，只读固定资源／配置；无任意Shell、脚本或秘密编辑 |
| F20-04 检查／计划定位 | 刷新后只按最大ID猜当前检查／计划会混用历史结果 | TaskView提供当前控制链中明确采用的检查／计划／交付引用，合格性由服务端计算；补齐原有检查／报告／移交接口的动作许可，不增加新业务阶段 |
| F20-05 前后差异 | DiffItem只有清单，FileChunk只读候选，无法读取修改前内容 | 按已固定比较对读取前／后字节，不允许客户端传任意Git树或服务器文件路径 |
| F20-06 移交及历史恢复 | 移交准备可写但缺刷新后的关联读取；历史修复／交付缺直接定位 | 补同任务只读移交及报告／修复／交付详情，不触发源问题答复或文档调用 |
| F20-07 原回执查询 | 未知HTTP若无operation_id，现有草稿只能重发POST来找原结果 | 在现有幂等记录上增加只读回执查询；无记录不证明没执行，GET不补送命令 |
| F20-08 新路由直达 | 当前生产SPA只放行/requirements及详情 | 后端前端壳明确放行新增页面路由；不添加通用静态目录或吞掉/api的catch-all |
| F20-09 页面生命周期 | 隐藏、离页、读失败、已接受、结果未知及版本冲突需分别处理 | 复用ApiAction及读取隔离，自动恢复只读；用户显式原键恢复才可能补送 |
| F20-10 文案及布局 | 新增区域必须按业务提供空态，按钮真实状态及宽窄可达 | 按共享模板5.1—5.6定义；静态文档不等于浏览器通过 |

## 4. 不变的业务边界

- 固定已确认Revision；文档新版本不静默换任务依据，采用新设计先终止旧任务并确认停止。
- 单主文档一个活动任务、单工作区一个写入者、三角色顺序执行及共享预算。
- 程序判断权限、状态、检查和交付事实；前端不能用按钮状态或模型文字代替事实。
- 固定代码、独立检查副本、完整目标预览、人工接收和实际Git交付分开。
- 创建不开始、移交不发送文档讨论、预算追加不自动继续、普通刷新不执行模型／检查／Git写入。
- F1／F2、主动工单、知识库或指标路线图不加入本期。
