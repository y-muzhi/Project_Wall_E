日期：2026-11-11。依据 BE APP-CODE-REPAIR、SHR-CODE-SINGLE-WRITER、原生终止观察和 FE 修复历史。此独立迭代保留在 pending，不自动合入正式设计。

原生已接受修复消息后，最后一轮以 CANCELLED 结束并且原 Guard／Job、会话、消息、问题／权限边界已核实静止时，沿同一事务保存原 QUIESCE 观察、消息及原工作区证明，关闭本轮模型窗口。原修复及未执行的候选捕获标为 CANCELLED，不形成新候选；当前任务回 VERIFYING，原候选、缺陷及会话历史保留。不能再以 EXECUTION_NOT_STOPPED 配合“本次修复未发送”描述已发送、已取消的原轮次。

后续继续仅接受新的明确修复或捕获动作。CLOSED、CANCELLED 或旧候选的历史静止本身都不授予写入权；必须核对同任务、原会话／消息、原代次、来源候选、固定恢复／发送步骤，以及原运行绑定的 QUIESCE 观察。新动作再检查当前写入者与工作区，既有原键仍读取原接收回执，不自动重发原消息，不伪装为新角色或完成阶段。

取消后用户也可明确捕获并自检当前代码。新候选必须来自同一会话、代次、原取消消息及工作区的后续真实捕获／QUIESCE，不用 CLOSED 标志或原取消记录替代该捕获证据；当前运行摘要使用新捕获的时间。旧缺陷仍绑定旧候选，不自动转移；对新候选发起修复前需明确登记／选择属于新候选的报告。
