# V2.0 代码任务开始原接收与工作区分配

2026-11-08，依据 BE APP-CODE-CONTROL、API17／34／35、7.2.6 及 SHR-TASK-UNSTARTED-STOP，正式设计保持原样。

- START 只收当前任务版本，先读取原幂等结果，再核对状态、停止意图、已有原操作、授权、预算、真实配置与受信工作区队列。原 202、版本递增及六步在同一事务；任务保持 PENDING／PREPARING。配置或安装未就绪保持原键可重试，不创建任务操作。
- 专用原生线程从持久队列推进 RESTORE_WORKSPACE。分配编号、原 nonce 与专用父目录身份先于目录创建保存；原暂存文件身份先于发布保存。Git 与 NTFS 操作在事务外运行，保存结果前复核原代次。丢失回执、停止竞争和重启沿原分配保留未知，禁止重复物化或凭目录存在认定就绪。
- API17 公开原步骤及已验证工作区 ID，隐藏路径、nonce、NTFS 与私有证据。实际首次消息确认之前不置 RUNNING。本批仅接开始及首次工作区，依据文件权限、原生会话和常规停止后续接同一原操作。

若停止抢占的是已接收但六个原步骤仍全部 PENDING 的 START，只有在原 202、原代次、工作区与其他分配全为空的证据成立时，才在原停止的完成事务内取消该 START 并完成空范围停止。仍回放 START 原 202。若已登记任何工作区分配，继续保留 STOPPING，等待原资源核对。
