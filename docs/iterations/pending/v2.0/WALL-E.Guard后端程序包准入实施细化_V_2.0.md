# Guard后端程序包准入实施细化（2026-11-06）

来源：BE0.17-draft-17 7.3.1要求真实后端程序／保护运行包和安装清单；用户已确认[跨控制方窄恢复](WALL-E.Guard重启跨控制方恢复权限细化_V_2.0.md)必须同已准入程序。技术实施细化，先记录再写代码，不自动合并正式设计。

## 输入、输出及不变量

Guard服务的受信安装配置指定固定本地NTFS运行包根及manifest SHA256；RPC不能提供或替换这些值。采用BACKEND20-PROTECTED-1清单：固定后端独立原生入口walle-backend.exe、程序引用、完整相对文件清单／长度／摘要。入口必须是受信打包的后端程序，不按任意Python解释器、命令行文字或用户可写脚本推断程序身份；BE已允许实施时选择Python／Win32打包方式，本细化选择可固定程序图像的独立入口，实际构建及安装另记录。

只读验证不更改ACL／所有者／权限／程序。实际CLIENT peer原进程令牌、固定图像FileID／字节应与该清单入口相同；全部包文件与目录、manifest和所有祖先必须经原句柄及真实后端令牌有效权限检查，不能写／删／改DACL或owner，且能按角色读取／执行。清单完整枚举，拒绝额外文件、路径别名／reparse／硬链接、缺文件或摘要不符；不只验证主exe。用原文件读取租约及路径句柄保持原对象，后续验证重核权限描述符和固定内容；任何缺项拒绝，未知不降级。输入有界、截止／取消在文件间检查，操作系统本地同步读本身不宣称可强制打断。

清单最多4096文件，单文件≤64MiB、总文件≤512MiB，manifest≤1MiB；确定UTF8排序、原路径不规范化。引用和hash属于Guard受信部署输入，不是认证凭证。lease仅证明本条包保护及当前peer，不替LPAC／WFP／模型或整个RuntimeBundle的全部准入。

## 与原登记及恢复接入

原控制方登记明确区分仅实际peer事实（无程序准入）与由实际保护包lease产生的准入摘要；无准入的旧记录不能事后补签或被新已准入程序接管。生产外部动作必须使用后者，不能根据metadata记录或请求中的布尔值放行。恢复还要核对同安装／用户／程序及原scope、旧控制方实际退出或Guard可靠封闭；程序验证本身不停止或释放任何对象。

## 验证边界

本轮先实现严格codec、只读原生验证、拒绝可写测试包／伪peer及资源寿命，使用新隔离目录和自有Job。没有实际受保护walle-backend.exe安装和SYSTEM Guard，不能把同用户／替身／纯向量当真实程序准入；runtime_admitted与ready保持false。系统安装、既有ACL／WFP或服务更新、真实模型均未扩展授权。
