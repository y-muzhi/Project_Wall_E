# V2.0 首次工作区固定字节物化

2026-11-08，依据后端 APP-CODE-CONTROL START、7.2.6 及 TC-GB20-05。此处细化内部物化边界，正式设计保持原样。

- 复用原固定 Git 读取，在通过路径、类型、字节、大小及秘密规则后按文件写入。仅以固定对象原字节构造新文件，Git 模式随原条目保留。Windows 属性不替代固定 Git 模式。
- 物化只接受受信代码提供的原预留 nonce 及专用的私有父目录。暂存与目标同父且名称由该 nonce 确定，使用独占创建与不覆盖重命名。Git 批、原引用、已登记内容摘要、暂存全量目录／身份／字节均核对后才发布。
- 目标或暂存已存在时拒绝新写入，不自动复用、清空、删除或重派。读失败、取消或结果未知时保留原暂存或发布目标，由未来原 RESTORE_WORKSPACE 步骤核对；不能凭目录存在确认步骤完成。
- 先验证私有物化入口与固定 Git 的衔接。原 START 接收、工作区行及持久分配身份、停止协调、恢复及授权施加在业务执行链落地后接入，现有只读查询及创建任务不会分配工作区。

## 原设计依据读取

同一读取事务按任务原绑定核对需求、主设计、材料及各版本的确认事件。主设计先返回，材料按 document_id 升序；读取完整 UTF-8 原文，保留 BOM、换行和已确认的空材料。缺失、未确认、错归属或无法编码的原文使整组失败。既有设计版本列表与任务读取继续只返回原元数据。原生只读入口、原步骤持久化及发送在实际运行器接入时完成。

## 启动接续边界

C35 在同一写事务核对原版本、可执行配置、预算及停止意图，固定原 START 和六步骤。RESTORE_WORKSPACE 的 code_workspaces 资源及原 nonce 应在进入组件前登记，原暂存卷及文件 ID 在发布前归入原步骤。发布回写重新核对控制代次和停止屏障；收到停止后仍保存已发生的资源事实供原停止核对。恢复沿已登记对象及原证据，不能因路径不存在或存在自行重派。现行组件仅接收私有的受信调用，不从 API32、API34、基线列表或用户输入获得路径与分配授权。


## 原执行工作区的固定字节发布（2026-11-08）

START 已保存的私有工作区和树清单继续作为只读原来源。Guard 核对本次 TASK 目录分配后提供实际 workspace 角色的 FileID、原 scope 和绑定。普通后端在尚未启动执行进程的原 START_INSTANCE 作用域内逐文件复制；每次核对同一原状态、清单内容、路径与目标身份。只用原清单字节，不读取真实源仓库或新 Revision。源与目标分离。目标必须是新分配且为空，文件以只新建方式写入，文件模式仍以原清单为准。

使用现有私有记录机制，在写目标前封存原发布意图，并在完整逐文件读回后保存同一发布的文件和目录身份摘要。重复请求只读取原意图和原回执、核对真实目标。中断导致没有完整回执时保留未知，不能凭同名目录、已存在文件或重启重新派发写入。

本批范围是可写 workspace。原 basis 仍由后端保管，生产中的只读依据副本要由 Guard 对已鉴权后端交接受限写入句柄，并在启动前封闭写入；Guard 不读取正文。配置及运行包的发布、实际 LPAC 读写、入口和 Job 证据仍独立验收。


异账户部署需为工作区交接准备独立受管父根。后端的原目录核对会逐级打开属性句柄，现有 Guard Journal 的 operator-only 根只适合同账户隔离测试，不作为异账户发布根。部署时应给原普通控制方授予必需的属性读取与穿越权限，并保持 Guard 私有记录和其它任务资源的边界。此项和实际 LPAC 读写分开取得证据。


### 独立执行父根

安装配置在已持有的可信目录下固定使用新建的 `task-runtime`，打开既有部署时必须提供同一个 NTFS FileID。父根由 Guard 操作者持有，给已登记的原普通后端 SID 一条不继承的 FILE_TRAVERSE、FILE_READ_ATTRIBUTES、SYNCHRONIZE 允许规则。不存在目录枚举、创建、删除、改 ACL 或改所有者授权，也没有任何任务 LPAC SID 的允许项。Guard 私有日志、后端来源和执行父根相互分离。创建只接受新对象，打开时校验原 DACL、标签、卷和 FileID，已有对象权限不修复。 [Microsoft 文件访问权限](https://learn.microsoft.com/en-us/windows/win32/fileio/file-access-rights-constants)

Guard 复用原控制方令牌的 Windows AccessCheck 核对原父根的有效掩码。异账户还核对每个上层目录的属性读取／穿越及不可改 ACL、所有者或原对象的边界。不可核对时不进入分配。同账户隔离夹具继续验证结构和实际任务复制，不能据此作为异账户部署证据。
