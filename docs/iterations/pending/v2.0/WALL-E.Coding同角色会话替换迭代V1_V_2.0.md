# Coding 同角色会话替换实施细化 V1

日期：2026-11-11。依据 BE 0.17-draft-17 APP-CODE-REPAIR／APP-CODE-HANDOFF、SHR-CODE-SINGLE-WRITER、TC20-96；FE 0.16-draft-16 的原操作／修复历史。保持 pending，未经用户要求不合入设计。

本批从明确修复中的原生会话已归档分支开始：原生 GET 的同一 session／metadata 中 time.archived 必须是正安全整数，且原触发消息已完成或取消、问题／权限为空、原 Job 只剩原根、工作区及 Guard 回执相同。归档本身不证明静止；缺失／失败／未知不创建新会话。可继续复用的原会话保留现有单次继续路径。

输入为原 C59 不可变操作／来源候选／有序缺陷、固定设计和授权及新核实旧静止。恢复原候选字节并保留所有选中变化文件后，在原 STOP／写入栅栏中保存 RESTORE_SOURCE 的不可变 replacement 创建意图：原会话、原代次、同角色目标会话、新代次、nonce、来源候选、原窗口及实际 QUIESCE 证明。旧入口撤销后退役，任务指向唯一 PREPARING 目标；原 Operation 的 session／control_generation 和原候选历史不改。新原生身份可核实且来源恢复成功后，才保存恢复结果并排入原 SEND_REPAIR，模型仅通过同一原意图授权的新窗口。旧入口永远不复活。

创建和首次发送复用 TaskNativeActions 的原私有意图／回执与精确 metadata 查找。已可能创建／发送只读回原身份，不建立第二会话或换消息。原四个修复步骤不新增并行操作类型，不用 HANDOFF_ROLE 伪造角色完成。同角色来源链必须逐条校验真实 REPAIR、来源候选、QUIESCE、目标和原生创建结果；后续角色交接仍只有 BACKEND→FRONTEND→INTEGRATION 两次。新候选必须重做当前和前序阶段自检，旧报告／交付资格不能沿用。

失败、取消、STOP 和恢复均保留原创建意图及旧新会话。未知创建保持原恢复步骤待核对；未知消息按原消息只读核对，不宣称未发送。没有原控制方／Job／工作区或完整来源时安全阻断。本批不处理整个旧实例丢失、新实例重建或无法证明旧写入者停止的情况。

检查先覆盖真实隔离 SQLite 不可变事实和角色链，再扩大原 START／RESUME／REPAIR、模型入口、捕获／STOP 与实际 Guard 联合。原生发送使用离线夹具；真实模型／计数、普通业务库、用户服务更新、SYSTEM／WFP 安装和 Git 提交／推送均未授权。

前端原修复历史的 EXTERNAL_RESULT_UNKNOWN 统一显示“原修复操作结果待核对。”，同时覆盖原恢复步骤的新会话创建未知和原消息未知。状态及原步骤继续按实际记录读取，不把尚未发送的创建未知描述成消息已发送；不新增自动重发或自动修复入口。取消、人工确认和原请求查询仍保留。

原生创建跨步骤完成后、保存原发送意图前，再核对同一旧触发消息的完成／取消、原 Job／Guard 和工作区；沿原完整来源清单复读／恢复实际字节，原文件句柄继续持有至 SQLite 记录发送意图。新的外部改动不因先前恢复记录而被忽略；不符合原恢复清单时保留原创建范围并阻断消息，不另建会话或遗失已保存原文件。
