# Git历史读取与当前内容校验实施细化

日期：2026-11-05。状态：实施中，保留pending，不合并两份DRAFT。依据BE0.17-draft-17的7.2.1／.2／.6、7.7.1／.2／.3；前后端设计SHA及当前pin沿实现进度。

## 目的及最终规则

完整可读历史与当前选定版本可物化分别核对，不给出新的可执行资格。历史检查从明确完整commit OID集合出发，读取每个原父commit、树及必要blob原始字节，逐对象校验类型／原OID，不能用refs枚举或单对象读取代替。只返回原根集合的对象关联证明，不声称仓库全部不可达对象或标签均已扫描。

历史树结构解码与CONTENT20路径校验共用一份二进制记录解析。历史旧文件名或符号链接blob不在本步骤物化，也不能据历史读取拒绝当前版本的合法文件或对其默许；选定树仍必须经过现有严格decode_tree_edges及完整内容规则。gitlink为外部对象依赖，本期拒绝，不跳过冒充闭包。此分离不增加当前版本的符号链接／子模块支持。

所有边（包括重复指向）、唯一对象、单次及累计原始读取字节、墙钟时间分别有显式程序预算；不是新增用户配置字段，也不把历史读取总字节冒充按当前文件条目计的max_snapshot_bytes。业务调用方需从已采用限制和当前原生能力建立适用预算，无法建立时不可就绪。每次原读取前后以及最终结果前核对取消、原来源／操作资格；超时／取消／缺失／错类型／坏对象一律不返回部分成功，不跳过或fetch补对象。重试只能由原操作判断，遍历器不自动重试。

输出仅有界确定元数据，不保留对象正文／用户身份／消息或私有路径为审计。读取仍由原RepositoryObjectCommand／原Native／Job／有界管道执行，不增加自由命令、第二套调度或由模型上传的对象证明。后续基线固定树遍历复用同一原始对象读取与既有ContentPathIndex／ContentEntry；秘密策略未真实登记验证时，不宣称基线可用。

## 影响及验证边界

修改git_object_graph.py共用结构解码，新增受限历史遍历组件；按实际调用路径补纯失败／容量／取消及真实固定Git两格式证据。对象结构或纯fixture通过不替代完整仓库业务、原OperationStep／保留ref／GitReceipt、Windows部署Guard或真实供应方验收。API／DTO／Schema、正常库／用户仓库、运行服务及系统策略均不改。完成及实际结果见需求映射和本轮Markdown验证记录。

## 固定树读取组件（2026-11-06）

当前树逐路径展开，重复blob／子树按每个路径计量，复用同一原对象读取预算；校验实际目标路径及全部目录别名，拒绝LFS指针头和普通模式外内容。文件检查必须由可信调用方显式提供，无默认放行；回调本身不代表真实secret_policy_ref已登记准入。组件只返回原文件元数据，不创建manifest、包或基线，不宣称策略资源／物化完成。
