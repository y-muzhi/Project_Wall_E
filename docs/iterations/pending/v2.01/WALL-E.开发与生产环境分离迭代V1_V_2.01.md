# 开发、集成与生产环境分离迭代大纲 V1（V2.01）

日期：2026-11-14。修订1.18／DRAFT。状态：多环境目标已确认；云端平台与技术选型为第一议题，部署范围及实现分工待选型收口；未实施、未合入正式设计。

本文定义本迭代的目标、业务边界、运行职责、完整流程及验收要求。后续前后端设计按本文展开，不另立第三份共同规格。架构与平台选型另文评审，README仅作导航。

## 0. 当前第一议题：架构与平台技术选型

平台评审单独见[架构与平台技术选型评审](WALL-E.架构与平台技术选型评审_V_2.01.md)。该文档集中维护Mac本地Linux开发、云端架构、V2.0平台影响、开源工具及验证门槛；本大纲只保留业务目标和流程要求，不重复定义选型结论。

## 1. 目标、范围与完成标准

### 1.1 目标

支持多个外部Agent并行修改WALL-E自身代码，防止开发、构建和测试污染正常使用的代码、数据与运行资源，并提供系统内可视化管理。总体结构为“一套生产环境＋多套任务开发环境＋独立集成环境”，通过固定候选包验证后再发布。

单宿主仍共享CPU、内存和磁盘，通过受管操作的资源检查、并发限制及协作约定降低争抢，不承诺开发负载对生产性能完全没有影响。

### 1.2 V2.01交付范围

| 必须交付 | 最低完成标准 |
| --- | --- |
| 基础隔离 | 工作区、依赖、配置、持久数据、可写运行资源、浏览器状态和请求不串环境 |
| 多Agent协作 | 两个独立任务能并行开发和检查；按任务绑定环境，支持人工接入、交接和成果保留 |
| 可用应用 | 隔离应用可以启动并访问页面，使用隔离创建的数据或明确夹具验证文档读取、人工编辑和保存；不能只验空页面 |
| 集成与交付 | 指定负责人组合任务成果并验证，生成准确版本的固定包；系统展示真实交付与验证依据 |
| 管理与发布 | 独立管理入口、完整创建、启停、分项清理、发布及恢复实际可用；在隔离的生产角色实例上验证完整流程 |
| 云端选型与准备 | 优先完成第0章平台比较与验证安排；配置和身份不绑定本机。实际云接入是否纳入本期及其验收范围，随选型明确 |

环境准备完成、应用启动正常、业务能力通过验证、真实模型获准调用是不同状态。默认禁止真实模型和计数，不妨碍无模型的基础功能验收；也不能用离线结果宣称真实模型能力通过。

内部Coding／Testing按明确的发布基线和能力清单独立准入。基线尚未具备的能力不因本迭代自动承诺补全；原已具备或本次拟启用的能力必须检查实际环境隔离及适用调用路径，不能通过统一禁用掩盖回归。声明要求的能力缺失时，阻止对应环境就绪或发布；不偷偷降为另一个用途后宣布完成。

### 1.3 不包含与后续事项

先以单宿主业务实例作为最小部署单元，具体本机／云端位置及管理方式由第0章选型确定。成熟平台已有的远程能力可评估复用，不预先自研跨机器控制系统，也不承诺多云、多租户、分布式数据库或多副本应用。

云端验证优先进入选型安排，正式云接入在平台与执行范围明确后实施；采用全新数据，不迁移旧历史记录、业务数据和任务成果，不要求旧任务续跑。这不授权现在删除本机数据，也不取消日常生产更新中的数据保留与恢复保护。

本迭代不建设外部Agent调度平台，不自动解决代码冲突，不替代内部Coding／Testing业务规则，不承诺无感热更新。不要求先完成全部V2功能，也不将所有在研代码默认发布到生产。

## 2. 基线、复用与适配依据

### 2.1 固定交付基线

先完成第0章选型；开始详细设计和实施时明确目标平台、来源提交、所选业务设计、资源与依赖版本、数据库结构、前后端协议以及能力清单。V1.5正式设计和V2.0草稿／独立迭代保持各自状态，文件存在不等于实现或验收完成；当前混合工作区不能直接视为可发布版本。

优先复用现有数据库维护、资源准入、打包、业务权限、原命令核对和受管执行机制。新环境管理记录与产品内部任务、业务状态及执行记录分开，不用占位Coding任务承载环境管理。

生产接入需要可运行且匹配数据的基线，但不阻塞先建立隔离开发环境。旧实例不具备环境身份或维护协议时，不伪装为已受管；接入计划需先核对现场，明确必要适配、停机和数据维护，再获得对应操作授权。

### 2.2 现有入口与增量边界

| 现有依据 | 本迭代适配要求 |
| --- | --- |
| 数据库显式路径、Schema核验和进程锁 | 保留显式初始化／升级；增加环境归属与真实路径冲突检查，不能仅依赖按路径生成的锁文件 |
| 普通与固定包启动入口、前端资源选择 | 统一解析明确配置；普通入口当前默认backend/frontend/dist，不作为生产隐式回退；同时检查业务入口和维护入口 |
| 服务启动恢复、HTTP与后台工作线程 | 环境及持久维护状态先于恢复和新执行生效；禁止新HTTP请求不等于后台已停写 |
| 部分读取入口会调用受管查询并保存私有记录 | 维护允许动作按真实副作用分类，GET不自动等于无写入、无进程活动 |
| 现有关闭宽限期与取消逻辑 | 不直接用于主动发布等待；先完成维护收尾再进入关闭，不能由宽限期到期代替用户取消决定 |
| 浏览器API严格解码、草稿及命令恢复 | 身份握手先于业务读取／恢复；新增维护与误绑定错误须前后端正确识别，不能一律吞成结果未知 |
| 工作区源码快照及包构建 | 补齐与固定提交、外部固定资源及前端产物的关联；源码快照通过不等于来源提交正确 |
| Guard固定程序身份、宿主配置与运行目录 | 不能把生产Guard配置直接交给可变开发程序；每个启用环境必须有匹配的准入及资源归属 |
| 业务任务授权、凭据与真实模型入口 | 任务预算／执行授权不等于管理登录或业务访问认证；显式隔离配置来源，限制计数、文档AI及内部任务的实际外发路径，不只隐藏界面按钮 |

适配依据入口：[V1.5设计](../../../design/v1.5/README.md)、[V2.0设计](../../../design/v2.0/README.md)、[部署说明](../../../project/v2.0/受信部署启动说明_V_2.0.md)、[数据维护说明](../../../project/v2.0/数据库维护使用说明_V_2.0.md)。以上是复用和适配依据，不是本迭代完成证明；具体源码位置与实现映射由详细设计及实施计划核实。

## 3. 环境模型与管理职责

### 3.1 用途与身份

| 环境用途 | 代码和运行方式 | 数据及成果 |
| --- | --- | --- |
| 任务开发 | 固定起点的独立工作区，可编辑、构建和检查 | 独立开发数据和可写依赖；成果明确交付 |
| 集成 | 独立工作区，指定负责人串行组合代码 | 独立验收数据；保留组合版本和检查依据 |
| 候选验证／模拟生产 | 固定候选包及运行配置，不跟随开发源码变化 | 隔离验证数据；验证与发布对应同一候选 |
| 生产 | 经确认的固定包和受控配置，不使用开发服务器 | 独立持久业务数据及恢复资产 |

候选验证是环境用途，不是新增业务角色；使用生产角色验证发布时仍采用隔离数据，默认禁用真实调用，不能仅凭角色名称获取生产凭据或模型权限。用途在准备时明确，开发／集成不能通过改标签变成生产；晋升的是已验证的固定包，不是任务工作区、验证数据或调用许可。生产采用自己的配置和持久数据。

环境稳定身份、用途、宿主、数据代次、部署版本、配置版本和本次运行身份分别表达。重启、正常业务写入、Agent交接不改变环境身份；新任务使用新环境。新建、清空、恢复旧快照或替换数据集产生新的数据代次，原命令和草稿不能自动归入新代次；保持数据连续性的兼容更新不因换程序就清空草稿。进程号、端口、环境名称均不能替代这些身份。

### 3.2 外部开发与内部执行

外部Agent修改WALL-E代码的开发任务，与WALL-E内部编程／测试任务分开，不混用身份、授权、工作区和结果。环境管理不决定内部业务任务成功、失败或完成。

开发和集成可位于本机或云端开发主机，通过固定版本和包交付；本期具体部署位置与管理方式由第0章确定。云端生产的内部任务在服务器侧执行，不依赖用户电脑开机，也不直接读取本机目录；成果通过明确下载或仓库交付取回。

当前Windows依赖按第0章评估；不将路径可配置解释为任意操作系统支持。Windows与Linux使用同一能力标准验证，不按操作系统偏好决定；目标平台与内部执行仍需实际准入，不预先承诺任意跨宿主执行或自动文件桥接。

### 3.3 管理、业务与维护入口

| 责任方 | 负责事项 | 不承担事项 |
| --- | --- | --- |
| 管理平台及必要适配层 | 配置登记、资源归属、操作协调、观察与结果记录、用户界面 | 不直接读写业务正文、替代业务事务或决定业务任务结果 |
| 业务实例 | 业务权限、请求接收、任务执行与收尾、提供必要状态 | 不管理其他环境或自行改变部署目标 |
| 专用维护入口 | 原有规则下的数据初始化、升级、核验和恢复 | 不因运行维护命令自动开放业务或扩大目标范围 |
| 宿主安装／维护入口 | 安装必要固定组件及管理程序的更新恢复 | 不随普通环境创建任意安装系统服务、扩权或修改其他实例 |

上述划分是职责边界，优先由选定平台和必要适配层承担，不默认新建完整自研管理后台。独立管理入口可由成熟平台提供，WALL-E补充任务关联及业务控制；不预建远程执行代理、分布式锁或通用调度协议。管理能力独立于业务实例运行，业务实例停止后仍可观察登记和操作。其程序、配置、持久记录不放在可变开发构建输出中；升级管理程序不能依赖该程序在被替换期间自行完成恢复。

首次安装完成管理访问身份、允许操作的根目录、资源来源及必要宿主组件准备。本机部署默认仅监听回环地址；云验证优先受控私网访问，入口、认证及监听位置随目标部署明确。不因同机或上云免除认证，也不自动向公网开放管理、数据库或执行控制端口。业务会话与管理权限分开，任务负责人名称不是认证凭据；不把管理秘密写进Agent使用说明。系统级安装使用专用受控入口，普通开发程序和业务进程不整体提升权限。

### 3.4 操作记录、互斥与观察

本期同一宿主采用一套受管环境登记和一个活动管理写入者；第二个管理实例不能通过另建空记录接管相同资源，多浏览器操作仍经过同一控制者。管理操作先持久记录目标、原意图和资源归属，再执行外部动作。请求被接收、动作正在运行、实际成功、明确失败和结果未知分别展示；进程退出码、端口消失和请求超时都不能单独证明业务结果。

同环境的启动、更新、清理等冲突动作互斥；跨环境竞争同一目录、端口、数据或宿主组件时也必须排他核对和预留，不能各自检查空闲后同时占用。预留不等于启动成功；结果未知时不把资源释放给新操作。查询和针对原操作的取消／核对不能被长操作互斥永久阻断。

重复请求关联原记录，不产生第二次副作用；取消是针对原操作的请求，不等于动作已经撤回。未派发步骤可撤销；已派发步骤只能按实际能力请求停止并核对，不能改称从未执行。继续原操作仅推进已确认未执行的步骤；部分完成或未知步骤先走原结果核对／专用恢复，不能盲目重复。已经执行的结果如实保留，需要补偿时另有受控动作。

管理程序重启或连接恢复后先核对原操作和资源，不自动重发。管理失联不自行终止正常业务；已维护的实例不因失联自动开放。管理记录缺失或损坏时停止控制操作，通过独立维护入口核对恢复，不扫描端口后自动认领。观察须绑定环境及本次运行，附时间；过期或失联显示未知，旧实例的迟到结果不能覆盖新实例状态。

## 4. 开发任务、创建、交接与清理

### 4.1 任务和人员分工

每个独立开发任务明确目标、负责人、起点版本、修改范围、依赖和检查要求，并分配独立工作区、环境及数据。用户决定任务、生产发布和清理；外部Agent开发并交付，指定集成负责人可以是Agent，负责组合验证；系统执行已授权的受控操作并提供事实。

用户或负责人登记使用者，系统生成工作区、环境入口、基线、允许动作和限制等使用说明，不负责自动拉起外部Agent。普通开发在任务授权范围内推进，不逐次询问；任务授权不自动授予真实模型调用、生产发布或清理权限。

同一任务交接保留身份、工作区及未提交成果；负责人确认原Agent已经停止写入后转交，无法确认时不完成交接。系统只登记一个当前写入负责人并约束管理入口的冲突操作，不声称能阻断同权限外部程序直接写文件。新任务不自动继承旧数据或未完成命令。

### 4.2 按用途创建

创建环境是完整准备流程：确定用途、固定基线和要求能力 → 检查宿主前提与资源冲突 → 准备工作区或固定包、配置和依赖 → 显式准备新数据 → 核验 → 标记准备完成。启动是独立操作。

开发和集成准备可编辑工作区及开发依赖；候选验证与全新生产准备固定包及运行依赖，不要求开发工作区。数据来自显式空库初始化或明确隔离夹具，不自动复制生产库。夹具不得携带生产凭据、真实交付目标或待执行外部意图，环境及数据身份独立登记。依赖按锁定版本和明确来源准备，缺失时明确阻塞，不搜索个人环境或采用latest。安装宿主组件是前置准备，不随每次创建重复执行。

准备失败或中断保留原操作、已创建资源及失败位置；核对后继续尚未执行部分，不能重复初始化。放弃创建的残留仍按明确范围清理。要求的能力未准备好时，不把部分完成显示为全部成功。

创建、更新与接入已有实例分开。更新保留持久数据，仅通过明确维护改变结构；接入先核对版本、协议、进程、配置及数据归属，不能因登记就覆盖或初始化。旧实例不兼容时明确未接入，不能借更新接口绕过前置要求。

### 4.3 并行开发与集成

固定基线 → 分配环境 → 各任务实现和检查 → 交付准确版本、变更及未覆盖事项 → 负责人串行集成 → 验证组合代码 → 构建固定候选 → 候选验证 → 准备生产发布。

同宿主可使用独立worktree，每个任务使用自己的分支及工作区，不强制让多个工作区共用同一可变分支；跨宿主的仓库副本交换留到相应阶段。公共仓库配置和维护由协调者负责，不允许各任务自行清理其他工作区或重写其他分支。HTTP契约、Schema、公共组件、依赖锁和固定资源指定协调责任；各任务保存进度，集成记录由单一负责人汇总。

负责人执行合并与冲突处理，系统记录交付和验证来源，不自动解决冲突、不把人工声明伪装成自动验证。交付版本必须可独立取得，不能只指向待删除工作区的未提交文件；固定候选以准确提交和列明的外部固定资源构建，不自动提交或发布当前脏工作区。

集成目标或任务成果变化后重核依赖及受影响检查；分支各自通过不等于组合通过。任务数据库不合并，环境只承接代码和固定交付物，不承接其他任务的模型许可。清理前保证仍被采用的提交、包及验证依据不依赖被删除目录。

### 4.4 停止与分项清理

停止运行、移除活动环境登记、删除工作区、删除数据分别操作，不相互隐含。停止运行指所属应用及受管活动，不代表终止外部Agent或编辑器；应用停止后仍可继续在任务范围内编辑源码，交接和删除工作区才须确认外部Agent停写。任务结束先保留成果，不因Agent退出、空闲或心跳过期自动清理。

清理前展示具体资源、影响和未提交／未交付成果，由用户确认。执行前重新核对实际文件身份、归属、占用及确认后的变化；仍有活动、结果未知或目标变化时阻止删除。外部Agent停止由负责人确认，受管进程与业务活动还需实际核对。生产停止和清理前的收尾遵守第7章，不用删除按钮绕过维护。

不联动删除共享仓库、其他环境、已发布包和独立保存的交付依据。移除登记只退出活动管理，不遗忘审计和未决操作；仍在运行或有未决操作时不可移除。部分清理失败逐项保留结果，仅继续尚未完成的明确目标，不重新递归删除整个父目录。

清理后保留任务归属、交付版本、清理范围与结果，已删除资源显示不可用，不继续提供启动。重新使用保留目录需显式核对登记，不自动覆盖旧归属或将新任务冒充原任务。

## 5. 隔离、身份与资源边界

### 5.1 文件、配置和运行资源

每个环境显式选择程序、配置、数据、日志、运行及临时根目录，路径在目标宿主解析，可以使用明确的目标绝对路径，但不能在源码或可交付包中写死用户本机目录。校验真实路径身份、父子包含关系和别名；可写依赖、缓存、数据库及运行记录不跨环境共用。固定只读资源只有在原契约允许并核验后共享，共享安装包不等于共享可变执行目录。非生产的Git交付目标、浏览器检查目标、网络端点和其他会产生写入的外部资源也必须明确隔离；仅隔离数据库而继续指向生产目标不算完成。

配置逐环境解析并固定到本次运行，不借修改管理进程的全局环境变量串行启动不同实例；不隐式继承父进程或其他工作区的生产密钥。运行中配置变更形成新的期望版本，必须显示尚未生效，不能自动换绑在途任务。普通重启、配置更新及部署按兼容性和维护规则处理。开发环境可在任务范围内更新源码或使用原有热更新，但要区分启动来源、当前工作区修改和已验证版本，不能把最新HEAD当作进程已经加载的版本；固定包的运行版本以实际包身份为准。

Guard等宿主组件必须按实际安装身份、受信程序和私有根核对。未经验证不能让不同环境共用可变运行记录或切换共享组件以服务开发，从而影响生产。可变开发源码不自动获得固定生产程序的执行资格；验证修改后的内部编程／测试路径时，应构建固定候选，在匹配准入的隔离验证环境检查，不能为开发方便放宽原受信程序要求。缺少可并行的受管执行条件时仅限制相应能力，按第1.2节判断是否阻止交付。

所有控制依据实际进程归属及运行身份，不按进程名批量停止。端口冲突明确失败，不静默漂移；其他程序占用时只报告，不自动结束对方。启动前完成环境、路径和能力准入，再进入受约束的业务恢复。只读观察使用专用元数据／宿主检查入口，不实例化业务应用或后台工作器，不在被观察环境中自动建目录、初始化库、安装组件或触发模型；管理自身可保存必要观察元数据。

### 5.2 前后端绑定与浏览器状态

环境入口的预期身份来自明确部署配置或管理入口，不能把任意API返回值直接当作期望值完成握手。固定前端包通过运行时公开配置绑定目标，不因候选转生产而重新构建前端；公开配置不包含凭据。

握手核对环境、数据代次和协议后，才创建业务请求及恢复上下文。所有业务读取和写入均核对绑定，握手本身只提供必要信息且不触发业务恢复。旧客户端缺少身份时明确拒绝，不默认绑定当前库。新身份、维护和认证错误同步接入前后端解码，明确拒绝与可能已经执行的未知结果分开。

浏览器草稿、命令快照、回执、页面缓存和跨标签消息按环境与数据代次隔离；文档、Coding和Testing存储均纳入，不只修改一处localStorage。切换环境后丢弃旧请求的迟到显示结果，保留其原操作核对入口，不合并到新环境。

原命令在准备时固定环境、代次及请求身份，发送时不能替换成当前界面选择的环境；结果按原作用域查询。原请求已受理时只能核对该次结果，不能因重连、重启或切换生成新键自动重发。旧的无环境绑定记录保留但不自动认领；同一地址换成新环境或恢复旧数据后，不向新库重放旧命令。原规则允许的同键恢复仍须先核对原作用域和执行资格，维护不得放行新的外部意图。恢复数据后原回执缺失或原作用域不可访问时，保留请求并显示无法核实；查不到不代表从未执行，不能换到新代次查询同名ID后重发。

正常版本更新不清草稿；数据代次变化时保留旧草稿并明确来源，不能自动保存到新数据集。浏览器暂存失败、容量不足或版本不兼容时保留可用内容，提示留在页面或导出，不强制刷新或宣称草稿已安全保存。云端全新部署不承担将旧本机草稿搬迁的义务。

### 5.3 权限与真实调用

环境身份用于防误连，不代替认证。管理、业务和内部控制凭据按用途分开；管理控制只接受授权目标及受控动作，不提供任意命令或任意文件路径执行入口。外部Agent需要通过程序入口操作时，使用限于本任务环境及已授权普通动作的访问方式，不取得全局管理凭据；负责人登记本身不自动授予权限，交接时同步撤销原控制资格，不能影响原结果的合规核对。认证和跨来源保护由程序执行，不以隐藏按钮、端口不同或Agent名称代替权限。

浏览器实际发送的会话凭据也必须隔离：开发入口不能收到生产或管理会话，身份握手不替代该保护。Cookie不按端口隔离，不能只用同一主机的不同端口存放敏感会话；具体访问地址、会话方式及跨来源保护由详细设计一并确定和验证，不能仅换Cookie名称。依据：[RFC 6265第8.5节](https://www.rfc-editor.org/rfc/rfc6265.html#section-8.5)。

开发、集成及候选验证默认禁止真实模型和计数；限制覆盖文档AI、内部编程／测试及其实际外发入口。允许调用时仍需原模型准入，明确环境、数据代次、任务范围、次数及预算，许可不能被其他环境继承。正常重启不重置已用额度，也不自行续期或新增许可；原许可是否仍有效按原契约核对，恢复不自动重发调用。恢复旧数据或替换数据集后，旧许可不得因库内记录存在而自动生效，须核对原外发结果和已耗额度，再明确新代次的调用授权；无法核实则保持外发关闭。权限或预算不足明确拒绝，不自动重试付费调用。

同一系统账户下的多工作区属于工作与运行隔离，不承诺防御同权限恶意程序。本期不增加多用户权限平台，但不得因此把所有开发进程都授予管理或生产凭据。

### 5.4 宿主容量与管理故障

受管创建、启动、依赖准备和构建核对磁盘及运行容量，按配置预留并发额度，避免多个请求各自通过检查后共同超额。优先保障生产；不足时阻止新增开发负载，不自动停止生产。外部Agent自行启动的进程遵守协作限制，不冒充系统已强制控制其全部资源。额度依据实际宿主确定并验证。

管理配置、登记、原操作及结果独立持久保存并纳入恢复，不与任务环境一起清理。恢复管理记录必须与真实宿主资源核对，旧备份不能直接重放当年的操作。管理或磁盘异常导致结果无法记录时保持未知并停止冲突动作；不以重新安装空管理程序掩盖原实例归属。

## 6. 可视化管理与用户流程

业务系统提供“环境管理”导航，也允许直接进入独立管理入口。平台已有的日志和基础设施管理界面优先复用；WALL-E负责业务关联、状态摘要及受控操作，不重复建设整套运维控制台。界面跳转与API适配方式随选型确定，任何正常操作入口都遵守本大纲的维护与清理边界。进入管理不切换原业务标签的绑定；打开另一个环境显示明确身份并保留原草稿。用户日常操作不填写协议字段或接触秘密值。

| 页面区域 | 展示及主要操作 |
| --- | --- |
| 总览 | 用途、关联任务、宿主、实际运行状态、版本、最近观察时间；生产明确标识；筛选、刷新和详情 |
| 创建与接入 | 用途、基线、要求能力、资源准备进度；分开新建与已有实例接入，创建完成后独立启动 |
| 环境详情 | 期望／实际配置、准备状态、应用状态、能力和外发限制；显示未生效、未验证、失败、失联的具体原因 |
| 任务与集成 | 使用说明、当前负责人、交接确认、成果版本、组合版本及验证依据；区分人工登记与系统观察 |
| 运维与发布 | 操作目标、影响、前置条件、固定候选、恢复方案、确认是否有效、进度和结果查询 |
| 清理 | 分项列出待删资源、占用、未交付内容及结果；确认范围变化后重新核对 |
| 云端验证／接入 | 目标平台、能力验证、新数据准备及入口启用；按选型后的实际阶段提供 |

页面区分加载、成功空数据、正常内容、筛选无匹配、无权限、明确失败、维护、未知及恢复；成功空态复用公共EmptyState，不能用空态覆盖错误。禁用动作说明具体原因；已有操作即使暂时失去执行权限，也应在原查看权限内保留结果查询。

关闭页面或请求断开不等于取消操作；处理中防重复提交，未知时查询原结果。状态不能只用一个“正常”掩盖运行未就绪或能力未验证。管理只展示必要元数据，使用说明可提供操作者需要的工作区和入口，不返回秘密或无关业务正文。

阶段一先展示真实只读事实，阶段二接入实际控制；不提前放空接口按钮或演示成功。管理端口不可达时如实显示失联，不把最后观察当当前状态。业务停机时，已取得有效维护状态的页面显示维护；没有依据的连接失败显示状态未知，并提供已知管理入口，不猜测正在更新。新打开的业务网址不保证能在服务停机时加载页面，操作进度从独立管理入口查看；宿主整体故障时该入口也可能不可用。

## 7. 固定发布、维护与恢复

### 7.1 发布依据与确认

从明确提交和列明的固定外部资源构建匹配目标平台的包，构建不覆盖任何正在运行的程序或前端资源。候选验证与生产晋升使用同一包摘要；生产程序与持久数据分离，不依赖活动工作区、可变开发依赖或开发服务器。构建产物不夹带生产数据库、凭据、管理秘密或未声明的工作区文件。包摘要一致不自动继承目标宿主的程序信任、文件身份或执行准入，安装到目标后的绑定仍须重新核对。

发布计划关联候选包、资源与配置版本、目标环境、当前部署、数据兼容条件、验证结果和恢复方式。开发、验证与生产的配置可不同，但差异必须明确检查；包、运行时公开配置及私有凭据分别管理，不通过重新打包掩盖差异。

用户确认绑定具体目标和计划，候选、配置、目标、基线或恢复范围改变后重新核对并确认。正常收尾产生的数据写入属于计划允许的准备过程，不拿过期数据快照执行升级；凡维护工具依赖准确源数据，必须在停写后以实际源重新核对或演练，并在计划变化时重新确认。

旧检查结果不能证明新候选通过；执行前再次核对实际条件和确认有效性。程序、管理协议、Schema或资源不兼容时阻止切换，不能以页面可打开作为全部就绪。

### 7.2 维护进入与任务收尾

生产停止、重启、更新及清理前收尾使用同一规则。普通非生产停止同样核对所属活动，不因开发环境而丢弃未保存事实；放弃任务或删除数据另按明确决定处理。不能直接利用现有关闭宽限期到期来代替主动维护中的收尾。

1. 在目标实例持久记录维护状态，关闭新业务写入和新执行准入，包括HTTP、后台队列及其他程序入口。记录维护与关闭准入要有可核对的一致顺序；实例尚未确认准入关闭时，只能显示进入中或结果未知，不能仅凭管理记录宣称已进入维护。进入维护与收尾停写完成分别表达；已接受请求明确归入待收尾集合。已受理但尚未派发的意图保留原记录，只有原契约支持可核对的安全挂起时才挂起，否则阻止切换并由用户选择取消维护或明确取消任务；不能自动删除、假定未执行或在维护中派发新工作。
2. 维护前已开始的原业务操作可以在原输入、原授权和原预算内完成必要内部步骤与落盘，不把其内部步骤一律当作新任务。保留查询、明确取消和原结果核对；对该操作的问题答复，只有原契约明确支持、不扩大范围且能绑定原操作时才允许。新任务、新人工执行轮次、独立复测、追加预算或扩大权限不属于收尾；无法判定时保持等待，由用户取消维护后继续或明确取消任务。
3. 按活动进程、在途请求、后台步骤、子进程和写入判断是否安静，不要求所有业务任务都变成完成状态。无活动、无可能继续改变业务内容或外部目标的未决意图、状态已保存且新版本兼容的等待任务可保留；更新不自动续跑。仅有原契约允许的迟到费用或观察记录，且执行权已封闭、资源已停止时，可保留待核对状态；这不能替代未知Git交付、未知模型结果处置或子进程停止的证明。
4. 失联、超时或取消结果不明时保留阻塞；不把业务状态终止、端口消失或主进程退出当完整停止证据。用户可继续等待、取消本次维护或明确取消任务，系统不自行强制终止。
5. 收尾完成后关闭剩余写入者并核对实际停止；需要后续数据维护时再取得维护权、准备恢复点并执行维护。普通停止以所属活动确实停止为结果，不隐含构建、全量备份或数据变更。HTTP停止与后台停写分别核对，旧实例不能与新实例同时写同一数据。

允许的收尾动作由后端详细设计按真实调用路径、原操作归属和权限列明，不能仅按HTTP读写方法一刀切；管理只读取必要结论，不直接修改任务状态。维护中的普通查看仅放行无新增执行和持久副作用的读取；会启动受管查询或写入私有记录的GET不得自动放行，应展示已有元数据或说明暂不可查看。原结果核对所需写入只能经明确收尾入口完成，并重新计入停写核验。取消请求不等于撤回已经保存的结果，不承诺退回已产生的模型费用。

### 7.3 切换、取消与重新开放

程序／配置发布和恢复需要受控切换，普通无变更重启不要求重新构建候选包。候选构建、组合验证和恢复方案准备尽量在进入维护前完成；最终一致性备份及依赖原数据的维护核验在收尾停写后完成。新实例先以维护状态启动，环境校验先于业务恢复；仅进行必要核对和恢复落盘，不接收新业务或重复外部调用。检查目标程序、数据、协议及要求能力正常后，记录切换结果并解除维护；普通停止保持停止。生产就绪核对使用身份、版本和必要只读健康信息，不自动创建测试业务、修改正文或发起真实模型调用；完整功能检查在隔离环境完成。

从已停止环境正常启动时，先核对停止原因和未决操作；普通停止且无阻塞的实例可按本次启动授权，在核验后开放。更新失败或原操作未知留下的维护不能借普通启动清除，仍须先核对恢复。

切换前取消维护，核对原实例、版本、数据及未决操作后才解除限制。切换已开始、数据已改变或结果未知时，不能简单标记取消成功；先完成原结果核对及必要恢复，再决定开放。管理崩溃、机器重启、弹窗关闭和等待超时均不自动解除维护；直接启动同一受管实例也必须读取维护状态。

维护准备期间可查看已有内容，禁止普通编辑保存但保留草稿；切换期间业务页面可暂时不可用，由独立管理入口展示进度。恢复后重新核对环境、数据代次、内容版本和权限，再由用户保存；冲突明确提示，不自动覆盖新内容或重发旧请求。

### 7.4 恢复点与回退

回退以数据兼容和真实写入为依据，不承诺一键处理所有情况：

| 时点或变化 | 处理原则 |
| --- | --- |
| 仅程序变化且旧程序兼容当前数据／资源 | 维护中切回固定旧包和匹配配置，核验后开放 |
| 涉及不兼容数据变更 | 发布前必须有实际演练通过、匹配源版本及资产范围的恢复方案，否则阻止发布；不得临时降级或重跑未知升级 |
| 新实例尚未开放普通业务写入 | 仍需计入启动恢复产生的真实写入，确认方案适用后恢复，不能默认数据未变 |
| 新实例已经开放且有新业务内容 | 不直接用旧备份覆盖；保留现有数据并重新制定不丢内容的处理方案，必要时保持维护等待处理 |

恢复点必须覆盖数据一致性所需的数据库、日志／审计、被引用的库外资产以及程序与配置关联，不能只复制一个正在使用的SQLite文件。沿用现有锁、备份、演练和原结果核对机制；若所选能力存在未覆盖资产或工具不支持恢复，明确阻断对应发布，不虚构通用恢复能力。

备份和回执是正常恢复资产，保存于不会随任务清理而删除的位置，不自动当临时垃圾回收。恢复旧快照或替换数据集时更新数据代次并核对目标文件身份；数据恢复、代次和配置绑定均核对持久结果后才能开放，任一步未知则保持维护。防止旧标签和命令写入恢复后的数据，正常保留数据的程序回退不无故更换代次。

### 7.5 云端全新部署

上云不迁移旧业务库、文档版本、对话、任务历史和成果、旧草稿或未决命令，不建设旧资产搬迁或历史任务接续能力。仍需程序、固定业务资源、目标凭据和访问保护，通过显式初始化建立新环境及新数据代次。

云端新数据仍正常持久保存、备份和恢复。实际启用时安排旧系统受控停用和新入口切换，旧本机数据是否删除另行明确。SQLite按单应用写入者及受验证存储运行，不默认共享网络盘或多副本写入。云平台、认证方式、存储、恢复目标和运维责任在第0章选型及对应部署设计中确定，不能留到上线后补充。

## 8. 分期、验收与交付判定

### 8.1 分期

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 零：平台选型与云验证准备 | Windows影响、开源能力、路线比较和最小验证方案 | 完成第0章选择依据与验证门槛；明确实际验证授权、费用及范围后执行，定案前不默认扩大自研后台 |
| 一：基础隔离与只读管理 | 宿主准备、明确配置、身份与数据隔离、固定构建、独立只读管理 | 在选定拓扑下两开发＋集成＋候选验证隔离成立；以显式准备工具建立环境，管理界面不提前执行控制动作 |
| 二：完整管理与发布 | 可视化创建、启停、接入、人工交接、集成展示、分项清理及发布恢复 | 第1.2节最低能力和本章闭环场景实际通过；不能仅以脚本可用代替界面接入 |
| 选型后确定批次：云端新部署 | 目标平台、复用管理能力、访问保护、新数据及恢复和启用 | 云验证在前置议题推进，正式接入批次及验收范围明确后执行，不默认沿用先本机后云端的顺序 |

功能验收在隔离的生产角色实例上真实验证，不操作用户正常业务数据。用户当前生产实例接入是单独部署步骤，需要现场基线和实际授权；未接入时明确“功能已验证、当前生产未接入”，不能宣称用户服务已经切换。设计完成、实现完成、验证通过、实际接入分别判定。

### 8.2 闭环验收场景

| 场景 | 必须得到的证据 |
| --- | --- |
| 首次安装与独立入口 | 业务未启动仍可登录管理；管理重启保留登记及操作；普通创建不重复安装系统组件 |
| 按用途准备 | 开发可编辑构建；候选和生产使用固定包；应用使用隔离数据实际完成文档读取、人工编辑和保存；缺少声明能力显示阻塞；创建完成与启动分开 |
| 新建与接入防错 | 新建不覆盖旧库，接入不触发初始化；不兼容旧实例明确未接入；同路径别名和重叠目录被拒绝 |
| 两任务并行 | 代码、依赖、数据、浏览器及运行资源不串用，构建不覆盖生产；源码修改不被误报为已验证运行版本；内部能力用匹配的固定候选与准入检查，不复用生产执行资格 |
| 任务交接 | 保留未提交成果，未确认原Agent停止不交接；旧控制资格不能继续操作新归属，受限入口不能操作其他环境；登记不被展示为系统级强制独占 |
| 组合版本交付 | 两任务准确版本可取得，组合检查形成固定候选；人工声明、离线检查和实际结果有明确来源 |
| 前后端误配与会话隔离 | 错误代理、旧客户端、同端口换环境均不能读写错误数据；握手失败不触发业务恢复；开发入口收不到管理或生产凭据，不以不同端口证明会话隔离 |
| 草稿及原命令 | 文档、Coding、Testing存储均分区；准备后切换环境不改原请求目标；旧代次、迟到响应和无绑定旧记录不进入新环境，暂存失败不丢可用输入 |
| 外发与外部目标 | 所有实际模型和计数入口受限；复制环境或换角色不继承许可；重启不重置额度，恢复旧数据不复活旧许可；固定包晋升不携带任务／验证数据；非生产Git交付及浏览器检查不写入生产目标 |
| 并发管理与资源争抢 | 第二个管理写入者不能接管原资源；同环境冲突动作及跨环境路径／端口竞争被拒绝；资源预留不超额，失败后不误释放未知占用 |
| 中断与取消 | 创建、启动或清理中断后核对原结果，不重复副作用；部分成功如实保留，查询和取消不被长操作堵死 |
| 管理失联与记录恢复 | 正常业务不被误停；维护不自动解除；旧观察不覆盖新运行，登记丢失不自动认领资源 |
| 维护收尾 | 进入中、已进入和收尾完成分别核实；新入口与后台均不接新业务意图，原操作必要步骤可完成；未派发意图不丢失或擅自派发；等待输入有处理或退出出口；有副作用的GET不绕过限制，进程及停写可核实 |
| 发布确认失效 | 候选、配置、目标或计划变化使原确认失效；收尾后的数据重新核验，不使用过期快照升级；相同包在目标侧仍核对程序与宿主准入 |
| 发布切换与停止重启 | 隔离生产实例实际完成发布、停止和重启；普通停止不附带构建或删除，外部Agent不被误停；只有新实例可写，维护跨重启有效，普通启动不能绕过更新失败的阻塞，状态与实际程序匹配 |
| 取消发布及更新失败 | 切换前可经核对解除维护；切换后或结果未知保持阻塞并恢复；不重复模型调用或隐式撤回已保存事实 |
| 回退与备份 | 兼容回退实际通过；无恢复方案的不兼容发布被拒绝；已产生新内容时不以旧备份覆盖现有数据；数据及代次任一步未知不开放，原回执缺失不被当作未执行；资产缺失明确阻断 |
| 分项清理 | 目标变化、占用或未决结果时拒绝；只删除确认范围，保留共享仓库、已发布包、独立交付依据和清理记录 |
| 页面状态 | 加载、空态、筛选、无权限、失败、维护、未知、部分完成及恢复可区分，按钮与实际可用动作一致 |

以上是待执行的验收要求，不是本轮验证结果。静态检查、专项、集成、浏览器和实际平台证据分别记录；Mock、离线通过或历史记录不替代真实受管执行与供应方证据。真实模型及计数检查另定次数、预算和重试边界，不因验收目标自动获得许可。

## 9. 后续前后端设计职责

### 9.1 两份独立迭代设计

| 文档 | 负责范围 |
| --- | --- |
| 后端迭代设计 | 共同对象与业务规则、配置／身份、资源归属、权限与外发限制、操作持久化及互斥、按用途准备、维护收尾、发布与恢复、HTTP契约和共享验收 |
| 前端迭代设计 | 独立入口、页面组件、任务与集成展示、身份握手、浏览器分区、操作确认和状态、维护与草稿恢复、前端验收；引用后端共同契约 |

两份文档保留在本版本pending目录，不自动合入正式设计。编制时结合真实源码和所选基线区分复用、修改、新增；不恢复已删除的旧技术草案，不创建第三份共同规格。

### 9.2 必须展开的实现契约

后端需确定最小配置与身份结构、受控入口及调用方、动作前置条件、允许的收尾动作、旧操作结果读取、不可重复副作用的恢复方式、备份及数据代次规则、资源预留和宿主组件归属；核对普通入口、固定包入口、后台工作线程和维护工具，不能只改HTTP层。

前端需确定运行时绑定来源、严格错误解码、全部存储接入位置、迟到结果处理、部分成功及未知状态、维护前后的草稿与权限核对；与后端共同确定访问地址和浏览器会话隔离方式。共同确认管理与业务的兼容版本及首次接入顺序，保证新协议启用前旧入口不会默认为通过。

准确平台及工具分工先由第0章收口；两份详细设计按选定方案展开，并明确第三方能力、适配和自研边界。认证、管理恢复和资源保护不能因采用现成平台而省略。具体字段、路由、状态编码、目录格式和额度在详细设计展开，不改变本文的交付与数据边界。
