# WALL-E 工作台返回位置恢复修正

日期：2026-11-02；编号M15-RETURN-01；目标V1.5；状态：按用户后续纠正完成直接导航及所列检查、待合并。

## 来源与范围

用户反馈5173的/requirements/1页面点击“工作台”不能返回。依据正式FE 1.0 EFFECTIVE的BND-WORKBENCH／BND-DETAIL离开保护与INF-BROWSER；复用V1.0既有history entry恢复约定。正式FE／BE摘要分别为b294153e11ef764f36f92b7390dc817c6ed079a81734c770ebe6f217601e2920／36d2e28630b5099a30253e5a5881492c8fc50c3cffaf4d9d4a88341bdc24defd。

本轮修正返回故障，执行必要离线路由／离开保护专项、strict类型／格式及现有5173只读模块和独立浏览器检查。不改正常正文／业务数据，不触发模型／计数，不启停服务、提交推送或自动合入正式设计。前轮固定当前文档及其他工作区变更保留。

## 复现与原因

正常从工作台进入详情再返回成功。离线已复现：工作台进入详情→sessionStorage不可用或返回位置记录丢失→详情刷新→点击返回；constructor只读辅助position键，没有使用history.state内已经严格校验的DetailEntry.position，当前位置错误回落0。返回计算得到history.go(0)，路由不离开；DetailDeparture已进入LEAVING，后续请求被保护拦住。原标签页未取得内部状态，不宣称此条件是用户现场唯一原因。

## 用户后续纠正与最终规则

用户随后反馈按钮退出应用、回到浏览器主页，并明确“直接返回到前端页面的工作台列表”。前轮修正仍用持久position差值执行history.go；校验历史对象字段只能确认格式，不能证明浏览器当前栈内的目标页面。旧检查缺少“保存的来源记录存在、实际前序已不是工作台”的边界，不能据前轮通过宣称现场修复。

1. “工作台”按钮仅在当前应用内直接切换到/requirements默认列表，采用replaceState更新当前地址和原apply载入列表；不调用history.go／back，不计算来源步数，不触碰外部页面。
2. 明确返回工作台与浏览器原生Back分开：按钮使用默认查询／第一页／顶部；原生Back的实际历史恢复及其查询保留仍沿原规则。此条替代原本按钮按from恢复查询和滚动的规则，不为该按钮新增位置机制。
3. 现有DetailDeparture先保存再离开；失败仍显示原警告，取消继续编辑，明确离开才进入列表。不重复请求保护，不修改业务数据或触发模型。
4. 输入只有已通过离开保护的按钮动作；输出为实际WORKBENCH路由和列表读取。来源缺失、过期、栈不对应或直接打开详情均不影响按钮结果。原正式设计保持，合并另需明确要求。
