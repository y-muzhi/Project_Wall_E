# WALL-E V2.2 按原固定操作重新开放

2026-11-21。实施细化，对应 V2.01 后端 4.11、7.10。固定发布的 OPEN 必须来自同一已确认操作。在新版独立进程和实际网关核验后，由固定发布启动入口重新取得原稳定锁并做准入。

- 新安装、原操作、新 run ID、确切前后记录和实际关闭控制、两份核验原回执及摘要由受保护规则一并确认。网关在最近 120 秒内核验，同一宿主启动标识、进程启动时刻和正在占用本机入口的 TCP inode 必须仍在。任一证据变化保持关闭。入口证明过期、原进程消失、监听读取失败或实物对不上时，返回 `RELEASE_OPEN_UNVERIFIED` 并保留原控制。按新观察核对实际网关后，使用新的原运行凭据重试。
- 开放前由原稳定锁保护，首次连接 SQLite 前发现 `-wal`、`-shm` 或 `-journal` 就返回 `RELEASE_OPEN_UNVERIFIED`，保持原数据库、边文件、关闭控制和回执原状。实际 Schema、原数据库身份和逻辑内容复核通过后，仅执行普通环境既有必要的接续恢复。普通 HTTP 及派发继续闭锁。持同一锁先发布原 open 回执，再将当前选中元组原子置为 OPEN，重读后才开放应用准入。
- 已 OPEN 时不得重新执行切换。已保存回执且控制仍关闭，只表示原步骤中断；重试仍须原证据、新鲜入口及当前实际数据单独成立。历史部署开放证据留在前后记录，普通 STOP 保留新版已开放事实。实际生产更新和末尾管理登记另受既定流程约束。
