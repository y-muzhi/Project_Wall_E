# WALL-E V2.2 普通环境配置切换

依据 V2.01 后端 4.10、4.11、6.6、7.10、8.2 与前端 5.9。当前普通能力已使用受保护访问策略并固定原程序。R170 补齐同程序的配置变更，在已有固定包上创建独立部署，继续沿原维护、备份、关闭切换和开放证据。首个受管配置是现有业务访问策略的身份和权限列表。

- 必须保持环境 ID、用途、固定程序／前端、Schema、运行包、数据代次、数据根、稳定锁、公开来源及 Unix 上游。只采用明确 pin 的新访问策略，原部署字节保留。已验证的原普通读写能力仍须能够用 WEB 业务身份核对。
- 常规发布、代码回退及数据恢复继续使用当前已采用的访问策略。在原访问策略与仓库目录不一致、原程序不明、恢复或开放未完成时停在关闭状态。程序还原和数据迁移仍用它们自己的意图。
- R171 管理确认和原键复用固定发布的事务、关闭、开放、登记和旧操作核对。管理页只展示已登记的配置。旧登记 Schema 保持，新换代见 Schema 7。配置不授予模型或执行。
- R172 每次业务访问从当前安装 pin 核对访问策略。缺文件或实际字节与安装不符时返回受控未就绪，策略只能在已确认部署切换后生效。普通与恢复期沿同一保护读取。验证旧身份失效、新身份访问，数据和部署读回。
- R173 允许受信宿主明确撤回已关闭、尚未尝试切换的原发布、回退或配置操作。先持久记录原撤回意图，选择工具拒绝继续。宿主必须确认没有已写切换事实并重新核对稳定停止。原环境回到正常停止，由独立启动意图开放。命令中断后只核对原撤回，与在途或未知切换分开阻断。管理原键据保护回执补记取消。
- R174 接续管理库恢复。只有原步骤无派发、无选择、无开放及无遗留占用，且撤回意图、低层回执、原计划和配置可互证时，才能在新登记代次补记切换前撤回。有此证据的原历史可用于停写后的正式归档判定。保留原操作与历史验证结构。
