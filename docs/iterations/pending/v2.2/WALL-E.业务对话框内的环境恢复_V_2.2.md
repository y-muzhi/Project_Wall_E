# WALL-E V2.2 业务对话框内的环境恢复

依据 V2.01 前端第 7 章及 TC201-FE-05、06、09。需求和文档新建沿用浏览器模态对话框。在环境失联或写入结果未知时，原输入和原请求须留在当前对话框，同时要能到达实际的环境核对入口。浏览器会将模态框外的页面设为不可交互，页级连接提示无法在此时操作。

沿用 Application 的环境状态、提示和已有恢复动作，当前顶层新建需求或文档对话框接管连接提示时，暂停页面上的同名提示，避免用户或辅助工具选中模态窗后的无效入口。关闭模态窗后页级提示按当前状态恢复。同作用域恢复就绪后，用户显式核实原请求。连接核对本身只读，不重新发出写入。若作用域已换代，沿已有保护入口保留原内容并可另开新标签，当前对话框不向新代次提交。

验证以真实 HTTPS 页面开始，首次后端实际返回创建成功，在浏览器网络层丢弃回执。检查用户能否在对话框内核对连接，之后只提交原请求，并返回原结果。输入、命令键与作用域的现有判断继续适用。

## 数据代次变化时的未决文档操作

依 V2.01 前端 4.4 和 TC201-FE-06，当前页冻结时，原文档目录命令处于提交中或结果未知应计入原待确认数量。用当前需求的既有命令拥有者读取状态，已确认但仅待读回详情的操作不计为未知。该核对只读原页面状态，不向新数据库查询或重发旧命令。
