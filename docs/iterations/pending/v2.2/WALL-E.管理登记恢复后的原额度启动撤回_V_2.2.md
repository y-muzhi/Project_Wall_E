# WALL-E V2.2 管理登记恢复后的原额度启动撤回

依据 V2.01 后端 3.5、4.6、4.12.3、7.9。补齐原 START 已正式受理且保留了固定运行额度、实际还未派发时的管理登记恢复。

- 必须具备同次暂停的原快照，归属相同的环境、代次、配置、原意图、原修订与唯一 PLANNED 步骤。原保留额度须为完整的四项，绑定该环境、原配置、固定原策略和原 profile。原维护观察目录必须可证实存在，且无已派发启动、准备、运行登记或运行占用。原环境须归属同一宿主。缺少原证据保持暂停。
- 新登记在同一 SQLite 事务写入独立结束记录，并释放原快照与当前库均完全一致的四项额度。原请求、原操作和原步骤保持只读。提交后重复执行只验证并读出原处置和释放回执；其他额度不受影响。
- 派发复核只结束有相符处置的原已受理 START。仍须核对原环境及其他资源，避免把登记变更当作原宿主已经退出。
- 普通等待容量状态继续用此前受信未派发处置；已允许派发、具有宿主记录或占用不完整继续走原流程。

R136 完成 Windows 隔离验证，见 [R136](../../../verification/v2.2/local-registry-reserved-start-r136-2026-11-22.md)。原生验证使用独立目录、原宿主权限和固定依赖。
