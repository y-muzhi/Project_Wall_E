# WALL-E V2.2 登记恢复核对已完成的发布与恢复运行

依据 V2.01 后端 4.11、4.12.2、4.12.3 和 7.9。原 RELEASE 或 RESTORE 已完成原登记结算时，换代期间仍须核对其宿主单元。实际开放请求保存环境、运行、部署、数据及策略，但登记代次在同一步骤的原维护授权中。

- R140 分别使用原维护授权及开放请求各自保存的字段，交叉校验操作、登记代次、环境、部署、数据代次及配置。已完成步骤核对保存的开放结果。固定来源不全时保持待核对。有原开放请求时只观察原操作单位；无原开放请求的旧步骤维持各自已有核对和处置。
- R141 若历史发布或恢复的单元仍有进程，须证明它是该环境当前登记的运行，核对该单元的进程、运行键及部署绑定。其他运行即便健康，也不能代替历史单元核对。原单元确证已消失或停止时，仍须分别通过当前环境和其他资源的核对。

保留封存清册、原历史和暂停门槛。只在隔离环境中实施验证，区分真实 SQLite、宿主观测适配和原生 Linux 结果。
