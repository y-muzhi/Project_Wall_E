# WALL-E V2.2 登记换代核对已开放待结算部署

依据 V2.01 后端 4.10、4.11、4.12.2、4.12.3、7.9。原 RELEASE／RESTORE 在写入受保护开放凭证后，管理事务可能尚未登记新部署。恢复登记保留原封存登记、原维护步骤、目标实际控制以及原运行占用。

- R148 在固定的登记换代核对中，从同一原步骤的维护授权、开放请求、已经选择的目标和受保护开放凭证识别目标。分别核对原登记的源绑定、目标活动或正常停止、宿主资源身份和原受管进程；区分未形成开放请求、开放未证实、曾开放但当前运行未核实、当前仍为同一运行、原运行已正常停止。
- 核对清册保留两侧记录，原步骤仍按已有规则阻止派发。诊断输出只给原操作、环境数据代次、部署、运行键、已核实状态及有限凭证摘要。
- R149 复用普通发布与恢复登记的记录校验，核对可重现的目标登记更新及保留额度，按原计划、原登记行版本、目标安装和可验证的运行／停止证据固化拟处置的依据。确认更新前须另核目标管理代次能管理该安装、现用与保留资源一致，以及恢复后 STOP／START 的真实控制入口。
- R150 受信宿主可显式为已认出的原开放运行执行原温和 STOP。在当前所选恢复与原派发暂停受保护的作用域中，停机策略须引用同一原运行策略和运行键，实际受管组由既有 STOP 执行器核对。原已记录派发只能读回同一停止事实。保持新登记暂停、原操作不重放，也不因停机调整原占用。
- R151 在同一宿主暂停内核对已停止的原运行和正式停止回执，并验证受信所选管理入口的目录可解析同一目标安装及对应运行容量策略，业务入口必须精确绑定目标数据、部署和配置。独立可重读的核对给出后续采用所需的新旧凭证摘要；跨代次普通重启许可由后续单元处理。
- R152 从同一选择、清册与暂停锁现场重新计算 R151，核对受信管理员提供的 R149 评估摘要、R151 核对摘要和原操作。通过后在所选管理代次发布只读凭证，绑定原操作、精确停止和候选接管入口。相同依据允许读回原凭证，原操作已有授权时拒绝另一个依据。后续事务须重新核对原登记投影、实际目标、暂停及此凭证，才可写入归属。
- R153 在已选择的 Schema 5 登记库接入固定采用事务。原封存库及原操作／原步骤保持字节和状态，新库独立记录采用结果。目标登记、原运行额度释放及采用结论须在同一 SQLite 事务中提交，并以固定文件读回；若事务后凭证发布结果缺失，重复验证原目标记录和额度，仅补齐凭证。目标与原数据路径声明保持，派发继续暂停。下一批负责在原清册上纳入采用后实测及跨代次普通启动。
- R154 普通启动仅在派发已按原固定门槛开放时可接受跨代次的停止前置依据。启动策略显式引用该次采用和登记结算摘要，按所选入口和封存来源核对，再持环境稳定锁核对同一停止后的控制、业务库对象和原运行组。只有尚无新代次启动租约的环境可首次采用该依据，既有同一启动的重试继续按现有租约。
- R155 派发复核仍读原封存清册及原观察。对已采用项，独立核对所选授权、原开放／停止、当前目标安装与所有原声明。仅对该项使用实测目标状态复核原声明，保留目标容器和稳定资源身份。原步骤待结算状态由已验证采用结果收口，其他环境、声明、操作和单元仍按原门槛。
- R156 以原快照、精确采用和当前核对批准固定重新开放，归档原暂停凭证后沿真实普通应用生命周期重启和读回。Windows 可替代原生宿主观察进行独立流程验证；ARM64 原生验证与生产接入独立记录。
