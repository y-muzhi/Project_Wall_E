# WALL-E V2.2 关闭控制下的固定部署选择

2026-11-21。实施细化，对应 V2.01 后端 4.10、4.11、7.10。使用已完成的备份检查、R26 预检及 R28 同环境装配。单独执行的 `select-release-deployment` 只在原维护身份和稳定锁下工作，需确认预检摘要、确切目标安装锚和原操作。

在持稳定环境锁重新核对原库、计数资产和原关闭事实成功后，取得宿主恢复共享准入锁，在两把锁下再次核对原关闭控制。先排他写入含完整前后元组的 `release-transition-<operation>.v1.json`，再 CAS 更新 `control.v1.json`。宿主冻结或正在切换恢复控制时，两个写入都不开始。发布、代码回退、重配与数据恢复复用此写入顺序。新控制继续 CLOSED、RECOVERY_REQUIRED、外发冻结和原维护归属。沿用稳定锁、原数据根、数据代次和原历史开放证据。旧安装不能继续使用当前控制，新安装只能核对与受信记录匹配的关闭事实。

如果只保存了选择记录，重新观察原库与同一原意图后可完成；控制已经完成时只重新验读，同一原操作的历史确认在宿主冻结期间也可读回。父目录同步结果不明时依真实元组核对，已有不同记录或控制则阻断，不能回写 OPEN。返回 `RELEASE_DEPLOYMENT_SELECTED_CLOSED` 仅表示持久选择，目标进程和用户公开入口尚需独立核验。
