# WALL-E V2.2 管理登记与交付写入

2026-11-20。本批按 V2.01 后端 4.6、4.7、6.5、7.9 及前端 4.6、5.6—5.8、6.4、7.6 实施。管理 API 在独立 HTTPS 入口接入两个已验证的登记类写入。

- `POST /operations` 仅接 ATTACH、REGISTER_DELIVERY，校验独立管理作用域、当前认证主体、来源、唯一原键、严格 JSON 和 64KiB 上限。复用受信本地入口相同的事务、互斥、目录／提交证据及版本。首次提交完成返回 202 和原操作，已存在同主体同意图返回 200 及原回执。同键不同输入返回 409，不因过时版本、证据过期或已归档而改变既有回执。按键读取只查资料。
- 管理页提交前将固定输入、原键及派发占用落盘于独立 IndexedDB，随后才发送。普通业务状态不参与分区。前端按已核实的管理作用域及主体读取原结果；断线、代理失败、重启、404 和失权保留原键。自动行为限于读取，显式继续仅使用同一固定原请求。
- ATTACH 表单仅选择服务端目录内的候选，候选以已核实的准备事实及当前注册状态解释可用性。登记保留已有安装、配置和数据。REGISTER_DELIVERY 只用明确 commit、已登记证据及未覆盖说明。受信 Git／资源观察由既有宿主入口生成，仍绑定精确原意图和操作者。
- 原页检测到同源管理 ID 或登记代次变化时，立即冻结该作用域的服务器读写，保留已保存的原请求及其本地查看／导出。“重新进入管理页”显式重新装配，进入新作用域后不会沿用或清除旧记录。
- 本批不开启 CREATE、受管启停、交接、清理、发布、维护及恢复动作。这些动作分别依赖其既有实际准入和控制契约。
