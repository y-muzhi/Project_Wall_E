# WALL-E V2.2 受管程序回退接续

依据 V2.01 后端 4.10、4.11、4.12.3、6.6、7.10、8.2，前端 5.9、6.4、8.2。原 R37 的固定程序回退已经能以新部署安装旧固定包，并维持当前数据。管理端现有 RELEASE 链路只接收普通同结构发布，尚无程序回退的受管受理与回执。

- R157 将受信回退配置接入发布源观察。配置须明确装有前一固定程序的原安装引用及对应程序，核对前一直接部署、当前数据兼容、同一环境和稳定锁、当前数据库、目标新安装及独立候选。通过同一固定观察写入已有凭证。
- R158 复用已有 RELEASE 的计划、确认、原键和执行步骤，区分明确确认的 ROLLBACK_CODE 及真正的恢复数据操作。只选择已准入的前一程序，保留受保护恢复点要求，然后沿原停写、回退选择、开放及登记路径执行。
- R159 接入现有管理页面的程序回退选项和计划对照，独立展示当前数据与目标程序，验证原键读回及权限。
- R160 验证原代码回退在登记换代及正常启停时的原结果与容量归属，保持旧登记结构的检查，无法证明的故障修复归属仍暂停。以实际宿主联验单独确认发布和回退。

R161 程序回退沿已验证的相同访问策略保留已登记业务入口。仅在受保护开放和新登记同时成立后，业务入口投影随新部署更新。移除目录授权时入口仍关闭。普通发布的现有开放回执和已批准登记采用摘要继续可核对。

R162 以原受管计划驱动关闭态持久切换。低层控制事实先持久化，再采用目标部署；丢回执时按原事实恢复结果。必须核对错误政策、当前数据字节和外发冻结，区分隔离文件及数据库证据与 Linux 宿主执行。

原设计及现行发布包保留。Windows 环境中的系统身份、锁和进程适配仅用于隔离验证。真实 ARM64 观察和生产接入另行记录。
