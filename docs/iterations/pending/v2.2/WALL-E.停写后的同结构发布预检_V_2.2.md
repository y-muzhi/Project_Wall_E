# WALL-E V2.2 停写后的同结构发布预检

实施条目 R26。依据 V2.01 后端 4.10.3、4.11、4.12、7.10。仅解决原维护关闭窗口内的 SAME_SCHEMA 发布前置核实。

- 固定原维护归属及原捕获调用、独立固定候选检查、目标二进制清单与 Schema、完整备份及该包的本机恢复回执、准确兼容记录。读取实际候选文件并拒绝缺少正式检查的候选。
- 以实际新旧结构契约相等作为同结构条件。兼容记录固定准确程序、运行包、源和候选 Schema 及所要求能力。版本号相同但结构、计划或资源事实不同则停止。
- 在验证候选和备份后，最后按 R12 实际锁和原控制重新读取停写源。必须与所选恢复点的环境、代次、部署、控制修订、原捕获及资产证明相同，维护取消或当前变化要求重新核实。
- 普通停止在请求及工作器排空后、原应用仍持稳定锁时核对数据库归属，由 SQLite 自身完成 WAL 检查点及连接关闭。只有检查点完成、主库身份保持、侧文件已由 SQLite 处理才记录正常关闭。初始化、启动诊断、维护、捕获和记录核对共用稳定锁内的只读打开。原数据库无 WAL、SHM 或回滚日志时使用 immutable，避免复核生成自己的侧文件。若源本来有侧文件，则保留它们并继续支持原只读备份读取。同数据根的发布预检和切换持锁再次要求无侧文件，未核实期间拒绝选择，不删除或跳过已有日志。
- 已启动的应用退出仍须核对 ASGI 实际关闭结果。监听租约和原文件由原清理边界处理。若工作器、数据库检查点或关闭钩子失败，启动器返回失败，持久控制状态继续作为停止是否生效的依据。退出判据及管理服务适用范围见 [固定服务生命周期退出状态](WALL-E.固定服务生命周期退出状态_V_2.2.md)。
- 只返回绑定当前意图的发布前置结果，不改变任何部署选择、数据代次、源库或持久控制状态。切换和实际重新开放须继续依原计划。
