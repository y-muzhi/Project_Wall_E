# WALL-E V2.2 普通启动准备过程的宿主归属

2026-11-21。依据 V2.01 后端 4.6、4.8、7.9。M21 先验证启动准备使用单独的原生受管服务组，准备进程取得应用稳定锁、写原准备回执后须真实退出，才能把普通启动交给应用进程。

- 每个原启动对应独立固定名称的准备单元。派发前落盘原启动、固定命令、宿主开机和目标摘要；由受信 systemd 单元调用固定 setpriv，只在本地启动边界保留 SETUID／SETGID。清除附加组、降为原维护 UID/GID 后运行现有固定启动器的 prepare-start。支持已配置的数字维护身份。
- 受限准备组使用一次性 systemd 服务和正常停止策略，退出后可读取同一 InvocationID、实际结果和进程组。操作回复丢失仅读取已登记作用域，核对已退出的维护组以及未被替换的原准备回执。
- 先持久保存已观察到的原 InvocationID 和准备回执摘要，只在组内无进程且同一准备单元已退出后继续原应用启动。未知或仍有进程的准备组保留容量和原操作，无法确认则不重放。准备阶段的关闭回退仍需独立安全事务。
- 已完成准备但应用尚未派发时，回退需绑定准备前的 CLOSED 控制与原准备控制，以维护身份持稳定锁比较原值和持久结果。首次打开前应恢复准备前的原初始化操作 ID，同时以当前准备版本为基准递增，确保原初始化证据可重取且旧准备凭据失效。其他控制事实按原准备前值校验并保留。实际原型见 [首次准备回退](../../../verification/v2.2/linux-managed-first-preparation-retirement-prototype-2026-11-21.md)，真实开放并关闭过的环境也通过保留原开放回执的反复准备。原管理控制接入仍待实施。
- 待接入的原取消需在派发前保存准备前控制事实，固定准备进程进入稳定锁后才核对该预期和写入。确认原准备组已退出且原应用尚未派发后，控制等于准备前值时保留该值，旧孤立回执继续留痕。控制恰好等于原准备值时执行上述递增回退。控制与两者均不相符、缺少进程组证据或已有应用派发时，保留原额度并继续核对。完成回退才能出具同一控制键的回执并释放原预留。
- 仍处于执行中的准备单元只在核对原启动、开机、InvocationID、固定命令、实际维护身份和整个受管组后，才保存原停止意图并按正常停止策略关闭。同一组无法确认、仍有进程或控制事实出现漂移时保持待核实。后端在原 START 下保留应用步骤未派发、准备取消已核对两条事实，管理页据此显示准备已撤回或准备未改变环境控制。
