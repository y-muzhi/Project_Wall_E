# WALL-E V2.2 管理登记恢复后的原停止核对

依据 V2.01 后端 3.5、4.10、4.12.3、7.9。原登记完成正常 STOP 后仍保留外部步骤及运行标识，需要在新登记开放前精确核对其原效果与实际宿主状态。

1. 按原请求、原快照及部署环境固定新处置。原 STOP 操作与唯一原步骤都已成功，且其停止回执、原运行认领记录、原目标运行操作及保存结果一致。原运行可来自正常启动、发布或正式恢复。
2. 核对原运行无未释放额度。保全原控制记录和原 SQLite 状态，单独追加受信停止记录。此入口只查既有原事实。
3. 派发复核使用原源控制的真实 unit 名称，确认原运行组不存在或已安静且不含进程。原运行单元未知、重新出现或仍活跃时保留阻塞；独立的当前环境状态与原资源仍须分别核对。
4. 管理站显示原已成功与独立核对时间。后续换代继承已结处置。没有完成停止或尚有原保留额度的在途旧 STOP 保持未决，等待其自身的取证和额度事务。

R132 同样支持原 STOP 仅已受理或处于待核对时的已知完成效果。只有原宿主受保护的最终 STOP、原运行认领及原有效授权匹配，才固定原效果。新登记按原运行 ID 仅释放与快照逐项相符的既有额度，处置和释放共用同一事务。提交后重试验证全部释放回执。原登记、原操作历史、其他额度及宿主程序保持原事实。对于只留下原计划的步骤，固定清册保留原 run_id，宿主适配器用相同保护事实发现对应的原始单元并重新测量。没有可核对证据、只有部分额度或原单元仍在运行时继续暂停，由原证据收尾。

R131–R132 完成 Windows 隔离验证，证据见 [R131](../../../verification/v2.2/local-registry-terminal-stop-r131-2026-11-22.md) 与 [R132](../../../verification/v2.2/local-registry-pending-stop-capacity-r132-2026-11-22.md)。验证覆盖成功凭证、不同运行、已停单元仍活跃或不可测、已停记录有剩余额度及历史只读。原生与生产分别验证。
