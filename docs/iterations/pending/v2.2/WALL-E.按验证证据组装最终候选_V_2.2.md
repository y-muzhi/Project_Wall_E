# WALL-E V2.2 按验证证据组装最终候选

2026-11-24。依据 V2.01 后端 4.11、7.7、7.10、8.1.3。接续固定候选预安装和发布证据准入。中转安装仍绑定原中转清单，收集实际证据后由独立目录生成最终封存输入。

- 受信宿主以 `prepare-release-final-build` 读取原构建中转策略及摘要，以及固定文件 `release-finalization-policy.v1.json`。最终计划固定管理范围、候选 ID、已登记候选摘要、原中转清单摘要、独立最终构建根及其文件系统身份，以及本次增加的验证记录引用。管理身份按原交付读取中转，宿主复核相同清单、程序和文件索引。
- 原应用、前端、资源、Schema、运行包、兼容引用、原集成交付及前序检查保持。最终清单只增加验证引用。所有引用逐项读取，完整四类检查均通过后才组装。原有失败不能通过省略旧引用规避。无实际保护证据的说明不作为验证记录。
- 组装使用与中转、发布根及固定管理资源分开的受保护 ext4 目录。新目录仅按原 release ID 排他公布，写完同步、完整复验后再公布，同一计划可核对并取回同一结果。不同字节同名目标保留，公布后的异常结果按待核实处理。
- 工具返回最终构建根及身份、最终清单摘要和可登记的原候选描述。候选管理索引由原有受信登记流程采用此描述，最终发布策略指向返回的固定构建根，再用既有 `seal-release` 和 `candidate --require-release-evidence` 读回。此次工具不写管理登记、原中转包或发布根。独立源与现有产品数据保全。
