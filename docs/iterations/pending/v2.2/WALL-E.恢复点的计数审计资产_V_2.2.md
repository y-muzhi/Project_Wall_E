# WALL-E V2.2 恢复点的计数审计资产

2026-11-21。依据 V2.01 后端 4.12.1、4.12.2、7.10，沿用 SQLite 快照和原意图回执。首个库外资产单元捕获实际安装数据根旁的 `CountingJournal` 原始审计。保护范围及缺失、空目录、已有文件三种事实分别记录。

- 受信捕获策略声明审计文件数和总字节上限。以同一稳定环境锁核对 CLOSED 和原控制版本，再取得审计目录及每个文件的类型、实际身份、权限、大小和内容。只按已实现的 CountingJournal 文件规则认领；符号链接、未知文件、硬链接、异常权限和变动使此单元停止。权限不足也必须保留实际原因。
- 数据库快照和计数审计复制共用同一停写锁和原操作。审计副本位于独立恢复根，文件独占创建并封存。索引记原安装及数据库摘要、审计状态、文件名、实际字节及摘要；重新读取原回执时逐项重新核实已封存内容，不再触碰源审计。未完成的副本保留供核对。
- 恢复计划同时固定原数据库和原计数审计索引摘要，准备新数据代次时保留原审计字节。新目标只在绑定同一原意图和新代次的标记下接续，逐个核对已封存文件，补齐确知未落盘的项；不覆盖冲突文件。旧索引随副本封存以保持原环境身份，外层恢复回执记新代次。全部原字节核对后才形成组件回执，保留外发冻结要求。
- 该单元的事实限于计数审计、数据库与原控制。其他任务资产、回执索引、固定程序和秘密引用完整恢复，以及独立演练与异机保存，仍需各自满足。管理状态保持组件验证，不承诺完整恢复点已准入。
