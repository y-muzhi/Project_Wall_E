# WALL-E V2.2 普通启动的受信执行步骤

2026-11-20。依据 V2.01 后端 4.2、4.5—4.8、7.9、8.2。延续 M9 运行观察和 M11 停止回执，提供普通启动的固定宿主执行器。

- 已登记的受信候选、独立普通安装、已准入的固定运行包和启动器、实际服务身份及受保护运行目录作为前置。调用固定的维护身份准备原启动回执。确定的原操作号先保存，再准备、派发。配置由受信安装输入固定，用户不输入命令、任意路径或系统服务属性。
- 单元名由环境和原启动操作派生。使用固定 systemd 属性、实际内存余量初查、显式 CPU／内存／任务上限，以及与 M11 匹配的正常停止规则。发布原启动结果依赖 M9 对真实系统服务组、稳定锁、持久控制及握手的共同核验。固定应用命令在记录 STARTING 前完成装配。只有在环境稳定锁及宿主共享锁内，原准备回执仍精确匹配当前正常关闭和控制修订、原普通套接字及单元均未占用且宿主仍在原 boot，才能持久记录派发。首次登记宿主启动前，按 Linux 账户的主组和附加组核对普通应用身份。持两把锁写入派发前以同一规则复核，拒绝额外组。入口代理拥有独立套接字组，普通应用依固定目录取得正确套接字组，无需加入代理或其他环境的组。释放锁后启动，实际应用再次核对原准入。既有观察和原取消仍沿原身份及结果规则。
- 同操作重取原结果；准备或派发结果不明时先核对原文件或进程，不重复调用。另一个启动意图须通过原唯一运行声明，已成功启动的环境再次进入须关联原运行的正常停止回执。崩溃或未决状态时保留原材料。
- 本步是显式手工调用的宿主阶段。额度预留事务、同时启动准入、网络控制与浏览器按钮在完整管理操作连接后再开放。

R258 的 Ubuntu 受管启停依次使用 `observe-attach`、管理 `ATTACH`、`observe-environment-control`、管理 `START`、固定 `start-runtime` 和原 `RECONCILE`。附件和工作树证据不能代替新鲜的关闭控制观察。正常停止使用管理 `STOP` 与固定 `stop-runtime`；停止中断时保留原控制键和已取到的停止效果，按同一业务回执复核。
