# WALL-E V2.2 普通运行容量预留与释放

2026-11-21。依据 V2.01 后端 3.5、4.6、4.8、6.5、7.9。M15 接入普通开发及集成的受管运行。

- 固定宿主的容量政策指定唯一管理安装与代次、登记锚、受信目录、管理执行私有目录、用途规格与普通总额。管理目录只登记政策摘要。每次原派发另外绑定实际 Linux 开机身份。
- 使用原 `resource_claims`。按内存、CPU、进程数及运行槽聚合，预留与原 START 同次提交。实际内存还要覆盖尚未证明就绪的占用及本次请求。等待保留意图与缺少项，容量采样不能核实时拒绝。各项都使用独立的普通容量总额。
- 固定宿主启动前由独立管理身份在原库保存派发凭据，绑定原环境、原操作和物理策略。没有原预留或派发身份不符时拒绝。宿主受信事实和事务状态分别记录，待核实不释放、不重放。
- 已核实的原 STOP 同时核对原启动、实际运行、范围、进程组和锁。释放和原 STOP 回执在同一个登记事务中保存。重取原键及旧回执不影响新的运行。
- 容量查询分别显示策略额度、实际预留及内核观察。磁盘和构建槽属于 CREATE／BUILD 的后续容量单元。启停目前只由受信本地工具执行。原继续和取消接续 M16。
