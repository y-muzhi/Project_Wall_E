# WALL-E V2.2 停写数据库快照实施细化

2026-11-20。依据未合入的 V2.01 后端 4.10、4.12.1、7.10、8.2。适用普通开发／集成环境关闭后的 SQLite 快照，以及其独立重开核验。

- 宿主安装者以受信策略钉住原环境安装、固定程序、控制 revision、恢复根的 inode／设备号、独占原操作号和数据库大小上限。恢复根单独预配，目录仅源维护身份可访问。入口不创建目录、不读取调用者指定的任意源库，不接受业务身份。
- 首次执行取得原稳定环境锁，复核已关闭的原部署、数据代次、来源结构和绑定，拒绝未核实的外发或执行事实。使用 SQLite Backup API 复制现有一致视图。正常关闭两条连接后，在独立目录重新打开并核对结构、环境身份及完整性，计算摘要并同步文件及目录。该路径不切换部署、不访问外部服务。
- 原操作只用自己的目录。有效的同意图回执支持只读重取。出现部分数据库但没有完整回执，保留文件并交由人工核对，原命令禁止再次捕获。已验证回执绑定快照 inode、大小、摘要及原部署事实。
- 本单元交付原数据库组件及其回执。多类资产覆盖、恢复演练、项目恢复清单、Restic 和正式恢复点登记由后续单元完成；这里的回执是形成完整恢复点的输入。
