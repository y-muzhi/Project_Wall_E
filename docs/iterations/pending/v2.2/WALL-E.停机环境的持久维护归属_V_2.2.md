# WALL-E V2.2 停机环境的持久维护归属

2026-11-21。依据 V2.01 后端 4.10.1、4.10.3、4.11、4.12 与 7.10。先处理普通环境已经按原契约停止的情况。

- 维护身份以受信计划固定当前安装、环境、数据代次、部署及控制完整摘要，使用现有稳定环境锁确认确为普通 CLOSED、无活动连接、无可使用的原启动准备，数据库无已识别的未决外部效果。把原控制及计划关联封存后，以单调递增版本进入 CLOSED／MAINTENANCE，保留最后开放事实并阻止外发。
- 普通 START 和启动准备必须仍满足 NORMAL_STOP；旧启动令和旧准备取消不能解除维护。停写捕获及恢复只有在各自计划显式固定同一维护操作与摘要时才使用该关闭窗口。旧捕获及恢复计划仍按 NORMAL_STOP 处理。维护动作与数据库操作使用同一稳定锁，各自提交并核对原事实。已持久记录取消意图时不再开始新捕获或恢复。
- 原维护取消按固定计划和当前原控制复核，保留原安装和代次，恢复普通 CLOSED 并再增一版。释放维护归属不启动应用。中断后按原封存意图、取消依据及当前控制核对，旧操作不会覆盖后来控制。设置、取消、只读核对分别由离线维护入口执行。
- 本单元覆盖已停止普通环境。在线闸门、长操作收尾、服务完全停止证据、管控权限及新元组采用保持原设计的后续准入条件。
