# WALL-E V2.2 旧数据代次原回执索引

2026-11-21。依据 V2.01 后端 4.12.1、4.12.2、6.6、7.10 与 TC201-REL-13。沿用既有 `idempotency_records` 和停止后数据库快照，供完整恢复清单引用。

- 停写后的 SQLite 捕获回执已固定原环境、代次、部署、控制版本与数据库摘要。索引由受限维护工具从这份已封存的 SQLite 只读快照建立，受信计划同时固定源捕获回执、独立索引目录身份和条目上限。完整计划应选择恢复前留存的最新可验证源，不能拿较早备份推断此后没有结果。
- 每个条目只存原能力、原目标和原请求键组成的规范范围摘要，以及持久回执状态与 HTTP 状态。投影不读取业务输入、返回正文或错误详情。已受理的 202 只证明原受理事实，不能证明异步业务已完成。原键未命中、持久处理中和未收录的动作保留 `UNVERIFIABLE`。
- 索引采用受信维护目录、按摘要分片及不覆盖发布。未封存时可在同一计划下仅补齐确知缺失且与原快照相符的分片，冲突保留。索引清单最后落盘，之后不重建缺片。查询固定索引摘要、原环境、原代次、能力、目标与原键，只给出安全摘要和快照依据。当前入口是维护身份专用离线工具。
- 完整恢复还需把索引纳入独立演练、完整封存包及管理权限查询。尚未接入管理 HTTPS 或给新代次开放原命令重发。外发、交付以及索引范围以外的旧结果仍依其独立原证据。旧设计目录保留。
