# WALL-E V2.2 受管发布的固定启动与原开放回执

状态为实施补充。来源为 V2.01 后端 4.11、7.9、7.10，原设计目录保持原样。

同一发布根操作持有原启动额度后，再由宿主执行已选目标的独立运行启动。权限来源为已保护的目标选择、发布核验与网关事实及普通运行 profile。命令来自已验证应用程序及固定 systemd 参数。命令装配和固定运行包核验先于额度登记。宿主在登记前与登记后、记录派发前分别取得稳定环境锁，复核仍为原关闭选择、网关证据仍新鲜且属于存活网关，入口及原目标 unit 仍未占用。记录派发之前还要确认宿主仍在本次 boot。两次检查均复用普通应用的宿主恢复准入，在稳定环境锁后取得同一宿主共享锁，确认当前部署与数据代次已经获准。在额度前核对及写入派发前，按 Linux 实际账户检查目标应用仅有安装允许的组。写入不可覆盖的派发记录时同时保持两把锁。宿主冻结已生效、未放行当前部署或排他恢复锁占用时，拒绝写入派发记录且不启动单元，已登记额度保留待原操作继续。两把锁释放后才启动原目标，应用仍从实际宿主控制完成最终准入。复核或命令装配失败发生在派发之前，允许原操作按相同身份重查，仍保留已登记额度；禁止归类为已派发或自动重复启动。已派发但未观察到效果时，只按派发记录使用原 boot、原额度和原单元核对。当前容量配置变更不授权补发，也不改写原观察要求。若已经跨宿主启动代次且缺最终回执，报告原结果待核实，保留原额度和原管理操作。已确认的原开放回执依原受保护启动策略摘要、关闭选择、派发记录和完整开放观察核对，读回不要求原宿主启动代次、已退出进程的用户目录或当前系统命令仍在。同一 boot 下仅核对已派发效果时，验证观察所需的固定启动器、systemctl 和原账户路径。systemd-run 只用于新的派发。观察工具或路径已失效则报告原结果待核实，保留原派发，不能重发。开放回执由普通应用在稳定锁内生成，宿主结合实际进程、资源额度、同一 Unix 入口和控制复读确认。
