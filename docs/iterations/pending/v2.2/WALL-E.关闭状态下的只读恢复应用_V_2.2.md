# WALL-E V2.2 关闭状态下的只读恢复应用

实施条目 R18。依据 V2.01 后端 4.10、4.12.2、4.22.2、6.6.2，接续 R16 已重开的新数据代次及 R17 的原结果依据。

- 固定 Linux 启动器独立准入 `serve-recovery`。只接受专用安装当前元组、明确的维护操作及受保护的读回计划。稳定环境锁必须可取得，当前控制为 `CLOSED`、`MAINTENANCE`、`outbound_hold=true`。保留安装原能力要求和维护归属。
- 演练回执摘要、固定 Schema、目标数据库字节、原初始化时刻及类型化业务摘要与本次安装新代次一致时才接收请求。库以只读 immutable SQLite 打开，拒绝附带 WAL、SHM 或回滚日志的目标，核对专用数据根及不可写的文件。当前安装、访问规则、控制、读回计划或数据库身份发生变化即停止提供读取。
- 沿用现有业务路由、身份与来源校验。仅开放核验范围内的 PURE_READ，首批为 `DOCUMENT_CONTENT` 和 `DOCUMENT_HISTORY`。前者含现有需求及正文和随正文加载的评论索引，后者含已存版本、评论及消息。未核验报告保持关闭。网关权限仍生效，业务握手投影 `READ_ONLY`、`CLOSED`、`BLOCKED` 和本次可信 `recovery_read`。
- 单独装配只读事务运行入口。启动、读回和退出均不创建业务执行器、不运行后台恢复或发布工作、不变更控制文件。原维护和恢复操作保持待处理。
- R18 入口消费已经受信准备的独立恢复安装和只读证据。关闭切换、前端维护交互、Linux 原生联调和生产采用须分别验证。
