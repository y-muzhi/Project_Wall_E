# WALL-E V2.2 受信环境登记与原交付

依据 V2.01 后端 3.4、3.5、4.6、4.7、6.5、7.9，前端第 6.2 和 7.6。M3 和 M4 先用固定 Linux 管理入口验证真实持久链路。登记调用只选择受信目录中的候选及固定摘要，固定核对程序另行在原业务和开发身份下读取真实资料。登记范围、负责人和受信证据均来自宿主安装。

- ATTACH 核对固定安装锚、配置、原数据身份、持久关停准入及原工作区／分支。短时只读观察来自原环境诊断和 M2 Git 证据，连同目录及样本身份进入管理库。登记不启动、更新或初始化原环境。宿主完整进程状态尚无准入证据时保持 UNKNOWN。
- 原请求绑定管理身份、登记代次、已授权主体、原键和严格规范化输入。同键同输入返回原结果，输入变化拒绝，已撤销账号无法读取。原负责人仅在原操作保有结果读权时核对其原结果。管理事务同时写环境、资源归属和回执，路径祖先关系、实际对象及 Git 分支的占用冲突一并拒绝。
- REGISTER_DELIVERY 核对目标环境和分配版本、准确提交及可信读取依据。固定资源和检查引用分别验证实际字节及提交关联。人工说明、未覆盖项和已核实检查分别保存。集成明确记录开发环境及其原交付 commit。已保存的原交付不因新交付而覆盖，也不授予合并、发布或外发权。
- 网络认证、实际启停与维护、浏览器持久化恢复沿原设计分批接入。离线管理入口使用宿主预置的受信输入和身份，独立于开发站点及其业务服务。
