# WALL-E V2.2 恢复应用的按需装配

日期 2026-11-26。实施依据为 V2.01 后端 4.12.2、4.22.2 及 8.2 的普通恢复和只读边界。本条保留在待合入迭代。

当前恢复子进程虽只允许现行纯读资料范围，仍在启动时导入普通代码任务、测试计划、AI 工作器和相应路由。R503 当前固定程序在 35 秒达到稳定锁，业务套接字未出现。R508 在同类无网 x86_64 来宾单独观测，原服务模块导入约 17 秒。已核验资料未能在原等待期限内通过真实应用回执。

恢复模式沿用同一个应用工厂、普通业务只读查询、前端静态装配、安装身份与环境准入。工厂按当前 scope 装配需求、文档、版本、评论和消息的现行路由，普通路由及工作器只在普通应用分支装配。恢复访问仍由现行绑定及闭合范围独立过滤。错误来源、错代次、写入、代码任务、执行、检查及模型等请求均依原契约拒绝。已验证范围仍为 DOCUMENT_CONTENT 与 DOCUMENT_HISTORY，原报告资产须待相应验证和 scope 能力成立后再装配。

保持运行包与程序逐项校验、稳定锁和设备原身份、固定只读数据库、恢复回执、outbound_hold、原 Unix 对端与启动和停止上限。恢复应用还须先取得锁并完成原有校验，再真实就绪。任一条件失败保留原未准入或未核实状态。

验证使用离线 Linux 的真实固定程序先选择普通安装、写入与正常关闭，随后完成便携包、搬移、恢复演练和独立恢复安装。核对真实私有应用的只读正文、历史、错代次及拒绝写入、停止与原结果回读。专项还须证明已有普通路由行为、恢复允许路径和各自 app 的工厂参数边界无回归。
