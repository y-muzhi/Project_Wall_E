# WALL-E V2.2 独立恢复副本与数据换代

2026-11-20。依据 V2.01 后端 4.12.2、7.10、8.2。此单元在原安装保持 CLOSED 的情况下，把 R2 已核验的 SQLite 组件恢复到独立根，并在副本内验证新数据代次。

- 宿主预先固定恢复操作 ID、原备份策略及数据库摘要、原环境／代次／部署、独占副本文件夹身份和唯一新代次。记录与原捕获、原程序／Schema 及原稳定锁相关联。
- 新副本用排他创建和持久的目标身份回执。以 SQLite Backup API 从封存输入复制。副本读取原结构、环境、代次、原首次初始化时间和所有表的类型化内容摘要。变更只在副本内一次事务更新 `environment_binding.data_generation`。其他字段及完整数据的类型化摘要保持一致，正常关闭后独立重开，并记录必须保持的外发冻结要求。
- 重新执行原操作只认经过预先绑定的目标 inode。已完成且可核实的返回原回执。副本仍是原代次或已为计划新代次时，核对完整内容再继续相应未完步骤。不能确认目标身份、结构、代次或内容时保留现状并返回待核实。
- 结果仅作为恢复演练和后续切换的数据库输入，工具不会替换现行安装或公开入口。库外资产、完整恢复清单、真实控制切换、RECOVERY_ONLY 及重新开放另依原契约。
