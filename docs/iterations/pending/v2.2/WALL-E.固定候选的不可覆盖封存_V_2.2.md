# WALL-E V2.2 固定候选的不可覆盖封存

2026-11-21。依据 V2.01 后端 4.11、7.7、7.10，接续 R4／R5 候选核对与 R9 独立安装。

- 管理登记继续固定候选 ID、原集成交付、最终清单位置及摘要、Schema 和独立构建事实。封存计划另固定同一候选摘要、受保护的构建中转根和独立发布根。管理身份用既有候选核对验证中转构建，宿主对同一摘要及实际文件复核。
- 受信工具只封存已完成的固定应用、前端及原清单。中转不重新构建或改写文件，封存要求实际固定程序入口和前端入口均存在。最终目录仅按原候选 ID 排他发布。发布前重读完整字节及索引，原子不覆盖改名后同步发布父目录，再以原候选入口验证最终对象。
- 同一原候选已存在时验证并读取原包，不依赖中转继续在场。不同字节的同名目录、错根或核对不完整均保留现状。父目录同步、发布后校验的结果不明时报告待核实，交由原候选标识继续核对。
- 封存成功只确认固定包及原集成交付。独立运行、业务与浏览器所需验证、恢复演练、目标维护采用及生产开放各自按既有设计取得证据。
