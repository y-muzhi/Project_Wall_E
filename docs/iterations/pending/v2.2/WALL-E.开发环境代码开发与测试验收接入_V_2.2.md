## 实施依据与顺序

1. 沿 V2.01 后端 6.1、7.11、8.2 和前端 4.2 核对真实能力，复用现有 Coding／Testing 页面、服务端业务命令和原回执。参考实现见 `e26466c`。工作台的导航、深链接和同源客户端都要使用服务端握手的实际准入，保留恢复态和只读身份限制。
2. 在隔离开发环境验证代码任务从文档依据、仓库输入到执行、候选和交付，验证测试任务从计划、版本和素材到独立检查、报告和回执。容器与进程来源、系统转储、模型通道及取消恢复按原设计的 P2-a、P2-b 验收。测试计划模型、代码执行及独立检查分别以实际运行结果准入。
3. 满足同源 API 与当前权限后复用现有页面。验证旧绑定、缺少执行资源、配置失效和任务取消时的提示及拒绝。浏览器验证以无副作用的查询和隔离数据为主。
4. 取得固定候选的宿主、隔离流程、浏览器和恢复证据后，再评估实际开发站开放。真实模型及计数调用另按本轮授权执行。

当前发布的后端能力和业务方法清单、浏览器握手和客户端方法清单、应用路由渲染分别受限。单独修改导航显示无法接通业务链路。
