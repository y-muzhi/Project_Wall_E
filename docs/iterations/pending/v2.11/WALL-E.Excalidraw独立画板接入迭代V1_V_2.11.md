# WALL-E V2.11 Excalidraw 独立画板接入

2026-11-25 · 事项 21 · 迭代修订 4 · 对话工作区已实施、待合并。

## 1. 文档说明与范围

用户确认从需求详情的「新建文档」创建独立画板。每份画板文档对应一张 Excalidraw 画布，与其他文档共同列在需求的文档目录里。创建、阅读、编辑、关闭、历史与恢复应与普通文档使用相同的工作区和操作方式。首版范围为独立画板文档，普通文档正文内嵌画板另行设计。

V1.5 正式前后端设计 1.0／EFFECTIVE 仍为共享业务规则依据。本迭代补充 V2.11 画板类型和内容处理。现行实现依据为 `cd48227` 及本轮读取的工作区代码，已核对新建、草稿、版本、恢复、`template_ref` 类型投影及固定数据库约束。本轮更新独立迭代，实施及正式设计合入待后续任务。参见 [V1.5 后端设计](../../../design/v1.5/WALL-E.后端设计文档_V_1.5.md)、[V1.5 前端设计](../../../design/v1.5/WALL-E.前端设计文档_V_1.5.md)、[V2.11 文档类型调整](WALL-E.文档类型调整迭代V1_V_2.11.md)。

## 2. 技术基线与公共规则

`@excalidraw/excalidraw` 拟锁定 `0.18.1`，沿现有 React／Vite 工作区按需加载画布组件、样式和应用静态资源。WALL-E 负责文档导航、标题、可编辑状态、保存、关闭与版本业务。Excalidraw 负责渲染、绘图工具和当前编辑会话的撤销、重做。

| 核对项 | 0.18.1 能力与采用方式 |
| --- | --- |
| 场景装载 | `initialData` 接受图形、画布状态和图片。组件初始化会恢复场景并清空会话撤销栈。文档、历史 `Revision` 或草稿身份变化时，按对应快照初始化；面板开合及窗口变化只调整尺寸。[初始化类型](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/types.ts#L29-L44)、[场景初始化](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/components/App.tsx#L2174-L2260) |
| 只读及变化反馈 | `viewModeEnabled` 由宿主控制。`onChange` 提供图形、画布状态和文件，画布接入层从中提取持久化内容，再交给文档草稿流程。[组件接口](https://github.com/excalidraw/excalidraw/blob/v0.18.1/dev-docs/docs/%40excalidraw/excalidraw/api/props/props.mdx) |
| 场景序列化 | `serializeAsJSON` 的 `local` 模式保留有效图形使用的图片，`database` 模式省略 `files`。文档快照采用包含图片的场景，历史读取可以独立恢复图片。[序列化源码](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/data/json.ts#L19-L64) |

现有文档操作的权限、需求级人工编辑占用、版本检查、幂等及审计适用于画板。业务命令使用服务端确认的真实文档与草稿身份。画布组件回调和临时状态仅作为客户端编辑输入。

前端生产构建按需加载画板包。字体与语言资源和其他静态资源一起构建，生产入口从同源 `/assets` 提供画板所需资源。官方组件默认通过 CDN 取字体，构建需为实际使用的语言及字体配置本地路径。验收使用包含中文的画板，核对无外网环境下加载、显示与重开。见 [Excalidraw 字体部署说明](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/README.md)、[WALL-E 静态资源入口](../../../../backend/app/frontend.py)。

## 3. 对象、关系与字段

| 对象或字段 | 本迭代定义 |
| --- | --- |
| `WorkDocument` | 画板是需求下的一个既有文档。`requirement_id`、文档 `id`、名称、归档状态、`content_version`、`metadata_version` 和确认关系沿用现有定义。格式在创建时确定，改名、清空画布、归档和归档恢复均保留画板类型。 |
| `document_kind`／`document_type` | 对外业务类型拟增加 `DRAWING`，显示为「画板」。`document_type` 继续表示 `CURRENT`／`MANUAL_DRAFT`。业务类型与记录用途独立。类型识别依赖不可变的文档格式引用，存储映射见 §7。 |
| 人工编辑草稿 | 既有独立草稿归属唯一目标文档。草稿具备自身 `id` 和保存版本，并绑定 `target_document_id`、`base_content_version` 及所属需求。当前文档和历史快照的画板原稿为编辑输入，草稿场景为编辑过程的唯一待提交内容。 |
| `Revision` | 继续使用文档级 `CONTENT` 快照与版本号。一次提交生成的版本保存整个场景，文档记录列表只读取摘要和标记，打开具体记录时再读取场景。读取或恢复时核对历史与当前文档属于同一需求、同一文档。 |
| 场景内容 | 一份原生场景包含格式标记、格式版本、`elements`、持久化 `appState` 及 `files`。图形、可见文本、分组、绑定关系、背景和有效引用的图片随场景保存。缩放、平移、选区、活动工具、弹层和撤销栈属于编辑器状态。空白画板是图形列表为空的有效场景。 |

## 4. 业务能力与状态转换

| 条目 | 进入条件与执行 | 成功与失败结果 |
| --- | --- | --- |
| DRAW-01 创建 | 选择「画板」并通过现有文档名称、创建权限及占用校验。服务端解析固定类型引用，并创建初始空场景。 | 在同一事务生成文档、V1 内容 `Revision` 和创建记录。复用创建回执选择新文档，打开时处于只读。结果待核实时重放原命令，已确认但读取失败时重读原文档。 |
| DRAW-02 开始人工编辑 | 当前文档可编辑且占用允许时，提交真实目标文档和当前内容版本。复用既有占用和草稿创建命令。 | 读取真实草稿后启用画布编辑；冲突时沿现有入口重读或接续已存在会话。 |
| DRAW-03 自动保存 | 仅收录当前活动草稿的有效场景变化。复用 `ManualDraftAutosave`、原请求冻结和本地草稿恢复。保存时提交目标、草稿和已确认的草稿版本。 | 保存成功后推进草稿版本，正式内容及版本列表保留原状态。失败保留本地修改。结果待核实时，先核实在途请求，避免旧回执覆盖较新的场景。 |
| DRAW-04 完成或取消 | 完成前按现有流程冻结编辑并同步最新有效场景，确认草稿版本后提交。取消沿现有确认与取消命令。服务端核对当前内容基准、真实草稿和占用。 | 有效内容变化时同事务更新当前文档、新建 `Revision`、写审计和释放占用。快照无变化时沿用原版本。取消确认后关闭草稿并返回正式内容。提交失败按既有规则保留可恢复内容和核实入口。 |
| DRAW-05 版本记录与确认 | 文档记录按同一文档分页读取版本，选中后读取完整快照。现有版本标记、当前版本确认、归档／恢复归档走各自命令。 | 历史快照只读。手工版本标记关联已有 `Revision` 和审计记录。确认绑定当前指定 `Revision`；有内容变化的新版本按现有规则待确认。 |
| DRAW-06 还原历史内容 | 在历史视图选择「恢复到编辑草稿」。开始命令携带当前文档的预期版本和同一文档的历史 `restore_revision_id`，沿现有草稿冲突处理。 | 以所选历史场景填充新草稿，可以继续绘制。完成后遵循 DRAW-04；原历史及确认记录保留。取消恢复草稿时回到原正式画板。 |
| DRAW-07 文档共用能力 | 通用目录、改名、归档、记录和确认继续按原权限及状态可用。普通讨论可使用画板的文档身份、名称与版本。文本写作、文字批注、修改建议及以文字设计为依据的代码任务，需通过原有能力入口的适用性校验。 | 画板不提供正文段落、章节及文字锚点。界面按真实能力显示原因，服务器拒绝对画板走文本写入或选择文本依据。讨论、源材料引用及模型预算投影不得携带场景封装、图片内容。 |

已有人工草稿时，从历史视图退出优先恢复原会话。若还原所选版本与现有草稿冲突，沿用现有历史草稿冲突处理，保留用户未确认放弃的草稿。已归档画板先按现行流程恢复归档，才可发起「恢复到编辑草稿」。旧版内容进入新草稿时，继续登记原历史 `Revision` 为来源，完成编辑后可在现有记录中追溯。见 [历史草稿冲突处理](../../../../frontend/src/requirements/document-controls.tsx)、[历史恢复命令](../../../../backend/app/documents/commands.py)。

完成编辑或取消编辑结果待核实时，沿用文档结束流程冻结原操作，重读实际文档与草稿，再用原幂等键核实原命令。服务端返回草稿不存在时，仍以原命令回执确认结果。读取失败时保留待核实状态。仅在确认原命令成功后关闭会话并清理这份草稿的本地记录。本地清理失败独立提示，已确认的完成或取消结果仍然成立。见 [人工编辑结束流程](../../../../frontend/src/documents/manual-end.ts)。

## 5. 页面、组件与交互

### 5.1 工作区与可编辑状态

1. 「新建文档」保留同一弹层、名称字段、创建按钮及回执。名称复用现有 1～80 个字符的校验。选择「画板」时，初始内容固定为空白画板。目录以现有方式展示画板名称、类型、版本、确认及归档状态。
2. 普通文档与画板共用需求详情、主编辑区域、文档标题、导航、业务操作区、状态栏、面板和文档记录。按钮沿用同一组件、文案、相对位置、尺寸、禁用反馈及焦点恢复。Excalidraw 画布及绘图工具装在现有正文容器，随面板和视口大小调整。保存、版本、关闭与恢复操作保留 WALL-E 的现有入口。
3. 当前只读和历史视图由宿主显式设置 `viewModeEnabled`。平移与缩放可用。会替换或修改场景的控件、拖放与快捷键须服从同一只读状态。进入人工编辑且真实草稿就绪后启用绘制。键盘操作限于画布范围，文档导航、按钮及对话输入保留自己的键盘行为。
4. 草稿、历史快照和当前内容分别按已有文档所有者管理。切换面板、调整宽度和切换只读历史视图时，保留仍在使用的草稿及编辑会话。切换文档后，上一文档晚到的读取或保存回执仍归原文档与草稿，不能覆盖当前视图。

### 5.2 状态与反馈

| 状态 | 表现与恢复 |
| --- | --- |
| 初次加载／切换读取 | 复用文档加载与错误区。文档响应、画布组件和场景均就绪后，才以当前身份显示画布。加载失败提供重试，已有草稿继续受保护。 |
| 无选择／成功空白 | 无选择沿用文档空态；有效空场景直接显示空画布，按已有条件提供「人工编辑」。大纲区域无可投影章节时，复用 `EmptyState` 说明当前画板无大纲。 |
| 出错／未授权／已归档 | 场景解析失败显示错误，避免将损坏场景当作空白内容提交。权限或占用限制沿用实际原因；已归档与历史画板可按现有规则只读查看。 |
| 编辑／保存中／结果待核实 | 使用同一保存状态栏和操作反馈。完成编辑依赖已确认的最新保存，结束前的手势或文本输入须先形成完整有效场景。保存失败时保留当前内容与上一份已保存草稿。 |
| 草稿未同步并尝试离开 | 复用离开保护及本地恢复。优先确认后端同步。未确认时显示现有提醒，标明本地是否已暂存，提供「继续编辑」和「仍然离开」。 |
| 文档记录无结果／分页变化 | 复用文档记录的分页、空态和越界处理。历史快照读取失败时保留原阅读位置与已有草稿，提供原入口重试。 |

### 5.3 复用位置

新建和目录沿用现有创建控制器及弹层。文档所有者按业务类型选择正文渲染器，维护当前、草稿、历史三种既有状态。画布接入层只交付就绪、有效性、内容变更、冻结和释放等编辑器信号，草稿会话、自动保存、退出及恢复继续由文档模块负责。若现有内容校验直接依赖 Milkdown 上下文，在内容快照边界引入按类型校验，使画板仍使用同一草稿恢复记录和提交协议。参见 [新建与目录](../../../../frontend/src/requirements/document-directory-view.tsx)、[文档工作区](../../../../frontend/src/requirements/detail.tsx)、[文档所有者](../../../../frontend/src/requirements/document-owner.ts)、[草稿会话](../../../../frontend/src/documents/manual-session.ts)、[文档记录](../../../../frontend/src/requirements/document-records.tsx)。

`onChange` 用于感知变化。共享会话要求同步草稿时，画布接入层应读取当前画布实例的 `getSceneElements`、`getAppState` 和 `getFiles`，确认它们属于同一有效场景，再让既有保存流程提交。拖动、中文输入或图片装载尚未结束时，保持当前编辑并等待有效快照。若已到离开保护时点而无法获得有效快照，则按文档未同步流程处理。校验失败或存储失败时，通过现有编辑流程继续处理。保存回执只推进已确认草稿的基准，保留提交之后发生的编辑。见 [Excalidraw 组件 API 类型](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/types.ts#L727-L764)、[文档冻结与同步](../../../../frontend/src/documents/manual-session.ts)、[自动保存账本使用](../../../../frontend/src/documents/autosave.ts)。

## 6. HTTP 契约与接入点

下表省略公共前缀 `/api/v1`。`{r}` 为需求 ID，`{d}` 为当前文档 ID，`{v}` 为 `Revision` ID。写入复用现有请求头 `Idempotency-Key`、错误码和结果核实规则。下表列出影响画板的参数。完整响应和通用校验继续依照原契约。

| 操作 | 复用的入口和相关输入 | 画板接入 |
| --- | --- | --- |
| 创建 | `POST /requirements/{r}/documents`，`name`、`document_kind`、`template_ref`、`initial_content` | `document_kind=DRAWING`，`initial_content=EMPTY`，`template_ref=null`。服务端解析固定类型引用并校验创建回执的类型。 |
| 读取 | `GET /requirements/{r}` 的现有目录及选择读取；`GET /requirements/{r}/current-document?document_id={d}` | 从现有文档摘要识别类型，按文档 ID 读取相应内容快照。校验返回的需求 ID、文档 ID、类型以及所选快照。 |
| 开始／还原 | `POST /requirements/{r}/manual-draft`，`document_id`、`expected_version`，还原时另传 `restore_revision_id` | 预期版本引用当前正式内容。恢复请求显式指向历史 `Revision`，由服务端核对归属并设置新草稿基准。 |
| 草稿读写 | `GET /requirements/{r}/manual-draft?document_id={d}`；`PUT /requirements/{r}/manual-draft`，`document_id`、`draft_id`、`expected_version`、`markdown_content`、`block_state_json` | 基于草稿版本保存。按真实草稿的 `target_document_id` 取得所属文档类型，核对所属需求、目标文档及草稿身份后处理场景。沿用草稿响应字段。 |
| 完成／取消 | `POST /requirements/{r}/manual-draft/complete`；`DELETE /requirements/{r}/manual-draft`，两者均传 `document_id`、`draft_id`、`expected_version` | 沿用占用及版本核实。完成返回现有内容提交回执，取消返回现有草稿结束回执。 |
| 文档属性／确认 | `PATCH /documents/{d}`，`expected_metadata_version`、`change`，确认携带 `expected_content_version` 和 `revision_id` | 原有 `RENAME`、`ARCHIVE`、`RESTORE`、`CONFIRM`。归档恢复适用本文档对象；内容还原走草稿入口。 |
| 版本列表／详情／标记 | `GET /requirements/{r}/revisions?document_id={d}&page=…`；`GET /revisions/{v}`；`POST /requirements/{r}/revisions`，`document_id`、`expected_version` 及可选 `description` | 沿用分页和响应字段。按版本返回的 `requirement_id`、`document_id` 核对所选文档，使用其不可变类型渲染指定快照。直接访问历史入口同样先核对文档归属。手工标记沿用版本记录的现有命令结果。 |

类型、对象校验及命令见 [文档 HTTP 模型](../../../../backend/app/documents/http_models.py)、[文档命令](../../../../backend/app/documents/commands.py)、[正式内容事务](../../../../backend/app/documents/content.py)、[版本 HTTP 模型](../../../../backend/app/revisions/http_models.py)、[版本标记事务](../../../../backend/app/revisions/commands.py)。

## 7. 存储、序列化与一致性

### 7.1 类型与内容映射

冻结库的 `document_kind` 列允许 `REQUIREMENT_BRIEF`、`DESIGN` 和 `SPECIFICATION`。拟沿现有前后端设计文档的类型投影机制，以物理 `DESIGN` 和服务器生成的版本化资源 `structure.excalidraw`／`blank-v1` 组成画板的不可变类型依据，公开投影为 `DRAWING`。资源引用沿用 `key`、`version`、`digest` 校验。读取时由引用与物理类型共同识别。既有 `DESIGN` 和现行设计资源保留自己的类型投影。该映射是本迭代的技术选择，实际锁定资源和前后端契约由实施首批验证。见 [现有类型投影](../../../../backend/app/documents/design_profiles.py)、[冻结文档字段](../../../../backend/app/infrastructure/schemas/v1_5.sql)。

创建回执、目录、当前文档及前端类型解码采用同一业务类型。草稿与历史投影通过所属文档取得类型，沿用各自响应。若已登记的画板资源标识与版本、摘要或物理类型不一致，按现有资源或快照错误处理。普通文档中即使有同名代码块，也继续按普通文档读取。类型投影、存储字段和 HTTP 入口均沿用既有机制。见 [文档目录投影](../../../../backend/app/infrastructure/document_repository.py)、[当前和草稿下的读取契约](../../../../backend/app/documents/contracts.py)、[版本读取](../../../../backend/app/revisions/queries.py)。

拟将紧凑场景 JSON 装入既有 `markdown_content` 的单个 `excalidraw` 围栏代码块，并使用现有 `block_state_json` 记录稳定的单区块快照。此封装只用于独立画板文档的存储与传输。正文界面由文档类型选择画布渲染，原始数据不作为可编辑 Markdown 展示。服务端用同一快照校验链核对只含一个对应区块、可解析且受支持的原生场景、图形及图片引用闭合、完整 Unicode 和合法容量。历史沿用 `markdown_snapshot` 和 `block_state_snapshot_json`，本地恢复沿用现有基于需求、目标、草稿及基准版本的键。见 [本地恢复记录](../../../../frontend/src/documents/recovery-store.ts)。

初始 V1 空场景即具有现有区块身份。日常绘图、删空画布或替换场景更新该区块内容。内部图形 ID 与文档 `block_id` 各自独立，文档区块身份、创建来源和历史还原仍通过原有身份证明规则校验。读取类型时校验服务端登记的资源引用；场景封装仅在画板类型已经确认后解析。见 [快照与身份继承](../../../../backend/app/documents/snapshot.py)、[草稿身份校验](../../../../backend/app/documents/manual_identity.py)。

### 7.2 保存与读取保证

- 规范化以锁定版本的原生持久化格式为基础，保持元素顺序、ID、绑定关系及必要原生字段。持久化比较排除初始化、缩放、平移、选区改变及图片缓存访问时间。载入旧场景时保留原快照，只有有效编辑进入现有草稿保存。空白初始场景与读回场景的无操作往返应可通过无变化判定。
- 场景是否需要保存与正式内容是否产生版本分别判定。Excalidraw 的元素版本号、随机版本标记和更新时间可能随撤销改变。若有效场景回到当前已确认草稿的内容且无中间保存，在比较时排除这些计数和时间差。若中间改稿仍在途，撤销后的场景须作为最新编辑保留，待该保存确认后按既有规则同步。若中间改稿已保存，撤销回原内容时须保存撤销后的场景。完成时继续按既有正文和权威区块快照判定 `NO_CHANGE`，包括已形成的区块修改来源记录。[Excalidraw 元素字段](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/element/types.ts#L49-L74)、[草稿来源推导](../../../../backend/app/documents/manual_identity.py)、[正式内容提交](../../../../backend/app/documents/content.py)
- 图片文件与使用它们的元素随同一快照提交。每个有效图片引用都必须能在本快照 `files` 中定位到完整、可解码的图片数据，并核对文件 ID 和类型。浏览器临时 `blob:` 地址或远程图片地址无法充当持久化图片数据。插入、替换或删除图片后，较早 `Revision` 仍能独立恢复自己的文件。缺失图片数据、损坏场景和不支持的格式版本按读取或保存错误处理。[Excalidraw 图片文件定义](https://github.com/excalidraw/excalidraw/blob/v0.18.1/packages/excalidraw/types.ts#L86-L114)
- 沿现行上限校验完整 Markdown 最多 1,000,000 Unicode 码点、完整 HTTP 请求最多 8 MiB，本地暂存仍受原恢复存储容量约束。容量以实际编码后的完整快照及请求计。对使用 Base64 的图片，单看 1,000,000 码点上限，原始图片数据的合计理论上限约为 750,000 字节，实际可用容量还需扣除图形、JSON 和封装开销。该估算用于设计审查，界面以实际序列化结果判断。超限沿既有保存失败路径提示，保留上次已保存结果和页面中的最新修改。[文档解析上限](../../../../backend/app/documents/markdown.py)、[HTTP 容量上限](../../../../backend/app/shared/http_boundary.py)
- 类型校验同时覆盖创建、草稿保存、版本还原及正式内容提交的实际入口。在进入文本模型组装、计数、代码任务资料投影或写入目标绑定前识别画板类型。服务端的可用性判断与事务校验共同约束直接调用、过期请求及异步结果。

### 7.3 文本入口的检查位置

在文档用作当前讨论对象、显式引用版本或关联文档时分别检查格式。当前画板的普通讨论保留真实 `document_id`，采用既有 `DISCUSS` 的 `target=null`、`scope=null` 路径。物理 `DESIGN` 值可供现有讨论资源选择使用，业务权限仍以画板类型为准。要求正文材料的入口在接收和冻结输入时即校验画板来源的适用性。历史 `REVISION` 来源在捕获前检查所属文档，防止旧画板场景随通用版本行进入请求快照。整篇修订同样校验格式。正式内容事务对 AI、建议批次等文本来源再次检查画板适用性。见 [现有讨论与目标契约](../../../../backend/app/guide/contracts.py)、[请求目标及历史来源捕获](../../../../backend/app/guide/accepted_context.py)、[模型装配](../../../../backend/app/guide/collaboration_context.py)、[正式内容事务](../../../../backend/app/documents/content.py)。

## 8. 实施顺序与验收

首批接通类型、场景封装及文档事务，并验证无需变更冻结数据库结构即可读写。第二批接通共用工作区的只读、编辑和历史渲染。第三批验证异常、容量、历史还原、文本入口保护及普通文档回归。各批检查使用隔离数据，状态和证据按项目规则写入需求实现映射及验证目录。

| 验收 | 执行与判定 | 对应条目 |
| --- | --- | --- |
| AT-01 独立创建 | 在同一需求创建普通文档和两张画板。核对新建选项、空白画布、V1、共同目录、点击后所选 ID、独立内容，以及重试后的唯一创建结果。验证同名代码块、错误资源引用及身份不符的载入结果。 | DRAW-01、§7.1 |
| AT-02 交互对照 | 在相同视口并排核对两种文档的标题、导航、操作栏、状态、记录及离开反馈。覆盖宽窄窗口、面板切换、键盘焦点、只读、占用、归档、无权限和加载失败。 | DRAW-02、DRAW-05、§5 |
| AT-03 草稿与正式提交 | 从人工编辑绘制并收到自动保存回执。确认重载可恢复、正式快照及列表在完成前保持原状。覆盖中文输入或拖动尚未结束时尝试完成，再完成有效编辑。对照未保存撤销、保存中撤销、已保存后撤销、有效完成与取消，检查服务端快照、版本、占用及审计。 | DRAW-02 至 DRAW-04、§7.2 |
| AT-04 历史与标记 | 第一版有效场景含图片、绑定箭头和分组，后一版替换图片及文字。逐版本读取并核对独立文件、图形、绑定与只读限制。手工标记验证仅关联当前 `Revision`。 | DRAW-05、§7 |
| AT-05 历史还原 | 从含图旧版恢复到编辑草稿，继续绘制并完成。核对新版本、历史原快照、来源记录、版本确认归属和图片。另行验证已有未提交草稿、还原后取消、目标版本冲突及跨文档 `restore_revision_id` 被拒绝。 | DRAW-04 至 DRAW-06 |
| AT-06 失败与并发 | 注入保存、完成与取消响应丢失，验证只能核实原操作，确认后才清理缓存。覆盖可重试失败、旧版本、缺失图片数据、损坏快照和超限图片，并切换 A、B 文档验证晚到回执、离开提醒及可恢复内容。 | DRAW-03、DRAW-04、§5 至 §7 |
| AT-07 文本能力边界 | 核对画板通用操作。以画板作为当前对象、历史版本引用和关联来源分别验证讨论、文本写入、文字锚点及文本资料请求，核对冻结输入、模型上下文和计数均无场景及图片。回归同需求下普通文档的文本编辑和历史。 | DRAW-07、§7.3 |
| AT-08 生产资源 | 在隔离生产构建的同源入口，关闭外网并打开包含中文的画板及其历史版本，检查文字、工具、画布尺寸、图片及静态资源响应。普通文档页面继续走既有加载路径。 | §2、§5 |

## 9. 实施结果

独立工作区分支 `codex/v211-excalidraw` 已接入。Excalidraw 是用户可见的画板编辑区，内容快照继续由现有文档编辑账本生成。当前、草稿、历史和恢复共用现有业务对象及接口。场景以一个稳定区块存储，原始场景不进入文本写入或模型材料。格式、构建、事务和浏览器证据见[隔离验证](../../../verification/v2.11/excalidraw-worktree-2026-11-25.md)。
