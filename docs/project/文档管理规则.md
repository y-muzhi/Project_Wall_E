# 跨版本文档管理规则

日期：2026-10-19。遵循用户采用的“文档类型 → v1.0／v1.5”分类方式。

1. 项目设计、迭代、合并、实施、决策、追踪、来源和验证记录按所属版本存放；目录名使用v1.0、v1.5，版本文档文件名采用_V_1.0、_V_1.5后缀。历史迭代批次不改写。
2. 类型根目录只保留导航或跨版本规则。共享模板不因项目升级复制成多份。
3. 新版规划可以明确引用旧版依据，但不能覆盖旧版规格、原始设计、批准来源或把旧验证结果当作新版本结果。
4. 原始设计、采用JSON、候选资源及批准来源保留原始字节。被冻结清单引用的proposals及adoptions保持固定路径，通过v1.0索引声明归属；1.5新内容进入自己的目录。
5. 迭代先放iterations/pending对应版本，确认合入后迁至archive/iterations，并在archive/merges同版本记录合入位置与边界。
6. 交互问题研究已被通用模板吸收，作为1.0迭代过程材料保存，不再单独设置research文档类别。
7. 用户已删除的5份旧参考／方案／维护记录保持删除，需要时从Git提交7341e23查询；不以整理为由恢复。
8. 本轮只维护文档、引用、字节保护和必要工具路径，不改业务代码、运行资源、数据或服务，不执行产品测试／构建／模型调用。

本轮核对见[分类记录](../verification/v1.5/document-organization-2026-10-19.md)。

## 现行状态与历史过程（2026-10-28，H03）

1. 各版本需求实现映射是能力、实现位置、实际证据、状态及缺口的唯一现行汇总；它引用正式前后端设计，不成为第三份业务规格。
2. 实施进度只保留一个“当前断点”，写当前任务及授权、实际代码／设计基线、现场观察日期、最近完整单元、未完成位置和下一步；旧断点转入按类型／版本组织的项目历史归档。
3. README只导航；实施计划写批次依赖和执行顺序；运行说明写有效步骤。不要在这些文件反复复制通过数、PID、资源阶段或每轮进度。
4. 验证报告保留原日期和实际失败／未覆盖，不随当前结果改写。必要时在旧汇总顶部添加历史提示并指向现行映射；不能把旧结论重新标为本轮证据。
5. 项目状态过程归档到`docs/archive/project/<版本>/`，与`archive/iterations`的设计迭代区分；归档要有来源、日期、原摘要及现行去向。历史中的“当前”、命令、PID与申请不作为现行授权。
6. 原始设计、冻结资源、来源／采用证据保持原字节。普通管理文档归档可增加历史提示、重定位链接；须明确这不是字节原样副本。不得恢复用户已删除文件或丢弃历史失败。
7. 当前状态变化只更新对应职责位置和必要链接。服务状态必须附观察日期，不由上次启动成功推断仍运行；真实调用、服务更新、提交推送许可不随历史档案续用。
