# V2.0离线执行器运行包清单准备

本说明对应OC20-CONFIG-1。工具只为已经离线准备好的目录生成并核对清单，不下载、安装或执行目录中的程序，不设置可执行准入。示例路径不是当前机器已准备资源，必须替换为操作者已核对的实际绝对路径。

## 输入条件

- Windows本机NTFS普通目录及文件；根与全部相对路径须符合现有内容路径规则，包括完整路径长度、大小写别名、链接及重定向限制。
- 根内已有opencode.json、.gitignore、package.json、package-lock.json及完整node_modules。配置满足既有隔离设置，固定@opencode-ai/plugin=1.19.5及锁文件一致；不自动补依赖。
- 清单输出位于源树外、父目录已经存在且目标文件不存在。工具不覆盖已有清单，即使字节相同。准备过程有120秒墙钟上限、100000枚举条目上限及原校验器的文件／字节／清单容量上限；超过即失败，不跳过条目。

## 准备与重新核对

在项目根、使用项目Python环境执行。以下路径仅为用法示例：

~~~powershell
.venv/Scripts/python.exe -B tools/prepare-opencode-runtime.py --bundle-root "C:\WALL-E-offline\opencode-runtime" --manifest "C:\WALL-E-offline\opencode-runtime-manifest.json"
~~~

成功打印文件数、opencode-bundle:sha256引用及“runtime admission unchanged”。保存本次引用和原清单；不手工改清单补齐缺失文件。清单覆盖实际原字节，成员按UTF-8路径顺序固定，源树不会被修改。

后续使用已有只读校验入口，传入实际输出引用：

~~~powershell
.venv/Scripts/python.exe -B tools/check-opencode-binary.py --bundle-root "C:\WALL-E-offline\opencode-runtime" --bundle-manifest "C:\WALL-E-offline\opencode-runtime-manifest.json" --bundle-ref "opencode-bundle:sha256:替换为本次实际64位摘要"
~~~

不因重核失败覆盖原清单；修改离线资源后使用新的清单位置重新准备，并按原运行准入流程处理新引用。首次准备失败会清理本轮同目录临时文件；若进程被强制结束，先确认原进程已退出，再人工核对专属.opencode-manifest-*.tmp，不批量删除其他资源。

## 与运行准入分开

准备器逐真实身份读完整文件，再复用原校验器核对闭包／配置／锁定依赖。清单先同目录临时写入、flush/fsync／关闭，再由正式校验器核对，最后原子无覆盖发布；相同目标有竞争时只保留一个完整文件。普通校验不保留非控制文件正文到内存；复制回调需要字节时保留原路径，分块读取执行取消检查。

清单不证明正式OpenCode二进制来源、只读ACL、SYSTEM／LPAC／WFP、原生协议、模型供应方或可执行配置已经准入。启动前必须重核原文件及真实OS权限；不得把此引用自行写成ready=true。本轮只在隔离假包上验证，未准备真实用户运行目录、安装执行器或更新用户服务。
