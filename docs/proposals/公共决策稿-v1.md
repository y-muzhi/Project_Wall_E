每个能力共享一条事务连接；写事务BEGIN IMMEDIATE，读事务BEGIN并在同一快照取items/total/counts。WAL、synchronous=FULL、foreign_keys=ON、busy_timeout=5000ms、read_uncommitted=OFF。连接不用共享跨请求可变状态；Provider请求在短事务外。锁等待耗尽503 STORAGE_UNAVAILABLE；唯一约束竞争由对应能力按真实状态复查后转换，不一概500。提交异常先检查幂等记录/数据库事实，不能宣称已回滚。DDL每次初始化整体事务；schema_migrations保存版本与文件hash，同版本重复仅核验，未知/较新版本拒绝启动，不重建已有表或覆盖业务数据。迁移前用SQLite backup API保存可恢复副本，迁移失败回滚；不为旧库自动删除文件。

ID每种实体独立sequence表，REQ编号独立1..999999序列，格式REQ000001起；消息序号每需求分配max+1，Revision同需求max+1，版本当前值+1，均在业务短事务中竞争保护。已成功分配不重复使用；回滚分配未成为事实可重试。达到上限保留现状并拒绝下一分配，建议新增明确503 CAPACITY_EXHAUSTED及安全中文“编号或版本容量已用尽”，须在公共错误表补充并逐接口列可达性，不假用普通输入错误。Block next_block_id为保留下一号，分配后必须还能表示新next，故不能消耗MAX_SAFE_INTEGER；不回绕。

幂等表键(capability_id,target_identity,idempotency_key)唯一；保存解析/default后的规范JSON输入（保留PATCH省略与null差别，数组顺序不变）、状态PROCESSING/SUCCEEDED、owner_epoch、created/updated、原success应用payload及HTTP状态。UUID大小写规范化为同一个UUID值。PROCESSING短事务领取后提交；并发原键返回REQUEST_IN_PROGRESS，异输入冲突。业务写与SUCCEEDED原成功结果同事务；正常拒绝/确定回滚释放PROCESSING，拒绝不存成功。启动锁确保无其他本机执行者，清除前进程未成功PROCESSING后才接受HTTP，不自动执行业务；SUCCEEDED永久保留，手动备份/归档不从在线库删幂等成功，保证原键重放。正在执行的PROCESSING不按任意TTL窃取。成功data冻结不取当前资源；每次响应生成新request_id。

后台asyncio任务集合按run_id去重，不另加业务重试。启动先恢复数据库RUNNING，不重发；事务提交后dispatch，dispatch失败保留事实由恢复机制处理。每30秒单次监测，前次未结束不重叠，错过扫描下次立即执行一次不补并发扫描；无进展阈值15分钟，正常调度可检测于阈值后30秒内，进程卡顿时不承诺墙钟硬上限，报告实际延迟。关闭先停止接入/新任务/监测，最多等10秒，尝试关闭在途连接，未完成RUNNING记录INTERRUPTED并终结未结束尝试；存储失败留给下次启动恢复；WAITING_USER、人工草稿、批次不动。Provider计算或计费不能回滚。

## B. 文档、身份、范围、锚点及补丁

来源BE Q-01/Q-05/Q-06族/Q-04/Q-CARD-STATE，FE-Q08/Q-FE-COMPONENT；阻塞P3/P4/P5/P6/P7。

模板建议新增NEW/CHANGE各一个固定v1，具体正文在本目录templates；未知处用“待确认”，不是产品事实。初始化锁定模板的标题文本、级别、相对顺序和对应block_id，允许其下内容补充/改写。ACTIVE解除该结构锁。模板key/version永久绑定，目录使用构建时生成同源静态catalog并随后端资源manifest hash校验；不虚构第37个配置HTTP接口。

Markdown候选为CommonMark 0.31.2加GFM表格、删除线、自动链接、任务列表；保留HTML/引用定义，HTML仅以惰性可见源文本显示不执行。顶层完整枚举heading/paragraph/blockquote/bullet_list/ordered_list/task_list/code_block/thematic_break/table/html_block/link_definition；图片为段落内inline image。表格为GFM规范；不额外接受未经注册的数学/图表指令为新类型，文本原样保留。候选解析器markdown-it-py 4.2.0，前端Milkdown remark/ProseMirror适配通过共享方言夹具核对；若现有编辑器无法无损承载HTML/引用定义，需实现保留原始节点适配，不静默吞内容。实际支持在P3以逐类型及混合嵌套/往返证明。参考[CommonMark规范](https://spec.commonmark.org/0.31.2/)、[GFM规范](https://github.github.com/gfm/)。

Markdown完整源不trim；解析每个顶层块的源片段与区块身份一一对应。标题section_path采用标题纯文本，从外到内包含自身；前标题为[]；同级新标题结束上一节，重复标题可存在，SECTION引用block_id而非标题字符串。空文档blocks=[]。完整Markdown与元数据作为同一快照校验，不能靠数量一致认定合法。纯文本投影保留文字/代码/链接标签及图片alt，去显示标记；软/硬换行都LF；列表项与表格行之间LF，表格列之间TAB；HTML使用原源文本。这一投影只用于选区/键列定位，不更改Markdown事实，前后端共用黄金夹具。

编辑器事务携带原节点block_id：编辑/移动原节点保留；复制/新插入分配next并递增；拆分保留前部ID、后部新ID；合并保留文档顺序首个ID、删除后续ID；移动区块包含其内部节点，列表顶层作为一个Block。移入另一个顶层块视为拆/合并，不能让一个ID同时出现在两个顶层节点。没有明确旧节点映射的粘贴一律新块；禁止用内容相似度猜ID。来源服务器验证并赋值：已存在创建信息全保留；内容/section_path真实变化更新last_modified；单纯次序移动保留原last_modified（若section_path变化则更新）。删除后next不倒退，undo可恢复原ID但新分配高水位不回退；恢复ID限于同一草稿编辑基线/事件映射，不能伪造历史对象来源。

草稿基线建议加内部manual_draft_context表，保存draft_id/current_document_id/base_content_version、初始BlockState及ID/来源验证所需编辑基线；不加公开Document字段。完成事务再检CURRENT仍同ID/基线版本，失败保留草稿。中间保存允许未闭合Markdown语法按正式解析器的文字解释，完整Schema/身份/来源仍合法；INITIALIZING不能删改锁定标题。ACTIVE修改原因缺少I12传输字段，推荐由实际正文变化分类生成内部reason_code=USER_MANUAL_EDIT并记录提交审计，前端不新增用户原因输入、I12不扩字段；“原因必须为用户提供”若另有期望需改变接口，本稿未如此假定。

Scope DOCUMENT允许全部当前块与所有五操作（行操作仅table）；SECTION从引用heading到下一个同/更高级heading前，允许其内块和内侧插入；BLOCK只该块，允许替换/删除/行替换及锚点前后插入；SELECTION只单块纯文本[start,end)范围，允许REPLACE_BLOCK但必须证明块外与选区外文本/标记未改变，不允许删除或插入块、不允许用行操作扩大范围。来源评论BLOCK相同BLOCK授权、SELECTION相同局部授权；读邻域不增加写权。AllowedTargets包括block_id、operations、selection_range(或null)、row_selectors(允许行集合或null)；保存在Run，不由模型自报。局部读取目标、祖先标题及左右各2块；SECTION读取节内全部及祖先标题、左右各2块。

SELECTION偏移统一Unicode码点半开区间；在原block_id的上述纯文本投影逐位置找selected_text，匹配紧邻prefix和suffix；不trim/归一化，不跨块，不把空前后缀作为任意上下文；只有一个候选才ATTACHED，0或多则ORPHANED。BLOCK按原block_id存在即可定位，创建时完整原Markdown快照不随改动重写；不存在则ORPHANED。创建评论及I34均后端从CURRENT实际构造/验证，不信客户端offset；前端selection事件带document_id/content_version/block_id/start_offset/end_offset/selected_text/prefix_text/suffix_text，并由UTF-16位置显式转码点。HTTP仍只传I29/I14已有字段。locate事件带requirement_id/document_id/content_version/block_id/range或null，旧文档/跨需求事件拒绝定位，历史快照不混当前锚点。

Patch基线一次性校验，所有original_content逐字等于生成时目标（行原文为那行Markdown完整片段）；全体ACCEPTED/EDITED只按order_no应用。替换/插入proposed必须解析为恰好一个顶层块；DELETE不EDITED；行cells必须列数相等、字符串按plain text转义，不允许整表替换；key_column_index以0起，key_value精确匹配纯文本且唯一。多个不同行替换可组合；同一行重复替换、同块多个替换/删除、块替换与行操作、目标删除与其插入组合均拒绝PATCH_INVALID；同锚点多个插入允许order_no确定顺序。任何目标/原文/权限变化TARGET_STALE，不部分采用。保留ID的REPLACE_BLOCK仅允许结果仍一个块；原类型可变化且重新section_path；插入新ID，删除不复用。ACCEPTED改动来源AI/SUGGESTION_BATCH；EDITED来源USER/SUGGESTION_BATCH；创建来源不改。

生成建议必须全部验证VALID后才生成正式批次；非法模型输出不能留部分批次。单项EDITED验证成功才更新；完成批次失败默认整体无写，错误详情建议新增安全{suggestion_errors:[{suggestion_id,code,message}]}用于定位，需明确补充I21/I22允许details。现有Suggestion.validation_status/error保留最近成功决定时的校验结果，不为失败完成动作偷偷写新状态；前端显示本次失败详情，可修正后重试。此选择解决“失败不写”与“标记失败项”的冲突，不放宽事务边界。

评论无expected_version：推荐事务内基于最新对象串行化，同字段并发编辑后提交者替换content；解决/重开依进入事务时状态执行，重复不改时间；软删除终态获胜，已删拒绝编辑/解决/重开，重复删除原时间。前端同一评论串行发动作，未知结果先复查；这是显式推荐覆盖策略，必须获确认，不能当原文已定。
