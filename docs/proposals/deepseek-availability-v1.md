## 当前卡点与可选保证

当前 `counting/v2` 没有封装余量，也没有兼容证明。完整 Prompt＋Schema 不能通过旧的 UTF-8 字节预算。现有精确文本计数编译器可按原规则裁剪，但没有条件开放正式 Chat。默认服务本次已接上真实计数器与两道门禁；在当前冻结资源下，门禁在远端计数前拒绝，不能靠环境开关、观测报告或改一个布尔值开放。

[Ark Tokenization 接口说明](https://docs.volcengine.com/docs/ark/sdk-v1-v2?lang=zh)描述 `text` 字符串/数组及逐项 token 数；[Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)返回实际 `usage`。本次检索没有找到适用于该固定 DeepSeek 版本、两角色、关闭思考请求的通用封装上界证明。因此，从六次观测全部成功推断任意输入都不超限，是不成立的。

推荐确认“实用预算控制”：每次发送前精确文本计数＋1024 token 固定余量，收到响应后复核实际用量。**它不再承诺发送前绝不会超过 24576 的实际输入预算。封装异常可能在一次已付费的 Chat 返回后才被发现，事后拒绝采用不能追回费用。** 如果仍要求原来的全输入严格保证，保留现有关闭状态，直到得到可独立验证的封装规范/上界依据；继续增加有限样本不能替代这一依据。
