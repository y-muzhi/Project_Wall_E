## 推荐确认的算法边界

1. 程序产出校验继续使用完整签名输出Schema。仅对发送给模型的Schema派生一个可达定义版本：保留全部根关键字、从根递归可达的$defs及其中全部关键字；仅删除根不可达的定义，不改名称、约束、oneOf/required/容量。只接受现有本地#/$defs/name引用；出现动态/递归/外部引用或未处理的标识解析机制时拒绝CONFIG_INVALID，不能套用简化结论。图闭包保证保留所有可能被根校验引用的定义；有限样本验证只是补充检查，不能代替该前提。
2. 原签名Schema和派生传输Schema分别计算SHA-256，和实际System文本、确切请求JSON、原协议引用/Read Manifest一起进入私有审计快照。原v1签名字节及完整校验器不变；不创建可变“最新Schema”回退，不公开审计或新增HTTP字段。
3. 冻结新增计数策略版本后准备官方Ark Tokenization API适配。它接收文本数组，返回同一实际模型版本与每项token数；System、完整User JSON及各受限字段按确切序列化文本计数。保留32768总预算、24576输入、8192输出和各4096/2048分项上限，不以更大窗口替换已确认预算。
